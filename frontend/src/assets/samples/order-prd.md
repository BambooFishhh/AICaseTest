# 电商订单系统 PRD（示例）

> 这是内置示例 PRD，用于快速体验"PRD → 用例生成"流程。可直接保存后点击"生成用例"。

## 1. 背景

电商平台需要一套订单管理系统，支撑用户从下单到收货的完整生命周期，并处理支付、退款、售后等异常场景。当前系统缺少自动化测试用例资产，希望通过 AI 生成覆盖核心流程与边界场景的测试用例。

## 2. 范围

### In scope

- 订单创建（普通下单、商品库存校验、优惠券抵扣）
- 订单支付（在线支付、支付回调、支付超时）
- 订单发货（商家发货、物流回填、收货确认）
- 订单退款（全额退款、部分退款、退款审批）
- 订单状态查询与列表筛选

### Out of scope

- 供应链、仓储 WMS 对接
- 营销活动引擎

## 3. 业务模块与状态

### 模块一：订单创建

状态：`DRAFT`（草稿）→ `PENDING_PAYMENT`（待支付）→ `CANCELLED`（已取消）

- 用户提交订单后进入待支付
- 库存不足时创建失败并提示
- 超过 30 分钟未支付自动取消

### 模块二：订单支付

状态：`PENDING_PAYMENT` → `PAID`（已支付）→ `PAYMENT_FAILED`（支付失败）

- 支付成功后回调更新订单状态
- 支付失败保留待支付状态，允许重试
- 重复回调幂等处理

### 模块三：订单履约

状态：`PAID` → `SHIPPED`（已发货）→ `COMPLETED`（已完成）

- 商家发货后回填物流单号
- 用户确认收货后订单完成
- 超时未确认自动完成

### 模块四：退款售后

状态：`SHIPPED`/`COMPLETED` → `REFUNDING`（退款中）→ `REFUNDED`（已退款）→ `REFUND_REJECTED`（退款拒绝）

- 支持全额与部分退款
- 退款需审批，拒绝时回到原状态

## 4. 核心接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/orders | 创建订单 |
| POST | /api/orders/{id}/pay | 发起支付 |
| POST | /api/orders/pay/callback | 支付回调 |
| POST | /api/orders/{id}/ship | 发货 |
| POST | /api/orders/{id}/confirm | 确认收货 |
| POST | /api/orders/{id}/refund | 申请退款 |
| GET | /api/orders | 订单列表（状态/时间筛选） |
| GET | /api/orders/{id} | 订单详情 |

## 5. 业务规则

- 库存不足禁止创建订单，返回 400
- 优惠券金额不得超过订单金额
- 未支付订单 30 分钟后自动取消
- 支付回调需校验签名，重复回调幂等
- 已发货订单不可直接取消，需走退款
- 退款金额不得超过实付金额

## 6. 验收标准

- 核心路径（创建→支付→发货→完成）全流程可用
- 异常路径（库存不足、支付失败、超时取消）有明确提示
- 退款流程覆盖全额/部分/拒绝三种结果
- 订单列表支持按状态、时间筛选
