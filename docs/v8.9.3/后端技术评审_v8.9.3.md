# 后端技术评审 v8.9.3 — 对账内存优化 + 并发残留清理

> 版本 v8.9.3，一旦确定尽量不要轻易改动。基线 v8.9.2。任务 12.5 + 12.6。

## 一、变更点

### 1.1 对账内存优化（12.5）

- **TestCaseRepository** 新增投影查询：`@Query("select t.id from TestCase t where t.projectId = :projectId") List<String> findIdsByProjectId(...)`；
- **MilvusService.queryIdsByProject** 改分页循环 `queryIdsPaged(c, collection, expr)`：每页 1000（QueryParam withLimit/withOffset），返回少于页大小即止；页获取抽包级私有 `queryIdPage(...)` 供单测覆写注入页序列；任一页失败整体返回 null（保留"失败≠空集"→SKIPPED 语义），失败计 milvus_op_failed_total{op=query}。取舍说明：SDK offset 深分页若实测劣化再切主键范围分批（注释预留）；
- **VectorReconciliationService**：dbIds 用投影集合比对；缺失补索引按 ≤500/批 findAllById 拉实体（REINDEX_BATCH_SIZE 常量）；dbCount=dbIdList.size()。

### 1.2 并发残留清理（12.6）

- ①(C5) compose LLM_MAX_PROMPT_CHARS 默认 300000→500000；删除 LLM_MAX_CONTEXT_CHARS 注入行（v7.13 已无读取方）；
- ②(C6) LlmService 两个路由包装器入口处 `degradedProvider.remove()`——池化线程上一次异常路径未消费的旧值在下一次调用入口即被清除，不再串台；消费点（TestGeneratorAgent/TestCaseService）不变；
- ③(C7) MetricsFacade 内部 counterCache/timerCache（键=name+tags），increment/incrementBy/registerCounter/registerTimer/recordMillis 全部走缓存；ObservabilityFilter.recordSlo 同模式本地缓存 sloCounters/sloTimers（method|status 键）；
- C8 VueAnalyzer 共享池：可选子项暂缓（现有池有 shutdown 且量级小）。
