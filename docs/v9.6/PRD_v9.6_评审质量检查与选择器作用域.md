# PRD v9.6：评审质量检查与选择器作用域

> 版本：v9.6 ｜ 类型：质量增强（评审层 + 生成侧选择器） ｜ 基线：v9.5（含 `8de42fc` 执行侧三修复）

## 一、背景与痛点

litemall 会员中心收藏/足迹 27 条用例实测评审暴露出两个系统性问题：

1. **评审层缺少两项检查**：28 条评审结果只标出 5 条修正，语义重复（同页面同行为、不同标题）一条未抓；「点击删除」类动作的预期仍写成页面标题或「页面跳转」等不可验证泛化表述。
2. **enrich 选择器池全局混用**：`enrichStructuredSteps` 把全项目 domSelectors 汇成一张池，不感知用例当前页面/路由。「我的页收藏入口」被配上「商品详情页收藏图标」，点击超时。

## 二、范围

### In Scope

- 评审层新增**语义重复**静态检查：同模块同类型、结构化步骤/断言高度重叠的用例标记为重复，进入评审问题清单。
- 评审层新增**预期与动作一致性**静态检查：
  - 删除/取消类动作的预期必须落在动作结果（列表消失、总数更新、提示文案）上；
  - 跳转型预期禁止「触发跳转/页面跳转/开始跳转」等无 URL/目标页锚点的泛化写法。
- AI 评审 prompt 同步增加两项检查维度（`ai-review.md` + 代码 fallback）。
- 生成侧 prompt 增加同口径硬规则，从源头减少懒断言。
- `enrichStructuredSteps` 按**路由/组件作用域**收敛选择器池：当前页面路由确定时只允许命中该路由对应组件的选择器；路由不确定或无可映射组件时宁缺勿错，不再全局混池。
- 补充单元测试与回归。

### Out of Scope

- 执行侧断言引擎改动（已在 `8de42fc` 落地）。
- `preDataSteps` UI 编辑器（后续卡）。
- 语义去重的自动删除策略：本版本只负责**标记并进入评审问题**，防止误删；自动合并留待评审建议闭环验证。
- 选择器池管理的可视化或运维界面。

## 三、功能详情

### F1 语义重复检查

- 输入：同一候选批的用例列表。
- 规则：
  - 模块一致、类型一致（避免正向/异常成对被误判）；
  - 结构化步骤的 type/action/target 序列与断言锚点高度重叠；
  - 标题不同的「同行为不同措辞」仍应命中，如「取消收藏后总数减少」vs「取消收藏后总数正确更新」。
- 输出：重复对双方用例的 `executionHints.reviewChecks.semanticDuplicates`，并作为评审问题交给 AI 评审二次确认与建议合并。

### F2 预期与动作一致性检查

- 删除/取消/提交类动作：步骤预期或后续状态断言只写「页面显示 XX 标题」且无动作结果关键词时标记 fix。
- 跳转型动作：预期含「触发跳转/开始跳转/页面跳转」且无 `URL`、路径引号或目标页标题时标记 fix。
- 输出：`executionHints.reviewChecks.expectedActionConsistency`，同时进入 `UiLanguageLinter` 违规清单（跳转泛化部分）。

### F3 选择器作用域匹配

- 由 `FrontendResult` 的 `componentSummaries`（component → route）与 `routes` 建立组件路由映射。
- 遍历 `structuredSteps` 跟踪当前路由：route 型 `uiSelector`、`/xxx` 形态 target 均视为导航并更新当前路由。
- 当前路由确定后，选择器池只取该路由对应组件的 domSelectors；带参路由（`/goods/:id`）按参数归一匹配。
- 当前路由未知或没有对应组件选择器：不写入 `uiSelector`，交给 Agent 模式执行时上下文定位。

## 四、验收标准

1. 构造两条语义重复用例（不同标题、同模块同类型、步骤一致）评审后均被标记，且 AI 评审 prompt 显式包含「语义重复」检查项。
2. 构造「点击删除选中」预期为「页面显示'浏览足迹'标题」的用例，静态检查标记预期与动作不匹配。
3. 构造「触发页面跳转」无 URL 目标的断言，`UiLanguageLinter` 与一致性检查同时标记。
4. 构造 User 页「我的收藏」入口与 GoodsDetail 页「收藏」按钮的选择器池，用例先导航 `/user` 再点击入口，enrich 结果为 User 页 `.like-o`，不得命中详情页选择器。
5. 无路由上下文时不写入跨页选择器（宁缺勿错）。
6. 后端 `mvn compile`/`mvn test` 与前端 `npm run build` 通过。

## 五、风险与规避

- **误报**：语义重复按「同模块同类型 + 高相似度」保守阈值，正向/异常成对用例不会被误并；重复只标记不自动删除。
- **错配**：路由无法确定时禁用全局池，宁可让执行链路用视觉/Agent 兜底，也不固化错误选择器。
- **带参路由**：`/goods/456` 与 `/goods/:id` 按参数归一匹配，避免具体商品用例失去选择器。
