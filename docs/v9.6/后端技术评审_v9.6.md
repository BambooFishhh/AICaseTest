# 后端技术评审 v9.6

**版本**：v9.6（一经确定不再轻易改动） ｜ **主题**：评审质量检查与选择器作用域

## 一、变更点

### 1. `ReviewQualityChecker`（新增）

静态、零 LLM 成本的质量检查器，两个入口：

```java
// 语义重复：同模块同类型 + 行为签名高相似
public static Map<String, List<String>> semanticDuplicates(List<TestCase> cases)
// 预期与动作一致性：删除/取消动作结果断言 + 跳转泛化
public static List<String> expectedActionConsistency(TestCase tc)
```

行为签名为结构化步骤 `(type, action, target)` + 断言引号锚点归一后的 token 集合；相似度阈值取 0.85，仅标记不删改。

### 2. `TestCaseReviewAgent.ruleReview`

- 批内先跑 `ReviewQualityChecker.semanticDuplicates`，把重复对双方的评审问题写入 `executionHints.reviewChecks.semanticDuplicates`。
- 每条用例跑 `ReviewQualityChecker.expectedActionConsistency`，结果写入 `executionHints.reviewChecks.expectedActionConsistency`。
- `ai-review.md` 与 `reviewRound` 的 Java fallback prompt 各新增 v9.6 两项检查维度。

### 3. `TestGeneratorAgent.enrichStructuredSteps`（选择器作用域）

- 由 `FrontendResult.componentSummaries`（`component` → `route`）和 `routes` 构建组件路由映射。
- 遍历步骤时维护 `currentRoute`：route 型 `uiSelector` 或 `/xxx` 形态 target 即导航，更新当前路由。
- 选择器池按当前路由过滤到对应组件；路由未知或组件映射缺失时跳过 enrich，不做全局混池。
- 带参路由做参数归一匹配（`/goods/456` 命中 `/goods/:id` 组件池）。
- 方法改包级可见（`void enrichStructuredSteps`），供单测直接验证。

### 4. `UiLanguageLinter`

新增跳转泛化规则：预期含「触发跳转/开始跳转/页面跳转」且无 URL、路径引号或目标页标题时记违规。

### 5. 生成 prompt 硬规则

- `backend/src/main/resources/skills/test-generation-prd-footer.md`
- `TestGeneratorAgent` 的 PRD-driven fallback prompt

新增 v9.6 约束：删除/取消类预期必须验证动作结果；跳转类预期必须写 `页面URL包含'/xxx'` 或目标页可见标题。

## 三、API 契约变化

无。全部改动为生成/评审内部逻辑与 `executionHints.reviewChecks` 元数据扩展。

## 四、向后兼容性

- `reviewChecks` 为新增可空字段，缺省无该键，前端与历史数据不受影响。
- `enrichStructuredSteps` 在路由不可解析时退回「不补选择器」，行为与现有 Agent 模式兜底一致，不写错误资产。
- 语义重复仅标记，不改变落库数量，避免误删风险。

## 五、测试验证方案

- `TestGeneratorAgentSelectorScopeTest`：跨页选择器不串、同页命中、带参路由命中、无路由不补。
- `TestCaseReviewQualityTest`：语义重复命中、不同行为不误报、删除动作懒断言命中、跳转泛化命中。
- `UiLanguageLinterTest` 扩展：跳转泛化违规用例。
- 回归：`mvn compile` + 全量 `mvn test`。
