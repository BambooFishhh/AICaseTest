# 后端技术评审 v6.6

> 版本 v6.6，一旦确定尽量不要轻易改动。主题：高可用 P1 - 执行接入与工具超时。

## 1. 变更点

### 1.1 MCP 超时

- `McpConnection` 构造增加 `requestTimeoutSeconds`，普通与流式调用统一 `future.get(timeout, SECONDS)`。
- 超时清理 pending 并抛 `IOException("TOOL_TIMEOUT")`，避免 `pending` 泄漏。

```java
try {
    return future.get(requestTimeoutSeconds, TimeUnit.SECONDS);
} catch (TimeoutException e) {
    pending.remove(id);
    throw new IOException("MCP [" + name + "] 请求超时: " + method);
}
```

### 1.2 工具错误分类

新增 `common/ToolRetryPolicy.java`：

- `isIdempotentTool(server, tool)`：仅截图/状态/滚动/只读查询为 true。
- `isRetryable(Throwable)`：TOOL_TIMEOUT/IOException/进程不可用为 true，其余 false。

`McpClientManager` 增加：

- `MeterRegistry` 工具失败计数 `aicasetest.tool.failures_total`。
- 幂等工具超时/不可用重试 1 次（延迟 500ms + 随机抖动）。

### 1.3 执行任务接入

- `AgentTaskService` 新增 `TYPE_EXECUTION` 与 `createTaskWithId`（taskId=executionId）。
- `ExecutionService.execute` 创建任务；`runAgentAsync/runAsync` 埋点：

```java
agentTaskService.start(executionId);
agentTaskService.checkpoint(executionId, "browser_launch", null);
// 每步完成后
agentTaskService.checkpoint(executionId, "step_" + (i + 1), null);
```

- 结束归一化：cancelled → cancel；failed/error → fail；passed → succeed。
- `cancelExecution` / `cancelBatch` / `finalizeCancelled` 同步 cancel。

### 1.4 TTL 与 QUEUED 调度

新增 `service/HaTaskScheduler.java`：

| 方法 | cron / 配置 | 说明 |
|---|---|---|
| `recoverStaleTasks` | `app.ha.recovery-cron` | lease 过期 RUNNING → NEEDS_REVIEW |
| `expireTasksByTtl` | `app.ha.ttl-cron` | startedAt 超时 RUNNING → NEEDS_REVIEW(TTL_EXCEEDED) |
| `dispatchQueuedTasks` | `app.ha.dispatch-cron` | QUEUED → 按类型分发 |

`TaskRetryDispatcher` 新增 `dispatchQueued(taskId)`，不修改状态要求，仅处理 QUEUED。

### 1.5 指标

`AgentTaskService` 使用可选注入 `MeterRegistry`：

- start → `aicasetest.task.started`
- succeed → `aicasetest.task.completed`
- fail → `aicasetest.task.failed`
- recover stale / TTL → `aicasetest.task.lease_expired_total`
- markDlq → `aicasetest.task.dlq_total`

## 2. API 契约变化

无新增端点；`/api/tasks/stats` 结构不变。配置新增：

- `APP_MCP_REQUEST_TIMEOUT_SECONDS`
- `APP_HA_TASK_TTL_MINUTES`
- `APP_HA_TTL_CRON`
- `APP_HA_DISPATCH_CRON`

## 3. 向后兼容性

- `McpConnection` 增加构造参数，提供旧构造重载（默认 60s），不影响测试。
- `ExecutionService` 执行入口行为不变，agent_task 为增量记录。
- 调度器与人工重试互不冲突，分发前校验状态。

## 4. 测试验证方案

- `ToolRetryPolicyTest`：幂等/非幂等、可重试错误分类。
- `AgentTaskServiceTest` 扩展：`createTaskWithId`、TTL 过期、QUEUED 查询。
- 回归：`mvn verify`、`npm run build`。
- 部署后：构造一次 `browser_take_screenshot` 超时场景验证计数与 NEEDS_REVIEW；执行一条用例验证 agent_task 终态。
