# PRD v4.3 — 项目组与权限

**版本**：v4.3
**基线**：v4.2
**日期**：2026-08-13
**主题**：项目组（部门）共享 + 成员操作权限 + 复制执行隔离

## 一、背景与痛点

1. 目前项目只有创建者本人可访问，同一部门/团队无法共享项目
2. 无"谁可以改、谁只能看、谁能执行"的权限粒度
3. 成员想跑组内用例时，会直接改动原用例的执行状态，无法隔离验证

## 二、范围

### In scope

- 项目组（ProjectGroup）：创建/重命名/删除/成员管理
- 成员角色：VIEWER（只读）/ OPERATOR（增删改查+执行），仅组创建者可指派
- 项目归属组：同组成员可查看组内所有项目；操作权限按成员角色
- 复制执行：成员可对选中用例"复制执行"（快照执行，不回写原用例状态），与原始完全隔离
- 前端：项目组管理页、建项目选组、列表组标识、按权限隐藏/禁用操作、复制执行入口

### Out of scope

- 多级组织架构、审批流
- 并发治理（已完成 v4.2）

## 三、权限模型

| 角色 | 项目访问 | 说明 |
|---|---|---|
| 项目创建者 | 完整（OWNER） | 继承既有权限 |
| 组创建者 | 组内项目完整（OWNER 级） | 可指派成员角色 |
| 组内 OPERATOR | 组内项目增删改查 + 执行 | 由组创建者指派 |
| 组内 VIEWER | 组内项目只读 + 复制执行 | 默认角色 |
| 系统管理员 | 全部 | - |

复制执行：按用例内容快照创建执行记录，执行过程与结果不影响原用例（不回写 executionStatus）。

## 四、验收标准

1. 创建项目组、添加成员、指派/回收 OPERATOR 角色
2. 组内成员可见组内全部项目；VIEWER 只能看，OPERATOR 可增删改查和执行
3. 复制执行不改变原用例执行状态，执行记录独立可查
4. 越权访问返回 403；列表只展示有权限的项目
5. mvn test + npm run build 通过
