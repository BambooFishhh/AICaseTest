## 2. 关键设计决策

### 2.1 A1 — src/test 过滤放 findJavaFiles 出口而非递归内

`collectJavaFiles` 递归中判断目录名（test under src）只能覆盖标准 Maven 布局且需传递父目录名；改为在 `findJavaFiles` 汇总后按 `relativize` 相对路径过滤（`rel.startsWith("src/test/") || rel.contains("/src/test/")`），可覆盖任意模块嵌套（monorepo 多模块 `module/src/test/`）。过滤数量计入 warnings。依赖图 L215 与 LLM 源码收集 L585 原有的 test 过滤保留（双保险，零成本）。

### 2.2 A2 — mapHttpMethod 保持旧签名 + 新增注解重载

旧 `mapHttpMethod(String)` 仅做注解名映射（类级/无属性场景）；新增 `mapHttpMethod(AnnotationExpr)`：注解名为 RequestMapping 时解析成员——
- `NormalAnnotationExpr`：遍历 pairs 找 `method` 成员，值取 `FieldAccessExpr`（`RequestMethod.POST` → POST）或 `ArrayInitializerExpr`（多值取第一个）；
- `SingleMemberAnnotationExpr`：值同上（`@RequestMapping(POST)` 场景，Spring 5+ 支持）；
- 解析失败或不识别 → 回退 "ANY"（保守，与现状一致）。

调用点 `extractEndpoints` 改用新重载。

### 2.3 A7 — extractBalanced 状态机（三态 + 栈）

```
代码态(NORMAL):
  '"'/'\'' → 入字符串态(记引号)
  '`'      → 入模板态
  open/close 计数（现行为）
字符串态: '\\' 跳过下一字符；匹配引号 → 弹出
模板态:   '\\' 跳过；'`' → 弹出；"${" → 入模板表达式态(depth=1)
模板表达式态: '"'/'\''/'`' → 入对应字符串/模板态（嵌套）；
  '{' → depth++；'}' → depth--，归零 → 弹出回模板态
```

- 栈式设计天然支持模板表达式内嵌套反引号模板（`` `${`nested ${x}`}` ``）；
- 模板表达式内的 `{}` 不影响外层括号计数——对 rules 块而言模板串整体是"不透明字符串"，语义正确；
- 原有纯引号/纯括号行为不变（现有调用方 extractForms 的 rules 块与字段规则数组提取均兼容）。

### 2.4 A8 — 全部 rules 块合并

`while (rs.find())` 循环收集每个匹配位置起的 balanced 块，`String.join("\n", blocks)` 后作为统一 rulesBlock 供字段查找。选择"全部保留合并"而非"就近 form 绑定"：就近绑定需要 form 与 rules 的位置关联（template 中 `:rules="formA.rules"` → data 中 formA/rulesA 映射），正则实现脆弱；合并后按字段名首次命中取规则，同名字段冲突场景罕见且不劣于现状（现状直接丢块）。

### 2.5 A9 — 递归出口排序

`collectVueFiles`/`collectJavaFiles` 在每次调用（含递归层）末尾 `result.sort(Comparator.comparing(File::getAbsolutePath))`：子目录先递归返回（其列表已排），父层再全量排序——顶层调用返回时全列表有序。代价 O(d·n log n)，可忽略。排序后所有下游（提取循环顺序、12k/16k 截断子集、组件摘要遍历、LLM 源码收集的 priority 排序稳定化）天然稳定。

### 2.6 A10 — 字段级/选择器级合并

- forms：按 component 找已有 form → 取其 `fields`（缺失则新建列表）→ LLM fields 中 name 不存在者追加（保留 LLM 的 label/rules 等完整字段）→ 无已有 form 才整条新增；
- domSelectors：按 component 找已有 → 取其 `selectors` → LLM selectors 中 type+value 组合不存在者追加；
- componentStates（component+type）/pageFlows（from+to）原粒度即细粒度，不动；
- 合并命中记 log.info（可观测）。

### 2.7 A19 — 死代码删除范围

- StateMachineAgent：`enhanceWithFrontend` + `mergeFrontendEnhancements` + `toMap`（仅死代码引用）。`readStateCodeMap`/`normalizeState`/`text`/`firstNonBlank`/`hasFrontendEvidence` 被 `validateTransitions`/`extractByLlm` 使用，保留。
- TestGeneratorAgent（v7.1 G5 清理遗漏，属同源死代码，顺带清理）：`buildSystemPrompt`、`buildQuantityGuide`、`SYSTEM_PROMPT_HEADER`、`SYSTEM_PROMPT_FOOTER`、`buildStateMachineRef`（2 参/4 参两个重载）、`buildForbiddenTransitions`、`matchEndpoints`。已 grep 确认主代码与测试均无引用；`FEW_SHOT_EXAMPLES` 为 PRD 链路存活资产，保留。

### 2.8 A20 — source 派生而非加列

StateMachine 实体已有 `sources` JSON 数组（`["rule_based"]` / `["llm"]` / `["backend","frontend","llm"]`）。新增 DB 列需要 Flyway 迁移且与 sources 语义重复——改为派生：

```java
static String stateMachineSource(StateMachine sm) {
    List<String> sources = JsonHelper.parseListString(sm.getSources());
    boolean ruleOnly = sources.contains("rule_based") && !sources.contains("llm");
    return ruleOnly ? "rule" : "llm";
}
```

- `generatePrdRound` 的 smMap 增加 `source` 键；rule 来源时 transitions 本就为 `[]`，无需特殊裁剪；
- `SYSTEM_PROMPT_PRD_FOOTER` "代码信息用于补充" 一节追加一行：
  `stateMachines[].source 为 "rule" 时表示规则兜底提取（仅状态枚举可信，无转换数据）：stateMachineRef.transitions 可为空数组，禁止为其虚构转换；source 为 "llm" 时正常引用真实状态流转`。
- 覆盖清单不受影响（rule 兜底 transitions 为空 → checklist 本就不含其 transition 项，无缺口压力）。

### 2.9 C1 — warnings 管道

- DTO 加字段即可随 `objectMapper.writeValueAsString` 落库 code_analysis（AnalysisService 无需改动）；
- warnings 通过参数逐层传入（VueAnalyzer 是单例 @Component，可能被多项目并发 analyze——**不得用实例字段收集**，避免串台）；
- SpringAnalyzer 主循环 catch 由静默 skip 改为收集 relPath；封顶策略：全部计数，warning 文本列前 5 个路径；
- VueAnalyzer 各提取器：整段 catch 记 warning + 文件级失败（读失败/rules 不配对）逐条记；组件摘要 LLM 失败计数聚合为一条；
- warnings 均为人可读中文，含文件名定位。

## 4. 回归风险评估

- **A7 重写 extractBalanced**：唯一风险点是模板态下的转义/嵌套处理——新增 5 个针对性单测覆盖（纯引号回归/模板串/嵌套模板/不配对 null/转义引号）；
- **A1 过滤**：测试代码中的 Controller 不再进入分析——这是期望行为（口径与依赖图/LLM 增强一致）；已有项目需重新分析才能体现（存量 code_analysis 不回填）；
- **A19 删除**：编译期验证（无引用即删），StateMachineAgentTest/相关 Agent 测试回归；
- **C1 warnings 字段**：纯增量，Jackson 序列化未知字段的消费方（前端）自动忽略。
