# 后端技术评审 v8.9.4 — 凭据卫生

> 版本 v8.9.4，一旦确定尽量不要轻易改动。基线 v8.9.3。任务 12.10。

## 一、变更点

### 1.1 SseTicketService 双实现（N1①）

```java
issue(): gen 随机 ticket → useRedis ? redis.opsForValue().set("sse:ticket:"+t, "user|role", TTL) : memory.put(...)
authenticate(): useRedis ? GET 解析 "user|role" : 内存 TTL 校验
useRedis() = redisEnabled && redis != null
```

- redis 注入 @Autowired(required=false)，开关 `@Value("${app.redis.enabled:false}")` setter——与 RuntimeStoreConfig 的条件口径一致；
- Redis TTL 到期自动失效，无需 purge；内存模式保留 1024 条 purge 兜底；
- 多实例互通由共享 Redis 保证（12.8 附录演练第 4 项同源机制）。

### 1.2 ticket 作用域限定（N1②）

JwtAuthFilter 新增 `isTicketAcceptedPath(uri)`：`uri.endsWith("/analyze-stream") || uri.contains("generate-stream") || isMediaPath(uri)`。ticket 校验分支前置该判断——非白名单路径忽略 `?ticket=` 参数（认证层直接不放行 → 401）。

### 1.3 媒体废弃期（N2）

媒体分支保留 `?token=` 可用性但命中即 WARN 日志（含 URI），日志文案声明废弃期后移除分支；新链路为前端先 ensureMediaTicket() 再 `?ticket=` 访问（filter 白名单已放行媒体路径的 ticket）。

### 1.4 admin 回退清零（N3）

DataInitializer：`@Value("${app.admin.password}")` 无默认 + run() 入口空值/空白抛 IllegalStateException（消息指明 APP_ADMIN_PASSWORD）——即使 SecurityKeyGuard 时序未来变动也不会静默以空口令创建 admin。
