# 后端技术评审 v6.7

> 版本 v6.7，一旦确定尽量不要轻易改动。主题：高可用 P2 - 断点续跑与降级闭环。

## 1. 变更点

### 1.1 分析断点续跑

`AnalysisService` 新增：

- `runAnalysisWithProgress(projectId, sourcePath, progressCb, taskIdOverride)`：复用 agent_task，不重复创建。
- `runAnalysisResume(projectId, sourcePath, taskId)`：completed 结果存在时跳过扫描/解析，重建语义索引，缺失状态机时重新提取。

`TaskRetryDispatcher` 分析分支改为调用 `runAnalysisResume`。

### 1.2 降级标记

`AgentTaskService` 新增 `markDegraded` / `getAttempt`：

```java
public void markDegraded(String taskId) {
    update(taskId, task -> task.setDegraded(true));
    metric("aicasetest.task.degraded_total");
}
```

`TestCaseService` 三个生成入口在结果含 `rule_based` 用例时标记 degraded。

### 1.3 LLM 熔断

新增 `common/LlmCircuitBreaker.java`，`LlmService` 三类 LLM 调用（chat/stream/image）接入：

- 调用前 `allowRequest()`，打开时直接 503。
- 成功后 `onSuccess()` 重置，最终失败 `onFailure()` 累计。
- 配置：`LLM_CIRCUIT_FAILURE_THRESHOLD` / `LLM_CIRCUIT_OPEN_SECONDS`。

### 1.4 Telemetry 关联

- Flyway `V9__add_task_telemetry_task_link.sql`。
- `TaskTelemetry` 增加 `taskId` / `attempt`。
- `TelemetryService` 增加带 task 的 `start` 重载与 `setTaskContext/clearTaskContext`。
- `AnalysisService` 使用新重载；`TestCaseService` 在生成前设置任务上下文。

### 1.5 前端任务中心

- `frontend/src/api/task.js`：`listTasks/getTask/retryTask`。
- `frontend/src/views/TaskCenter.vue`：筛选/表格/分页/详情抽屉/重试。
- 路由 `/tasks` + 侧边栏仅 ADMIN 可见。

## 2. API 契约变化

无新增 REST 端点（任务中心复用 v6.5 的 `/api/admin/tasks`）；`task_telemetry` 新增字段，仅数据库内部。

## 3. 向后兼容性

- `runAnalysisWithProgress` 原签名保留，新增重载不破坏调用方。
- `task_telemetry` 新增可空列，存量行不受影响。
- LLM 熔断默认 5 次/30s，不改变正常调用行为。

## 4. 测试验证方案

- `LlmCircuitBreakerTest`：阈值打开与成功重置。
- `AgentTaskServiceTest`：markDegraded / getAttempt。
- 回归：`mvn verify`、`npm test`、`npm run build`。
