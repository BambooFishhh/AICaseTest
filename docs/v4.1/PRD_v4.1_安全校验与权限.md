# PRD v4.1 — 安全校验与权限

**版本**：v4.1
**基线**：v4.0
**日期**：2026-08-12
**主题**：登录防爆破 + 密码策略与改密 + CORS 收敛 + 审计完善（评审人/执行人取登录态）

## 一、背景与痛点

1. 登录无防爆破：可无限尝试密码
2. 密码策略弱（仅 ≥6 位），且无法修改密码
3. CORS 全开放（`*`），与多用户场景不符
4. 评审人由前端传入、执行记录无操作人，审计不可信
5. 发现 v4.0 遗留问题：`runGenerate`（@Async）内做越权校验会因异步线程无登录态而误报 401

## 二、范围

### In scope

- 登录防爆破：同一用户名 5 次失败锁定 5 分钟（内存计数）
- 密码策略：≥8 位且包含字母和数字；注册与改密统一校验
- 修改密码接口 + 前端弹窗
- CORS 收敛为配置化白名单
- 审计：评审人取登录态（后端覆盖前端传参）；执行记录新增操作人
- 修复 v4.0 异步生成误报 401 的断言问题

### Out of scope

- token 刷新、多设备管理（后续）
- 线程池与并发治理（v4.2）

## 三、验收标准

1. 同一用户连续 5 次密码错误被锁定 5 分钟，提示剩余时间
2. 注册/改密密码需 ≥8 位含字母数字
3. 修改密码后旧密码失效、新密码可登录
4. CORS 仅允许配置白名单来源
5. 批量评审记录当前登录用户；执行记录含操作人
6. 重新生成（异步）不再误报 401
7. mvn test + npm run build 通过
