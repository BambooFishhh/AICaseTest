# PRD v3.5 — 追加生成模式

> 版本：v3.5 | 主题：按类型追加生成测试用例
> 基线：v3.4（生成参数可配置）
> 日期：2026-08-11

## 一、背景与痛点

### 1.1 现状

v3.2-3.4 已将生成体验打磨成熟：流式输出、取消保护、参数可配。但"重新生成"仍是**全量覆盖**语义——

```
TestCaseService.runGenerateStream:
  testCaseRepository.deleteAll(testCaseRepository.findByProjectId(projectId));  // 删全部
  for (tc : testCases) testCaseRepository.save(tc);  // 存全部
```

### 1.2 痛点

| 场景 | 当前行为 | 用户痛点 |
|------|----------|----------|
| 边界用例太少，想多生成一些边界用例 | "重新生成"删除全部用例（含已评审/已修改），重新生成全部类型 | 已评审工作丢失，且无法只补边界 |
| 异常用例质量差，想重新生成异常用例 | 同上 | 同上 |
| 想用更高 temperature 追加一批发散用例 | 无法追加，只能全量覆盖 | 无法增量改进 |

用户不敢点"重新生成"，因为会丢失人工评审成果。导致生成参数（v3.4）调好了也不敢重新生成。

### 1.3 机会

v3.4 已实现 GenerationParams（caseDensity/temperature/focusTypes），追加生成可复用参数 + 类型过滤，自然衔接。

## 二、范围

### In Scope

1. **追加生成端点**：`GET /api/projects/{id}/testcases/generate-stream-append?type={type}`
2. **追加语义**：不删除现有用例，新用例追加到列表末尾
3. **类型过滤**：可选 `type` 参数（positive/negative/boundary/data），仅保留该类型的新生成用例
4. **跨去重**：新生成用例与现有用例去重（不只新用例之间去重）
5. **ID 续号**：新用例 ID 从现有最大编号 +1 开始
6. **前端追加生成按钮**：在"重新生成"旁新增"追加生成"，弹出类型选择对话框

### Out of Scope

- 模块级追加（需要 PRD 模块列表联动，复杂度高，留待 v3.6）
- 选择性删除现有用例（数据安全风险，保持 v3.3 落库保护原则）
- 修改 LLM prompt 只生成某类型（LLM 不可靠，用后置过滤更稳）
- 追加生成历史记录（留待后续）

## 三、功能详情

### 3.1 追加生成 vs 重新生成

| 维度 | 重新生成（v3.2） | 追加生成（v3.5） |
|------|------------------|------------------|
| 现有用例 | 删除全部 | 保留 |
| 新用例 | 全部保存 | 追加保存 |
| 去重范围 | 新用例之间 | 新用例之间 + 新 vs 现有 |
| ID 编号 | 从 TC-001 重新开始 | 从现有最大 +1 继续 |
| 类型 | 全部 | 可选过滤（仅保留指定类型） |
| 参数 | Project.settings generationParams | 同左（复用 v3.4） |

### 3.2 类型过滤策略

```
LLM 生成全部类型用例
  → 后置过滤：仅保留 type 参数指定类型的用例
  → 跨去重：与现有同模块用例做标题相似度判重
  → 续号保存
```

> **为什么不改 prompt 只生成某类型？** LLM 可能不遵守类型约束，且会丢失其他类型的优质用例。后置过滤更可靠，虽浪费部分 token 但保证质量。type 为空时不过滤（全类型追加）。

### 3.3 API 端点

```
GET /api/projects/{id}/testcases/generate-stream-append?type=boundary
```

- `type` 可选，空=全类型追加
- SSE 事件与 v3.2 一致（progress/case/complete/cancelled/error）
- complete 事件新增 `appended` 字段（实际追加数量，可能 < 生成数量，因去重/过滤）

### 3.4 前端交互

1. 工具栏新增"追加生成"按钮（在"重新生成"旁）
2. 点击弹出类型选择对话框：
   - 全部类型 / 正向 / 异常 / 边界 / 数据（radio）
   - 确认后触发流式追加
3. 流式面板标题改为"正在追加生成... 已收到 X 条"
4. 完成后 ElMessage 显示"追加 N 条用例，去重/过滤 M 条"

### 3.5 状态机与并发

- 追加生成复用 `generating` 状态机，与重新生成互斥
- 追加生成可被取消（复用 v3.3 取消机制），取消时不落库（保留现有用例，符合 v3.3 落库保护）
- 追加生成失败时现有用例不受影响

## 四、验收标准

| # | 验收点 |
|---|--------|
| 1 | 追加生成后现有用例数量不减少 |
| 2 | 追加生成的新用例 ID 从现有最大 +1 继续 |
| 3 | type=boundary 时仅追加 boundary 类型用例 |
| 4 | type 为空时追加全类型用例 |
| 5 | 新用例与现有用例标题重复时被去重 |
| 6 | 追加生成可被取消，取消后现有用例完整保留 |
| 7 | 追加生成与重新生成互斥（generating 状态拒绝） |
| 8 | 后端编译通过 |
| 9 | 前端构建通过 |

## 五、风险与缓解

| 风险 | 缓解 |
|------|------|
| 追加生成导致用例膨胀 | 跨去重过滤重复；用户可手动删除冗余用例 |
| type 过滤后 0 条用例追加 | complete 事件返回 appended=0，前端提示"未追加新用例（可能已被去重）" |
| LLM 生成的用例与现有高度重复 | 跨去重复用现有 isDuplicate 逻辑（标题相似度 > 80%） |
| 追加生成时并发修改现有用例 | generating 状态互斥，不会并发 |
