# PRD v5.10 — PRD 上下文改版与用例级执行历史

**版本**: v5.10
**基线**: v5.9 / vP5
**日期**: 2026-08-16
**主题**: “额外 Prompt”更名“其他上下文信息”、上下文文档支持 PRD 式多来源录入、执行历史可按用例维度查看

---

## 一、迭代背景与痛点

1. v5.9 新增的“额外 Prompt”命名偏技术化，用户实际期望它是一个更通用的“其他上下文信息”入口，可用于补充业务说明、约束条件等任意提示内容。
2. v5.9 的上下文文档只有“标题 + 内容”两种字段，录入方式与主 PRD 不一致；用户希望每篇文档也能像 PRD 一样通过文本/Markdown、md/txt 上传、PDF 上传、在线链接抓取录入，且文档保持可选、可多篇。
3. 执行历史页目前只展示项目维度全量记录。用户希望从某个用例出发，只查看该用例自己的执行历史，并在用例操作列（执行、标记状态旁边）提供一个小入口按钮。
4. 工作区已有部分未提交改动（用例卡片“执行记录”按钮/弹窗、执行历史接口 `testCaseId` 过滤、Agent 元素查找滚动兜底），需要随本次迭代统一收口、验证并提交。

## 二、范围

### In scope

- PRD 面板：
  - “额外 Prompt”改名“其他上下文信息”
  - 上下文文档可选、可多篇，每篇支持 PRD 式录入：文本/Markdown、md/txt 上传、PDF 上传、在线链接
  - 后端 context 接口兼容新旧字段名（`otherContextInfo` / `extraPrompt`）
  - 生成用例时把“其他上下文信息”与文档数组注入 LLM 上下文
- 用例级执行历史：
  - 用例列表操作列新增“执行历史”小按钮
  - 执行历史页支持 `testCaseId` 过滤，仅展示该用例的记录、统计与趋势
  - 保留用例卡片内的“执行记录”弹窗入口
- 收口工作区已有改动：执行历史接口过滤、Agent 滚动兜底、浏览器滚动工具

### Out of scope

- 上下文文档语义索引 / RAG 召回（保留给后续版本）
- 多个主 PRD 实体（仍为 1 个主 PRD + N 个上下文文档）
- 执行历史按用例维度的聚合报表、用例筛选器下拉（后续版本可基于 `/executions?testCaseId=` 扩展）

## 三、功能详情

### 3.1 PRD 上下文改版

#### 其他上下文信息

- “额外 Prompt”文本域改名为“其他上下文信息”，保持 2-4 行可伸缩输入。
- 保存按钮文案改为“保存上下文信息”。
- 后端存储键从 `extraPrompt` 迁移为 `otherContextInfo`；读取时兼容旧数据 `extraPrompt`，写入时新旧字段都接受。
- 生成时注入 LLM 的 context 键同步改为 `otherContextInfo`。

#### 上下文文档

- 文档保持可选、可多篇，字段扩展为：`id`、`title`、`content`、`sourceType`、`sourceRef`。
- 新增/编辑弹窗提供与主 PRD 一致的四种来源：
  - 文本 / Markdown：textarea 直接编辑
  - md / txt 上传：前端读取文件内容填入文档
  - PDF 上传：调用 `POST /context/docs/upload`，复用 PDFBox 解析
  - 在线链接：调用 `POST /context/docs/fetch`，复用 Jsoup 抓取
- 文档列表展示来源标签（文本 / md / PDF / 链接），保留编辑、删除操作。

### 3.2 用例级执行历史

#### 用例操作列入口

- 用例列表“操作”列在执行、标记状态按钮旁新增“执行历史”小图标按钮。
- 点击后跳转 `/projects/{projectId}/executions?testCaseId={caseId}&testCaseTitle={title}`。

#### 执行历史页过滤

- 页面读取 `testCaseId` 查询参数并传给 `GET /projects/{id}/executions`。
- 有过滤时显示提示条：当前仅展示该用例的执行记录，并提供“查看全部”返回项目全量。
- 统计卡与通过率趋势基于过滤后的记录计算（后端已在过滤后统计）。
- 无过滤时保持原有项目全量展示，行为不变。

#### 用例卡片弹窗（收口已有改动）

- `TestCaseCard` 操作区保留“执行记录”按钮，弹窗内按 `testCaseId` 拉取该用例最近执行记录，支持跳转详情。

## 四、验收标准

1. PRD 面板显示“其他上下文信息”，保存后重新加载仍存在；旧数据 `extraPrompt` 可正常回显。
2. 上下文文档可新增多篇，每篇可通过文本、md/txt 上传、PDF 上传、链接抓取录入并保存。
3. 生成用例时 LLM 上下文包含 `otherContextInfo` 与 `contextDocs` 内容。
4. 用例列表操作列出现“执行历史”小按钮；点击后执行历史页只展示该用例记录，统计与趋势随过滤变化。
5. 执行历史页“查看全部”恢复项目全量记录。
6. 用例卡片“执行记录”弹窗只展示该用例记录。
7. `mvn compile` BUILD SUCCESS；`npm run build` 成功。

## 五、风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 字段改名导致旧前端/旧数据不可用 | 已有项目上下文丢失 | 后端读写兼容 `otherContextInfo` 与 `extraPrompt`，返回双字段 |
| 上下文文档 PDF/链接解析失败 | 单篇文档无法录入 | 复用主 PRD 解析逻辑，失败时前端提示且不写入 |
| 执行历史过滤后统计口径不一致 | 用户误解数据 | 后端在过滤后统一计算 total/stats/trend |
| 操作列按钮增多导致过窄 | 移动端/窄屏拥挤 | 保持图标按钮 + tooltip，并适当加宽操作列 |
