## 一、变更点 + 代码片段

### 1.1 项目上下文字段改名与兼容

`ProjectService` 读取上下文时优先取新键 `otherContextInfo`，旧数据回退 `extraPrompt`；返回时同时带两个字段，保证旧前端不破坏。

```java
// getProjectContext
String otherContextInfo = readSettingsField(p.getSettings(), "otherContextInfo");
if (otherContextInfo.isBlank()) {
    otherContextInfo = readSettingsField(p.getSettings(), "extraPrompt");
}
r.put("otherContextInfo", otherContextInfo);
r.put("extraPrompt", otherContextInfo); // 旧客户端兼容
```

```java
// updateProjectContext：接受新/旧字段名，统一落库为 otherContextInfo
Object otherRaw = payload == null ? null : payload.get("otherContextInfo");
if (!(otherRaw instanceof String) && payload != null) {
    otherRaw = payload.get("extraPrompt");
}
if (otherRaw instanceof String info) {
    settings.put("otherContextInfo", info);
}
```

`OrchestratorAgent` 注入时同样双键兼容，写入 `PrdAnalysisResult.otherContextInfo`；`TestGeneratorAgent` 生成 context 使用 `otherContextInfo` 键。

### 1.2 上下文文档 PRD 式录入

新增两个解析型接口（只返回解析结果，不直接落库，由前端随整体上下文保存）：

```java
// ProjectController
@PostMapping(value = "/{projectId}/context/docs/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ApiResponse<Map<String, Object>> uploadContextDoc(
        @PathVariable String projectId,
        @RequestParam("file") MultipartFile file) {
    return ApiResponse.success(projectService.parseContextDoc(projectId, file));
}

@PostMapping("/{projectId}/context/docs/fetch")
public ApiResponse<Map<String, Object>> fetchContextDoc(
        @PathVariable String projectId,
        @RequestBody Map<String, String> req) {
    return ApiResponse.success(projectService.fetchContextDoc(projectId, req.get("url")));
}
```

`ProjectService` 复用主 PRD 的 PDFBox/Jsoup 解析：

```java
public Map<String, Object> parseContextDoc(String projectId, MultipartFile file) {
    projectAccessService.assertOperateAccess(projectId);
    uploadGuard.assertSize(file, "上下文文档");
    String name = file.getOriginalFilename();
    boolean isPdf = name != null && name.toLowerCase(Locale.ROOT).endsWith(".pdf");
    String content;
    String sourceType;
    if (isPdf) {
        content = prdAgent.parsePdf(file);
        sourceType = "pdf";
    } else {
        content = new String(file.getBytes(), StandardCharsets.UTF_8);
        sourceType = "md";
    }
    if (content == null || content.isBlank()) {
        throw BusinessException.invalidParam("文档内容为空");
    }
    Map<String, Object> doc = new LinkedHashMap<>();
    doc.put("id", "doc-" + UUID.randomUUID());
    doc.put("title", stripExtension(name));
    doc.put("content", content);
    doc.put("sourceType", sourceType);
    doc.put("sourceRef", name);
    return doc;
}
```

### 1.3 执行历史按用例过滤（收口工作区已有改动）

`ExecutionController.getExecutions` 增加可选 `testCaseId` 参数，`ExecutionService` 在加载后过滤并统一计算分页、统计与趋势：

```java
if (testCaseId != null && !testCaseId.isBlank()) {
    all.removeIf(r -> !testCaseId.equals(r.getTestCaseId()));
}
```

该改动使 `stats.total/passed/failed/running` 与 `trend` 全部基于过滤后的记录计算。

### 1.4 收口执行稳定性改动（工作区已有）

- `PlaywrightRecordSkill` 新增 `scroll(sessionId, direction, amount)`。
- `ExecutionAgent` 元素多模态定位失败时按 down/down/up/up 滚动重试。
- `playwright-mcp-server` 新增 `browser_scroll` 工具。

## 三、API 契约变化

| 方法 | 路径 | 变化 |
|---|---|---|
| POST | `/api/projects/{id}/context/docs/upload` | 新增：multipart 上传 md/txt/PDF，返回解析后的文档对象 |
| POST | `/api/projects/{id}/context/docs/fetch` | 新增：body `{url}`，返回抓取后的文档对象 |
| GET | `/api/projects/{id}/context` | 响应新增 `otherContextInfo`，保留 `extraPrompt` 兼容字段 |
| PUT | `/api/projects/{id}/context` | 接受 `otherContextInfo` 或 `extraPrompt`，`contextDocs` 支持 `sourceType/sourceRef` |
| GET | `/api/projects/{id}/executions` | 新增可选参数 `testCaseId` |

## 四、向后兼容性

- 旧数据 `extraPrompt` 正常回显并迁移到新键读取路径。
- 旧前端 PUT 只传 `extraPrompt` 仍可保存。
- 执行历史接口不带 `testCaseId` 时行为与 v5.9 完全一致。
- 上下文文档缺省 `sourceType/sourceRef` 时前端按文本文档展示，不影响旧数据。

## 五、测试验证方案

1. `mvn clean compile`（JDK 17，`-Dmaven.repo.local=../.m2-repo`）必须 BUILD SUCCESS。
2. 手工验证：
   - 旧项目 GET context 回显 `extraPrompt` 与 `otherContextInfo` 一致。
   - PUT context 传 `otherContextInfo` 后重新加载可见。
   - 上传 md/txt/PDF 与链接抓取均返回可保存的文档对象。
   - `GET /executions?testCaseId=xxx` 只返回该用例记录，stats/trend 正确。
