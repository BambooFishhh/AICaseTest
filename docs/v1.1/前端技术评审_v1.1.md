## 一、现有前端架构（v1.0 基线）

### 1.1 技术栈

- Vue 3（Composition API，`<script setup>`）
- Vite
- Element Plus
- Pinia（状态管理）
- Vue Router

### 1.2 用例相关组件

| 组件 | 路径 | 职责 |
|------|------|------|
| `TestCaseList.vue` | views/TestCaseList.vue | 用例列表页（表格+统计+筛选+分页+重新生成） |
| `TestCaseCard.vue` | components/TestCaseCard.vue | 用例详情对话框（查看+编辑双模式） |

| `testcase.js` | api/testcase.js | 用例 API 封装 |

### 1.3 现有用例数据结构（前端视角）

```js
{
  id, title, module, type, priority,
  preconditions: [],      // string[]
  steps: [],              // string[]
  expectedResults: [],    // string[]
  stateMachineRef: {},    // 通常为空

}
```

### 1.4 现有展示方式

TestCaseCard 查看模式：
- el-descriptions 展示元信息
- 前置条件/测试步骤/预期结果 各为 `<ol>` 编号列表纯文本
- 状态机引用区块（通常显示"该用例未关联状态机"）

## 二、v1.1 前端改动点

### 2.1 TestCaseCard 查看模式升级

文件：`frontend/src/components/TestCaseCard.vue`

#### 2.1.1 结构化步骤区块（新增）

当 `testCase.structuredSteps` 非空时，**替代**纯文本 steps 列表展示：

```html
<el-divider content-position="left">测试步骤（结构化）</el-divider>
<div v-if="hasStructuredSteps" class="structured-steps">
  <div v-for="step in testCase.structuredSteps" :key="step.order" class="step-card">
    <div class="step-header">
      <el-tag size="small">{{ step.order }}</el-tag>
      <span class="step-action">{{ step.action }}</span>
      <el-tag v-if="step.type" :type="stepTypeTag(step.type)" size="small">
        {{ stepTypeLabel(step.type) }}
      </el-tag>
    </div>
    <div class="step-body">
      <div v-if="step.target" class="step-row">
        <span class="label">目标:</span>
        <code>{{ step.target }}</code>
      </div>
      <div v-if="step.expected" class="step-row">
        <span class="label">预期:</span>
        <span>{{ step.expected }}</span>
      </div>
      <div v-if="step.data && Object.keys(step.data).length" class="step-row">
        <span class="label">数据:</span>
        <code>{{ JSON.stringify(step.data) }}</code>
      </div>
    </div>
  </div>
</div>
```

**回退策略**：`structuredSteps` 为空时，展示旧 `steps` 纯文本列表（保证 v1.0 用例兼容）。

#### 2.1.2 API 关联区块（新增）

```html
<el-divider v-if="hasApiEndpoints" content-position="left">关联接口</el-divider>
<div v-if="hasApiEndpoints" class="api-endpoints">
  <el-tag v-for="(ep, i) in testCase.apiEndpoints" :key="i" class="api-tag">
    <strong>{{ ep.method }}</strong> {{ ep.path }}
  </el-tag>
</div>
```

method 着色：GET=success, POST=warning, PUT/DELETE=danger

#### 2.1.3 执行提示区块（新增）

```html
<el-divider v-if="hasExecutionHints" content-position="left">执行提示</el-divider>
<el-alert v-if="hasExecutionHints" :type="approachAlertType" :closable="false" show-icon>
  <template #title>
    推荐执行方式: {{ approachLabel }}
  </template>
  <div v-if="testCase.executionHints.notes">{{ testCase.executionHints.notes }}</div>
</el-alert>
```

approach 标签：api_call=success, browser=warning, manual=info

#### 2.1.4 测试数据区块（新增）

```html
<el-divider v-if="hasTestData" content-position="left">测试数据</el-divider>
<el-descriptions v-if="hasTestData" :column="2" border size="small">
  <el-descriptions-item v-for="(val, key) in testCase.testData" :key="key" :label="key">
    {{ val }}
  </el-descriptions-item>
</el-descriptions>
```

#### 2.1.5 执行状态展示（新增，在元信息区）

```html
<el-descriptions-item label="执行状态">
  <el-tag :type="executionStatusTagType(testCase.executionStatus)" size="small">
    {{ executionStatusLabel(testCase.executionStatus) }}
  </el-tag>
</el-descriptions-item>
```

### 2.2 计算属性新增

```js
const hasStructuredSteps = computed(() =>
  Array.isArray(props.testCase?.structuredSteps) && props.testCase.structuredSteps.length > 0
)
const hasApiEndpoints = computed(() =>
  Array.isArray(props.testCase?.apiEndpoints) && props.testCase.apiEndpoints.length > 0
)
const hasExecutionHints = computed(() => {
  const h = props.testCase?.executionHints
  return h && Object.keys(h).length > 0 && h.approach
})
const hasTestData = computed(() => {
  const d = props.testCase?.testData
  return d && Object.keys(d).length > 0
})
```

### 2.3 辅助方法新增

- `stepTypeLabel(type)`：api_call→接口调用, ui_action→界面操作, state_assert→状态断言, manual→人工
- `stepTypeTag(type)`：api_call→success, ui_action→warning, state_assert→primary, manual→info
- `executionStatusLabel(status)`：not_executed→未执行, running→执行中, passed→通过, failed→失败, blocked→阻塞
- `executionStatusTagType(status)`：passed→success, failed→danger, running→warning, blocked→info, not_executed→info

### 2.4 编辑模式（v1.1 不变）

v1.1 编辑模式保持 v1.0 能力（编辑旧 steps/preconditions/expectedResults）。结构化步骤编辑留待 v1.2。

### 2.5 TestCaseList.vue（v1.1 基本不变）

列表页保持不变。可选增强：表格行状态色（按 executionStatus），v1.1 不做，留 v1.2。

## 三、数据流

```
后端 TestCaseDTO（新增字段）
  → api/testcase.js（无需改动，透传）
  → TestCaseList loadList()（testCases 透传新字段）
  → TestCaseCard props.testCase（含新字段）
  → 模板按计算属性条件渲染
```

**无 API 调用变更**，纯展示层升级。

## 六、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| structuredSteps 字段格式不符合预期 | 中 | 计算属性判空 + try-catch 兜底 |
| 步骤 data 为复杂嵌套对象 | 低 | JSON.stringify 展示，v1.2 再做结构化 |
| Element Plus 版本兼容 | 低 | 使用稳定 API（el-tag/el-descriptions/el-alert） |
