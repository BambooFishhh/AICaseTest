## 一、现有后端架构（v1.0 基线）

### 1.1 技术栈

- Java 17 + Spring Boot 3.2
- Spring Data JPA + H2（文件模式，ddl-auto=update）
- LLM 调用：OkHttp + OpenAI 兼容协议
- 构建：Maven

### 1.2 核心类与职责

| 类 | 路径 | 职责 |
|----|------|------|
| `TestCase` | entity/TestCase.java | 用例实体（JPA） |
| `TestCaseDTO` | dto/TestCaseDTO.java | 用例传输对象 + from() 转换 |
| `TestCaseService` | service/TestCaseService.java | 异步生成编排 + 列表/更新 |
| `TestGeneratorAgent` | agent/TestGeneratorAgent.java | LLM 生成 + 规则回退 |
| `LlmService` | service/LlmService.java | OpenAI 兼容 API 调用 |
| `TestCaseController` | controller/TestCaseController.java | REST 端点 |
| `JsonHelper` | dto/JsonHelper.java | JSON 解析工具 |
| `UpdateTestCaseRequest` | dto/UpdateTestCaseRequest.java | 更新请求 DTO |

### 1.3 现有 TestCase 实体字段

```
id, projectId, title, module, type, priority,
preconditions(TEXT JSON string[]),
steps(TEXT JSON string[]),
expectedResults(TEXT JSON string[]),
stateMachineRef(TEXT JSON, 实际写死 {}),
source, confidence, createdAt
```

### 1.4 现有用例生成流程

```
TestCaseService.runGenerate(async)
  → 查询 stateMachines + CodeAnalysis.backendResult
  → TestGeneratorAgent.generate(stateMachines, backendResult)
      → generateByLlm(): 拼 context → LLM chat → 解析 JSON 数组
      → 失败回退 generateByRules(): 每状态机 3 个粗糙用例
  → 删除旧用例 → 保存新用例 → 更新项目状态
```

## 二、v1.1 后端改动点

### 2.1 TestCase 实体新增字段

文件：`backend/src/main/java/com/testagent/entity/TestCase.java`

新增字段（JPA @Column，H2 ddl-auto=update 自动加列）：

```java
@Column(name = "structured_steps", columnDefinition = "TEXT")
private String structuredSteps = "[]";

@Column(name = "api_endpoints", columnDefinition = "TEXT")
private String apiEndpoints = "[]";

@Column(name = "test_data", columnDefinition = "TEXT")
private String testData = "{}";

@Column(name = "execution_hints", columnDefinition = "TEXT")
private String executionHints = "{}";

@Column(name = "execution_status")
private String executionStatus = "not_executed";
```

**设计决策**：所有结构化字段以 TEXT(JSON) 存储，与现有 preconditions/steps 风格一致，避免 JPA 复杂关联映射，保持轻量。

### 2.2 JsonHelper 新增方法

文件：`backend/src/main/java/com/testagent/dto/JsonHelper.java`

新增 `parseListMapString`（已有 `parseListMap` 返回 `List<Map<String,Object>>`，可复用）。无需新增方法，直接用 `parseListMap` 解析 structuredSteps / apiEndpoints。

### 2.3 TestCaseDTO 适配新字段

文件：`backend/src/main/java/com/testagent/dto/TestCaseDTO.java`

新增字段：
```java
private List<Map<String, Object>> structuredSteps;
private List<Map<String, Object>> apiEndpoints;
private Map<String, Object> testData;
private Map<String, Object> executionHints;
private String executionStatus;
```

`from()` 方法补充：
```java
.structuredSteps(JsonHelper.parseListMap(entity.getStructuredSteps()))
.apiEndpoints(JsonHelper.parseListMap(entity.getApiEndpoints()))
.testData(JsonHelper.parseMap(entity.getTestData()))
.executionHints(JsonHelper.parseMap(entity.getExecutionHints()))
.executionStatus(entity.getExecutionStatus())
```

### 2.4 TestGeneratorAgent 升级

文件：`backend/src/main/java/com/testagent/agent/TestGeneratorAgent.java`

#### 2.4.1 generateByLlm() 升级

- systemPrompt 升级：要求返回 structuredSteps（每步含 action/target/expected/data/type）、apiEndpoints、testData、executionHints、stateMachineRef
- 解析 LLM 返回时填充新字段
- 每个 TestCase 设置新字段

#### 2.4.2 generateByRules() 升级

规则生成也填充新字段：
- `buildPositiveTest`：每条 transition 生成一个 structuredStep（type=state_assert）
- `buildNegativeTest`：填充 stateMachineRef.forbiddenTransitions
- `buildBoundaryTest`：填充 stateMachineRef.states
- 关联 endpoint：从 backendResult.endpoints 按 module/function 简单匹配
- executionHints.approach 默认 `manual`（规则生成置信度低）

#### 2.4.3 stateMachineRef 真实填充

新增辅助方法 `buildStateMachineRef(StateMachine sm, List<Map> transitions, boolean includeForbidden)`：
- 正向用例：填充 transitions
- 负向用例：填充 forbiddenTransitions（反向转换）
- 边界用例：填充 states

### 2.5 UpdateTestCaseRequest 适配

文件：`backend/src/main/java/com/testagent/dto/UpdateTestCaseRequest.java`

新增可选字段（v1.1 编辑模式暂不前端编辑结构化步骤，但 API 支持更新）：
```java
private List<Map<String, Object>> structuredSteps;
private List<Map<String, Object>> apiEndpoints;
private Map<String, Object> testData;
private Map<String, Object> executionHints;
private String executionStatus;
```

TestCaseService.updateTestCase() 补充新字段更新逻辑。

### 2.6 Controller 无需改动

TestCaseController 现有端点透传 DTO，新字段自动序列化。无需改动。

## 四、向后兼容与数据迁移

| 场景 | 处理 |
|------|------|
| v1.0 旧用例（无新字段） | DB 新列默认值 `"[]"`/`"{}"`/`"not_executed"`，DTO 解析返回空结构，前端回退展示 |
| H2 schema | ddl-auto=update 自动加列，无需迁移脚本 |
| XMind 导出 | XmindService 继续用旧 steps 字段，不受影响 |
| 列表展示 | TestCaseList 表格不变 |

## 五、风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| LLM 返回结构化 JSON 不稳定 | 中 | 增强 extractJsonArray 容错 + 规则回退 |
| structuredSteps 解析失败 | 低 | parseListMap 已有异常兜底返回空列表 |
| 新字段加列失败 | 低 | ddl-auto=update 成熟可靠 |
| LLM 生成 token 超限 | 中 | v1.1 保持单次生成；如超限 v1.2 分模块 |
