## 1. 现状与调用链

```
ProjectService.createProject ── git_url ──> GitCloneService.clone（--depth 1 浅克隆）
AnalysisService.runAnalysis ──> CodeAnalysis{frontendResult, backendResult JSON}
SpringAnalyzer.extractEndpoints ──> EndpointInfo{method,path,file(相对路径,/分隔)}
SpringAnalyzer.extractStateTransitions ──> 证据 [{field,from,to,method,file}]
StateMachineAgent.applyEvidence ──> 证据 from/to 匹配 → transition.verified 标记
```

关键事实：

- `EndpointInfo.file` / `EntityInfo.file` 为**相对扫描目录、正斜杠**的路径（relativize 统一处理），与 `git diff --name-status` 输出同构，可直接匹配
- SM transitions JSON 不含文件；但证据结构含 `{file}`，且 applyEvidence 已有"剥枚举前缀+小写归一"的 from/to 匹配逻辑可复用
- CoverageService/生成链路本期**零改动**

## 2. 数据模型

### V13__add_scope_tables.sql

```sql
CREATE TABLE IF NOT EXISTS scope_definition (
    id VARCHAR(8) PRIMARY KEY,
    project_id VARCHAR(8) NOT NULL,
    name VARCHAR(128) NOT NULL,
    baseline_ref VARCHAR(256) NOT NULL,
    head_ref VARCHAR(256),
    status VARCHAR(16) NOT NULL DEFAULT 'draft',
    changed_files TEXT,
    created_at DATETIME,
    updated_at DATETIME,
    KEY idx_scope_def_project (project_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS scope_item (
    id VARCHAR(8) PRIMARY KEY,
    definition_id VARCHAR(8) NOT NULL,
    item_type VARCHAR(20) NOT NULL,
    item_ref VARCHAR(512) NOT NULL,
    change_kind VARCHAR(16) NOT NULL,
    origin VARCHAR(16) NOT NULL,
    note TEXT,
    created_at DATETIME,
    KEY idx_scope_item_def (definition_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

实体对齐 Project/StateMachine 风格：@Id String(8)、TEXT columnDefinition、PrePersist/PreUpdate 时间戳。

## 3. GitDiffService（新增）

```java
@Service public class GitDiffService {
    boolean isGitRepo(Path dir)                    // .git 存在
    Map<String,Object> listRefs(Path dir)          // heads/remotes/tags + 当前 HEAD
    List<ChangedFile> diffFiles(Path dir, String baseline, String headRef)
                                                   // --name-status 三点diff，失败回退两点
}
// ChangedFile{status(A/M/T/R/C/D...), path}；D 状态在 ScopeService 中忽略
```

实现要点：
- ProcessBuilder 执行 `git -C <dir> ...`，超时 60s，UTF-8 读取，错误流合并截断 2000 字符
- R100 重命名取新路径（tab 分隔第二段）
- 输出 path 统一 `/` 分隔

## 5. ScopeMappingAgent（新增）

- 输入：PRD 全文 ≤8000 字符 + 接口清单 ≤120 条（method|path|description|businessLogic）
- system prompt 要求仅输出 JSON 数组 `[{"method","path","reason"}]`
- 解析：截取首个 `[` 到末个 `]` 子串 objectMapper 解析，失败抛业务异常由调用方捕获降级
- 合并去重键：`METHOD 大写 + " " + path 原样`；已存在（任意 origin）则跳过
- LlmService.chat 单次调用，失败 warn 日志返回空表（不阻断）

## 6. ScopeService / ScopeController

- createDraft：校验 git 仓库 → diffFiles → 映射 → LLM 补充 → 保存 definition(draft)+items
- recompute：删 AUTO_DIFF/LLM_MAPPED 项重跑 [2]-[5]，MANUAL 保留；confirmed 定义不允许 recompute/add/delete（invalidState）
- confirm：items 非空才允许；status→confirmed
- 手动添加：itemType ∈ {ENDPOINT,STATE_MACHINE}、changeKind ∈ {ADDED,MODIFIED,AFFECTED}、origin=MANUAL
- 所有写操作 assertOperateAccess，读操作 assertViewAccess
- id 生成：UUID 截 8 位（与 Project 一致）
