# 前端技术评审 v8.1 — 范围感知基础

> 对应 PRD：PRD_v8.1_范围感知基础.md
> 一旦确定尽量不要轻易改动

## 1. 现状

- API 层：`src/api/*.js` 每域一文件，统一走 `request.js`（axios 封装，返回 res.data）
- 路由：`router/index.js` 平铺注册，项目子页路径 `/projects/:id/xxx`
- 页面入口：ProjectDetail.vue 顶部导航区聚合项目子页链接
- 组件库：Element Plus；列表页惯用 el-table + el-tag + el-dialog

### 2.2 src/views/ScopeReview.vue

页面结构：

```
├── 头部：标题 + 「新建范围」按钮
├── 新建 dialog：
│    ├── 名称输入
│    └── 基线选择：el-select（选项来自 git-refs：本地分支/远端分支/tag 分组）
│        + 手动输入兜底（allow-create filterable）；非 Git 项目显示提示文案
└── 定义卡片/el-table 列表：
     ├── 字段：名称、基线、状态 tag（draft=灰 confirmed=绿）、条目计数、创建时间
     └── 操作：查看条目（展开行）、确认、重算（仅draft）、删除（仅draft）
└── 条目展开表格：
     ├── 字段：类型 tag、引用、变更类型 tag（ADDED=绿/MODIFIED=橙/AFFECTED=蓝）、
     │        来源 tag（AUTO_DIFF/LLM_MAPPED/MANUAL）、说明、操作（移除）
     └── 手动添加行：类型下拉 + 引用输入 + 变更类型下拉
```

交互要点：

- 创建草稿为长耗时操作（含 LLM 映射）：按钮 loading + 全局 loading 文案"正在识别本期变更…"
- git-refs 加载失败（非 Git 项目）→ 基线下拉降级为 allow-create 空输入 + 警示条
- confirmed 定义只读：隐藏全部写操作按钮
- 错误统一走 request.js 拦截器 ElMessage

## 4. 数据流

```
ScopeReview onMounted → getScopeList
新建 dialog open      → getGitRefs（缓存一次）
createScope 成功       → 刷新列表并自动展开新定义的条目表
confirm/recompute/delete → 操作成功后刷新当前定义与条目
```

## 6. 测试验证

1. npm run build 通过
2. 本地联调：进入某 Git 项目 → 新建范围（选基线）→ 出现 ENDPOINT/AFFECTED 条目 → confirm 后状态变绿且按钮消失
3. 非 Git 项目：git-refs 报错降级 + 创建草稿后端报错正确弹出
