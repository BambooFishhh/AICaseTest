# 后端技术评审 v8.8.2 — 双实例就绪 + 积压可观测 + 混沌演练固化

> 版本 v8.8.2，一旦确定尽量不要轻易改动。基线 v8.8.1。任务 10.4–10.6。纯后端版本。

## 一、变更点

### 1.1 补锁（10.4）

四个既有任务新增 @SchedulerLock（锁表/Provider 复用 v8.6.1 的 shedlock 体系）：

| 方法 | 锁名 | lockAtMostFor / AtLeastFor |
|---|---|---|
| HaTaskScheduler.recoverStaleTasks | haRecoverStaleTasks | PT4M / PT10S |
| HaTaskScheduler.expireTasksByTtl | haExpireTasksByTtl | PT9M / PT10S |
| HaTaskScheduler.dispatchQueuedTasks | haDispatchQueuedTasks | PT14S / PT5S |
| DataRetentionService.cleanOldExecutions | dataRetentionClean | PT10M / PT30S |

AtMostFor 均大于调度周期防真空；dispatch 的 14S/5S 匹配 fixedDelay 15S。

### 1.2 积压 Gauge（10.5）

**新增 `observability/TaskBacklogMetrics.java`**：

- @PostConstruct 预注册七状态 Gauge（QUEUED/RUNNING/COMPLETED/FAILED/CANCELLED/NEEDS_REVIEW/DLQ → agent_task_<lower>）
- @Scheduled(fixedDelay=app.backlog.refresh-ms:30000) 读 `AgentTaskRepository.countGroupByStatus()`（既有查询，零新 SQL）原位 set AtomicLong
- 只读刷新幂等，多实例并发无害——刻意不上 ShedLock（与写任务区分）
- MetricsFacade 新增 `gaugeRaw(name, Number holder)`：调用方自持强引用的注册形态

**告警**：AICaseTestRunningBacklogHigh（agent_task_running>5 for 15m）/ AICaseTestQueueStarved（agent_task_queued>20 for 10m）。看板 data-consistency.json 追加任务积压面板（含 NEEDS_REVIEW/DLQ 曲线）。

### 1.3 chaos 分组（10.6）

pom：`<excludedGroups>${surefire.excludedGroups}</excludedGroups>` + properties 默认 `chaos`——日常构建排除；`mvn test -Dgroups=chaos -Dsurefire.excludedGroups=` 显式放行（属性覆盖绕开硬编码限制）。

三测试：

| 类 | 场景 | 断言要点 |
|---|---|---|
| chaos/MalformedOutputChaosTest ×4 | 截断数组、非数组整段 → 上抛重试；标量/null 条目、嵌套炸弹 steps → 条目级容错不抛异常 | 固化 parseTestCases 两层容错契约 |
| service/MilvusDisconnectChaosTest ×3 | gRPC UNAVAILABLE 终败落补偿表不抛异常；断连反复 upsert 单行；DNS 故障 clone 按 invalidParam 拒绝（真实 .invalid 解析失败模拟） | recordDeleteFailure 幂等语义 |
| chaos/ThreadpoolSaturationChaosTest ×1 | capacity=1 池打满后第三任务被拒且 executor_rejected_total{pool} 计数 | 快速拒绝链路端到端 |

包位置说明：MilvusDisconnectChaosTest 落 com.testagent.service 包（recordDeleteFailure 包级私有，跨包不可见），Tag 分组与包解耦。
