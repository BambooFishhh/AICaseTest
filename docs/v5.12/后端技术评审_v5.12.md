# 后端技术评审 v5.12

**版本**: v5.12
**日期**: 2026-08-16

> 本评审文档对应 v5.12 后端实现，一旦确定尽量不要轻易改动。

## 一、变更点

### 1. AI 评审历史表

新增 `test_case_ai_reviews` 表与实体，保存每次生成/重评的评审结果：

```sql
CREATE TABLE test_case_ai_reviews (
    id VARCHAR(64) NOT NULL,
    project_id VARCHAR(255),
    test_case_id VARCHAR(255),
    status VARCHAR(32),
    issues LONGTEXT,
    suggested_changes LONGTEXT,
    coverage_refs LONGTEXT,
    confidence DOUBLE,
    source VARCHAR(32) DEFAULT 'generation',
    created_at DATETIME(6),
    PRIMARY KEY (id),
    KEY idx_ai_review_project (project_id),
    KEY idx_ai_review_testcase (test_case_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

实体 `TestCaseAiReview` 对应表，仓储提供按用例查最新、按用例/项目删除。

### 2. 评审历史写入器

新增 `AiReviewHistoryRecorder`，统一把 `review + coverageRefs` 写入历史表：

```java
@Component
public class AiReviewHistoryRecorder {
    public void record(TestCase tc, Map<String, Object> review,
                       Map<String, Object> coverageRefs, String source) {
        // 构造 TestCaseAiReview 并 save
    }
}
```

`TestCaseReviewAgent` 在 LLM 评审落结果时调用；`TestCaseService` 在评审失败兜底时也调用。

### 3. suggestedChanges 归一化

`TestCaseReviewAgent.applyReview` 始终写入固定五键对象：

```java
Map<String, Object> suggestions = new LinkedHashMap<>();
suggestions.put("title", null);
suggestions.put("module", null);
suggestions.put("type", null);
suggestions.put("priority", null);
suggestions.put("coverageRefs", null);
// 仅覆盖 LLM 返回的非 null 值
```

### 4. coverageRefs 合并而非覆盖

`applyReview` 改为读取既有 `coverageRefs` 后再合并：

```java
hints.put("coverageRefs", mergeCoverageRefs(existingRefs, llmRefs));
```

规则：`requirementIds / transitionIds / endpointIds / ruleIds` 中，LLM 返回非空列表才替换；空列表保留原值。

### 5. 接口引用过滤

`mergeEndpointRefs` 在有代码清单时只保留真实存在的接口 id，并继续补 `apiEndpoints` 相似匹配结果：

```java
Set<String> validIds = readValidEndpointIds(coverage);
if (validIds.isEmpty() || validIds.contains(normalizedId)) {
    endpointIds.add(normalizedId);
}
```

### 6. 单条重评异步化

新增 `TestCaseReviewRunner`，提交到 `generationExecutor`：

```java
@Component
public class TestCaseReviewRunner {
    public void startReview(String projectId, String testcaseId) {
        testCaseService.markReviewing(projectId, testcaseId);
        generationExecutor.execute(() -> {
            try {
                testCaseService.reviewTestCaseInternal(projectId, testcaseId);
            } catch (Exception e) {
                testCaseService.markReviewFailed(projectId, testcaseId, e.getMessage());
            }
        });
    }
}
```

`TestCaseService` 新增：

- `markReviewing`：置 `aiReview.status=reviewing` 并落库，重复提交返回 409。
- `reviewTestCaseInternal`：执行规则 + LLM 评审，失败时置 `failed`。
- `markReviewFailed`：把状态置为 `failed`，保留规则兜底并写历史。

### 7. 采纳/忽略同步

`UpdateTestCaseRequest` 新增 `reviewStatus`。`updateTestCase` 在收到 `aiReview.status=applied/ignored` 且状态变化时，同步更新该用例最近一条评审历史的状态。

### 8. 覆盖率口径统一

`TestCaseService.calculateCoverage` 改为：

```java
coveredTransitions.addAll(parseCoverageRefTransitions(tc)); // 计划覆盖
if (isExecuted(tc)) {
    coveredTransitions.addAll(parseStateMachineRefTransitions(tc)); // 实际执行
}
```

接口覆盖率同样先并入 `coverageRefs.endpointIds`，再并入已执行用例的 `apiEndpoints`。

## 三、API 契约变化

### POST /api/projects/{projectId}/testcases/{testcaseId}/review

旧契约：同步返回 `TestCaseDTO`。

新契约：立即返回 `ApiResponse<Map<String,Object>>`：

```json
{ "code": 200, "message": "已开始 AI 评审", "data": { "status": "reviewing" } }
```

前端通过原 `GET /api/projects/{projectId}/testcases/{testcaseId}` 轮询 `executionHints.aiReview.status`。

### PUT /api/projects/{projectId}/testcases/{testcaseId}

请求体新增可选 `reviewStatus`，用于 AI 采纳后同步人工评审状态；旧请求体完全兼容。

## 四、向后兼容性

- 旧用例 `executionHints.aiReview` 无 `suggestedChanges` 时，前端按空建议处理，仍可“忽略/重评”。
- 既有重评接口路径不变，只是语义从同步改为异步，前端同步升级。
- 覆盖率统计口径变化为计划 + 执行，接口字段结构不变。
- Flyway 新增 V5 迁移，H2 开发 profile 由 JPA `ddl-auto=update` 自动建表。

## 五、测试验证方案

1. `mvn compile`：BUILD SUCCESS。
2. MySQL Flyway 迁移：启动后确认 `test_case_ai_reviews` 表存在。
3. 手工验证：
   - 重评接口立即返回 `reviewing`。
   - 重评完成后 `aiReview` 含固定五键 `suggestedChanges`。
   - 单条重评不丢失既有 `requirementIds/ruleIds/transitionIds`。
   - 采纳后标题/模块/类型/优先级按非空建议更新，`reviewStatus=reviewed`。
4. 回归验证：生成链路仍写历史，删除用例/项目级联清理。
