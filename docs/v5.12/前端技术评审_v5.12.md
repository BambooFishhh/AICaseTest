# 前端技术评审 v5.12

**版本**: v5.12
**日期**: 2026-08-16

> 本评审文档对应 v5.12 前端实现，一旦确定尽量不要轻易改动。

## 一、变更点

### 1. 重评异步轮询

新增 `frontend/src/utils/aiReview.js`：

```js
export async function pollAiReview(projectId, tcId, { intervalMs = 2000, maxAttempts = 180 } = {}) {
  for (let i = 0; i < maxAttempts; i++) {
    await new Promise((resolve) => setTimeout(resolve, intervalMs))
    const res = await getTestCase(projectId, tcId)
    const review = res.data?.executionHints?.aiReview
    if (!review || review.status !== 'reviewing') return review || null
  }
  return null
}
```

`TestCaseCard.vue` 与 `TestCaseList.vue` 的“重新评审”改为：

```js
await reviewTestCase(projectId, tcId)
const review = await pollAiReview(projectId, tcId)
```

不再依赖同步长连接，避免 30s axios 超时。

### 2. suggestedChanges 非空判断

新增 `hasSuggestedChanges(review)`：

```js
export function hasSuggestedChanges(review) {
  const s = review?.suggestedChanges
  if (!s) return false
  return Object.values(s).some((v) => v !== null && v !== undefined)
}
```

卡片中的“建议修改”区块改用它判断，避免固定五键对象被误判为有建议。

### 3. 采纳只提交非空建议

`applyAiReview` / `applyAiReviewRow` 改为：

```js
if (s.title) body.title = s.title
if (s.module) body.module = s.module
if (s.type) body.type = s.type
if (s.priority) body.priority = s.priority
if (s.coverageRefs) nextHints.coverageRefs = s.coverageRefs
body.reviewStatus = 'reviewed'
```

有建议时真正修改用例字段；无建议时只把 `aiReview.status` 标记为 `applied`，并把人工 `reviewStatus` 置为 `reviewed`。

### 4. 状态文案补齐

`reviewStatusText` / `aiReviewStatusText` 增加：

| 状态 | 文案 | Tag 类型 |
|---|---|---|
| `reviewing` | 评审中 | warning |
| `failed` | 评审失败 | danger |
| `rule` | 规则兜底 | info |

## 二、props / emit 变化

- `TestCaseCard.vue` props/emit 不变。
- `emit('reviewUpdated', updated)` 仍保留，重评完成后改为传入轮询后取回的最新 `TestCaseDTO`。
- `TestCaseList.vue` 无新增 props。

## 三、数据流

1. 用户点击“重新评审”。
2. 前端 `POST /testcases/{id}/review`，立即收到 `{status:"reviewing"}`。
3. 前端每 2s 轮询 `GET /testcases/{id}`，读取 `executionHints.aiReview.status`。
4. 状态离开 `reviewing` 后刷新列表/统计；`failed` 时提示错误信息。
5. 用户点击“采纳”，前端只提交非空 `suggestedChanges` 字段与 `reviewStatus=reviewed`。

## 四、向后兼容性

- 旧数据 `aiReview` 无 `suggestedChanges` 时按“无建议”处理，不阻断展示。
- 重评按钮加载态沿用 `reviewing` / `reviewingId`，不需要新全局状态。
- AI 评审结果表仍从当前列表数据派生，分页参数保持原样。

## 五、测试验证方案

1. `npm run build` 成功。
2. 手工验证：
   - 重评接口立即返回，按钮进入加载态，完成后自动刷新。
   - 有建议的用例“采纳”后字段真正变化，`reviewStatus` 显示 reviewed。
   - 无建议的用例“采纳/忽略”不报错，状态正确展示。
   - 评审失败时显示 `failed`，不会一直停留在 `reviewing`。
