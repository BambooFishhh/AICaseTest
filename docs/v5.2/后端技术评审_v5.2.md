# 后端技术评审 v5.2：Redis 运行态接入

> 版本 v5.2，一旦确定尽量不要轻易改动。

## 1. 变更点

### 1.1 新增 runtime 包

| 类 | 职责 |
|---|---|
| RuntimeStore | 运行态存储接口 |
| MemoryRuntimeStore | 内存实现（默认） |
| RedisRuntimeStore | Redis 实现（Lua 信号量 + Hash/Value） |
| CancellationSignal | 取消信号接口 |
| RuntimeFlag | 本地 + 存储层双重取消标志 |
| RuntimeStoreConfig | 按 `app.redis.enabled` 选择实现 |

### 1.2 关键代码

```java
@Configuration
public class RuntimeStoreConfig {
    @Bean
    @ConditionalOnProperty(name = "app.redis.enabled", havingValue = "true")
    public RuntimeStore redisRuntimeStore(StringRedisTemplate redisTemplate) {
        return new RedisRuntimeStore(redisTemplate);
    }

    @Bean
    @ConditionalOnProperty(name = "app.redis.enabled", havingValue = "false", matchIfMissing = true)
    public RuntimeStore memoryRuntimeStore() {
        return new MemoryRuntimeStore();
    }
}
```

```java
public interface CancellationSignal {
    boolean isCancelled();
    void cancel();
}
```

`TestGeneratorAgent` / `OrchestratorAgent` 的取消参数由 `AtomicBoolean` 改为 `CancellationSignal`，`TestCaseService` 使用 `RuntimeFlag`，取消时同步写 Redis。

### 1.3 服务改造

- `TestCaseService`：`cancellationFlags` 改为 `RuntimeFlag`，生成/追加生成完成时 `clear()`。
- `ExecutionService`：取消标志 / 会话 / 心跳全部走 `RuntimeStore`；`markRunningCancelled` 从 Redis 取会话并强制关浏览器。
- `ProjectExecutionLimiter`：改用 `RuntimeStore.acquire/releaseProjectPermit`（Redis Lua 计数）。
- `LoginAttemptService`：计数与锁定迁入 `RuntimeStore`。

## 3. API 契约变化

无 REST API 变化。

## 4. 向后兼容性

- 默认 `APP_REDIS_ENABLED=false`，完全兼容原内存行为。
- Redis 开启但不可用时单操作降级内存，不阻断流程。

## 5. 测试验证方案

- `mvn compile` / `mvn test`。
- 启动 Redis（compose）后设置 `APP_REDIS_ENABLED=true` 冒烟：触发生成取消、执行取消、登录失败锁定。
- 停掉 Redis 后确认服务仍可启动并降级。
