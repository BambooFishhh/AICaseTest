# 后端技术评审 v9.3 — 断言占位符元描述剔除 + 编号模块归组重编

> 版本 v9.3，一旦确定尽量不要轻易改动。基线 v9.2。

## 一、变更点

### 1.1 断言（ExecutionAssert）

- **stripPlaceholderClauses(expected)**：按子句切分（`，|,|；|;|。|并且|同时|以及|且`），含占位符的子句整体剔除后再做中文段/英文 token 提取——层 1（URL/标题）与层 2（DOM 文本）提取均改用剔除后的文本；
- **CLAUSE_PLACEHOLDER**：`(?<![a-zA-Z0-9])[A-Z](?![a-zA-Z0-9])|\{[^}]*\}`。**不能用 `\b`**：Java 的 `\b` 是 Unicode 感知的（汉字算词字符），"且N为"中 N 两侧形不成词边界——占位符元描述恰恰把 N 嵌在中文里；显式 lookaround 允许紧贴中文；
- 引号短语校验不变：`placeholderPhraseRegex`（字面段+\d+）仍是权威判定，页面无该形态照样 failed；无占位符子句保持原字面/ngram 校验强度；
- 顺带修复：`{orderId}` 变量名此前被 ASSERT_TEXT_TOKEN 抽成英文 token 要求页面出现 "orderId"。

### 1.2 编号重编（TestCasePersistenceService / TestCaseService）

- `resequenceProjectSeq(projectId)`（@Transactional）：projectSeq 升序为基准序 → 模块按首次出现建组（LinkedHashMap，null/空白归"未分类"）→ 组内保持原相对顺序重编 1..N → saveAll；
- 挂钩五个落库收口：replaceAll（重新生成）、追加生成、JSON 导入、XMind 导入、copyToProject；id（TC-xxx 全局主键）不受影响；
- 存量数据：同规则 SQL（窗口函数 ROW_NUMBER OVER [PARTITION BY project_id ORDER BY 模块首次序, 组内序]）一次性重编全部 6 项目。
