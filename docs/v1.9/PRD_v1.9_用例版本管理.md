# PRD v1.9 — 用例版本管理

**版本**: v1.9
**基线**: v1.8
**日期**: 2026-08-09
**主题**: 用例历史版本快照 + 版本列表 + 对比差异 + 回滚

---

## 一、背景与痛点

v1.0–v1.8 已围绕用例生成、质量、体验、批量、可视化、高可用、导入导出、评审状态完成 9 个版本迭代，用例侧功能较完善。但在用例**编辑与回溯**层面存在明显缺口：

1. **编辑不可撤销**：用户在 TestCaseCard 编辑结构化步骤/字段后保存（`updateTestCase`），旧内容直接被覆盖，无法找回。误编辑会导致内容丢失。
2. **无变更追溯**：团队成员无法查看一条用例"从生成到现在改过哪些、改成什么样"，评审时缺少变更依据。
3. **无法回滚**：发现某次编辑把用例改坏后，只能手动改回，缺少一键回滚到任意历史版本的能力。

虽然 v1.3 已为"重新生成"加了确认提示、v1.7 提供了导出备份，但都无法覆盖"日常编辑"这一最高频的变更场景。

## 二、目标

为用例编辑引入**版本快照机制**：每次保存编辑前自动保留一份历史快照，支持查看历史版本、对比当前差异、一键回滚。让用例具备完整的变更可追溯与可回滚能力。

## 三、范围

### In Scope（本次实现）

- **编辑触发版本快照**：`updateTestCase` 保存前，为该用例创建一条版本快照（action=edit），保留编辑前的完整内容。
- **回滚触发版本快照**：回滚操作前，把当前内容也存一份版本（action=rollback），保证回滚本身可撤销。
- **版本列表查询**：按用例查询其历史版本列表（版本号、动作、时间），不含快照正文以减小传输。
- **版本详情查询**：查询单个版本的完整快照内容，用于查看与对比。
- **版本对比**：前端将某历史版本与当前用例逐字段对比，高亮变化字段。
- **版本回滚**：将用例内容回滚到指定历史版本（二次确认），回滚后列表刷新。
- 生成覆盖（`runGenerate` 的 `deleteAll`）**不纳入**本次版本管理（已有 v1.3 确认 + v1.7 导出备份兜底）。

### Out of Scope（本次不做，留待后续）

- 重新生成覆盖前的全量用例快照与整体回滚（涉及项目级快照实体，复杂度高，v1.x MVP 不做）。
- 版本数量上限与自动清理策略（先用 H2 存储，后续视数据量再加 retention 策略）。
- 跨用例的批量回滚。
- 版本 diff 的行级精细化展示（本次仅字段级 diff）。

## 四、功能详情

### 4.1 版本数据模型

新增 `test_case_versions` 表：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | VARCHAR(PK) | UUID |
| test_case_id | VARCHAR | 关联用例 ID |
| project_id | VARCHAR | 项目 ID（便于隔离与清理） |
| version_no | INT | 该用例的版本序号，自增 |
| snapshot | TEXT | 用例完整字段 JSON 快照 |
| action | VARCHAR | 触发动作：`edit` / `rollback` |
| created_at | DATETIME | 版本创建时间 |

### 4.2 触发时机

| 时机 | action | 说明 |
|------|--------|------|
| `updateTestCase` 保存前 | `edit` | 保留编辑前内容 |
| `rollbackToVersion` 回滚前 | `rollback` | 保留回滚前内容，使回滚可撤销 |

### 4.3 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/projects/{projectId}/testcases/{tcId}/versions` | 版本列表（精简，无 snapshot 正文） |
| GET | `/projects/{projectId}/testcases/{tcId}/versions/{versionId}` | 版本详情（含 snapshot 解析后字段） |
| POST | `/projects/{projectId}/testcases/{tcId}/versions/{versionId}/rollback` | 回滚到该版本 |

### 4.4 前端交互

- 用例详情对话框（TestCaseCard）新增"历史版本"按钮。
- 点击弹出抽屉：列表展示该用例所有历史版本（版本号、动作 tag、时间、"查看""回滚"操作）。
- 点击"查看"：展示该版本快照内容（只读），并与当前用例做字段级 diff，变化字段高亮（如标题/模块/步骤数等）。
- 点击"回滚"：二次确认后回滚，列表与详情刷新。
- 动作 tag：edit（蓝）/ rollback（橙）。

## 五、验收标准

1. 编辑一条用例并保存 → 该用例版本列表新增一条 `edit` 记录，快照内容为编辑前的内容。
2. 查看版本详情 → 快照字段与编辑前一致。
3. 版本对比 → 变化字段被正确高亮（如修改了 title，title 标记为"已变更"）。
4. 回滚到某版本 → 当前用例内容变为该版本快照内容；版本列表新增一条 `rollback` 记录。
5. 回滚后再回滚（撤销回滚）→ 可行，因回滚前已存 `rollback` 版本。
6. 历史用例（v1.9 前数据）无版本记录时，列表为空，不报错。
7. 后端编译 BUILD SUCCESS；前端 `npm run build` 成功。

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 快照存储占用增长 | MVP 不设上限；后续可加 retention（如保留最近 20 条） |
| 回滚与并发编辑冲突 | 回滚接口带 `@Transactional`；MVP 单用户场景不处理乐观锁 |
| 历史用例无版本 | 列表为空兜底，前端展示"暂无历史版本" |
| 快照 JSON 解析失败 | 服务端解析异常时返回空对象，不阻断列表 |
