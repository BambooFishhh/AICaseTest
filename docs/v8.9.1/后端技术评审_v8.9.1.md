# 后端技术评审 v8.9.1 — 部署层凭据清零 + MCP 来源过滤提层

> 版本 v8.9.1，一旦确定尽量不要轻易改动。基线 v8.8.2。任务 12.3 + 12.4。

## 一、变更点

### 1.1 compose 弱默认清零（12.3）

docker-compose.yml 八处改 `:?` 必填语法（报错中文）：

```yaml
# mysql
- MYSQL_ROOT_PASSWORD=${MYSQL_ROOT_PASSWORD:?MYSQL_ROOT_PASSWORD 必须设置}
- MYSQL_PASSWORD=${MYSQL_PASSWORD:?MYSQL_PASSWORD 必须设置}
# healthcheck 同步去默认
test: [... "-p${MYSQL_ROOT_PASSWORD}" ...]
# redis
command: ["redis-server", "--requirepass", "${REDIS_PASSWORD:?REDIS_PASSWORD 必须设置}", ...]
- REDIS_PASSWORD=${REDIS_PASSWORD:?REDIS_PASSWORD 必须设置}
# minio（Milvus 对象存储层）
- MINIO_ACCESS_KEY=${MINIO_ACCESS_KEY:?MINIO_ACCESS_KEY 必须设置}
- MINIO_SECRET_KEY=${MINIO_SECRET_KEY:?MINIO_SECRET_KEY 必须设置}
# milvus
- COMMON_SECURITY_ROOTPASSWORD=${MILVUS_ROOT_PASSWORD:?MILVUS_ROOT_PASSWORD 必须设置}
# backend 注入
- MYSQL_PASSWORD=${MYSQL_PASSWORD:?...}   - REDIS_PASSWORD=:?   - MILVUS_PASSWORD=${MILVUS_ROOT_PASSWORD:?...}
- MCP_BRIDGE_TOKEN=${MCP_BRIDGE_TOKEN:?MCP_BRIDGE_TOKEN 必须设置}
# grafana 注入
- MYSQL_PASSWORD=${MYSQL_PASSWORD:?...}
```

非敏感项（端口、模型名等）维持默认不动。`.env.example` 新增键全部给出强占位示例并标注"v8.9.1 新增必填"。

**CI 适配**：ci.yml compose 校验步骤 env 注入八键占位值（与必填清单同处注释互相锚定，后续加必填项需同步）。

**存量卷兼容**：本机 `.env` 追加的值对齐现有数据目录初始化凭据（MySQL/Milvus 凭据固化于首次初始化），升级不破坏运行栈；生产首次部署应设随机强值（README 已标注）。

### 1.2 MCP 来源过滤提层（12.4）

**新增 `security/McpSourceFilter.java`**（OncePerRequestFilter，非 Bean）：

```java
public class McpSourceFilter extends OncePerRequestFilter {
    private final Set<String> allowedRemoteAddrs;   // 含回环语义由 resolveClientIp 统一判定
    private final boolean trustProxy;

    protected boolean shouldNotFilter(req) { return !req.getRequestURI().startsWith("/api/mcp/"); }
    doFilterInternal:
        String ip = resolveClientIp(req, trustProxy);
        if (isLoopbackIp(ip) || allowedRemoteAddrs.contains(ip)) { chain.doFilter; return; }
        // 403 JSON：ApiResponse.error(40300, "MCP bridge 仅允许本机回环访问")，status 403

    public static String resolveClientIp(req, boolean trustProxy) {
        // trustProxy=true：X-Forwarded-For 首跳（trim），空则回落 remoteAddr
        // false：remoteAddr（注释警告：XFF 可伪造，仅可信反代后开启）
    }
    public static boolean isLoopbackIp(String ip) { 127.* / ::1 / 0:0:0:0:0:0:0:1 }
}
```

**SecurityConfig**：注入 `@Value("${app.mcp.allowed-remote-addrs:}")` 与 `@Value("${app.mcp.trust-proxy:false}")`，构造 filter 并 `http.addFilterBefore(mcpSourceFilter, JwtAuthFilter.class)`。非 @Component 声明规避 Boot 对 OncePerRequestFilter Bean 的 Servlet 自动注册（防双重执行）。

**McpBridgeController 第二道防线统一口径**：`assertLoopbackSource` 改用 `McpSourceFilter.resolveClientIp(request, trustProxy)`（新增同键 `app.mcp.trust-proxy` 注入），代理场景两层判定一致；白名单判断逻辑不变。

**配置**：application.yml mcp 段新增 `trust-proxy: ${APP_MCP_TRUST_PROXY:false}`（注释警告伪造风险）；`.env.example` 同步。
