# 后端技术评审 v8.8.1 — 多供应商双通道 + 降级路由

> 版本 v8.8.1，一旦确定尽量不要轻易改动。基线 v8.7.2。任务 10.1–10.3。纯后端版本。

## 一、变更点

### 1.1 多模型注册（10.1）

**新增 `config/LlmProviders.java`**（@Component）：

```java
public ProviderSpec primary();                 // name=primary, 复用现有 llm.* 
public ProviderSpec fallback();                // name=fallback, llm.models.fallback.*
public boolean fallbackEnabled();              // base-url/api-key/model 三键齐备
public ChatClient fallbackChatClient();        // 懒构建缓存（ConcurrentHashMap）
public EmbeddingModel fallbackEmbeddingModel();// 三键齐备才构建，双重检查锁
```

程序化构建形态（Spring AI 1.0.0 GA）：

```java
OpenAiApi api = OpenAiApi.builder().baseUrl(fb).apiKey(key).build();
OpenAiChatModel model = OpenAiChatModel.builder().openAiApi(api)
        .defaultOptions(OpenAiChatOptions.builder().model(m).build())
        .retryTemplate(RetryTemplate.builder().maxAttempts(2)
                .retryOn(TransientAiException.class).exponentialBackoff(1000,2000,4000).build())
        .build();
return ChatClient.builder(model).build();
```

primary 不经此类构建——LlmService 直接复用既有自动装配 chatClientBuilder，零迁移风险。

### 1.2 降级路由（10.2）

**LlmService 改造**（chat 与 chatStreaming 同构）：

1. 原方法体改名 `chatWithUsageOn(providerName, ...)` / `chatStreamingOn(...)`：
   - `chatClientFor(providerName)` seam 取客户端（protected 可测）
   - 熔断键 `breakerChannelOf` = text | text:fallback
   - allow/onSuccess/onFailure 全部改用派生键
2. 原签名变为路由包装器：
   ```java
   try { return *On("primary", ...); }
   catch (BusinessException primaryEx) {
       if (providers == null || !providers.fallbackEnabled()) throw primaryEx;
       metrics.increment("llm_fallback_used_total", "channel", ...);
       degradedProvider.set("fallback");
       [流式：先 retryResetHook.run() 清草稿]
       try { return *On("fallback", ...); }
       catch (Exception fb) { throw new BusinessException(50300, "主/降级均不可用", SERVICE_UNAVAILABLE); }
   }
   ```
3. GenerationCancelledException 直接透传不参与路由（用户取消不应换通道续跑）。

**degradedProvider 透出链**：ThreadLocal（同线程语义匹配生成线程模型）→ `consumeDegradedProvider()` → TestGeneratorAgent.generateAllRounds 出口写 report.degradedProvider → toMap 条件输出 → TestCaseService complete 事件条件 put（primary 生成无此键，前端零适配）。

### 1.3 embedding 独立熔断与降级（10.3）

EmbeddingService.embed 重构为三段：熔断检查（open 则跳过主模型直奔降级）→ 主模型 embed（成功 onSuccess / 可重试异常 onFailure，4xx 不计）→ 降级端点兜底（providers.fallbackEmbeddingModel()，未配置返回空向量保持既有语义）。常量 `CHANNEL_EMBEDDING = "embedding"`。

```yaml
  models:

      base-url: ${LLM_FALLBACK_BASE_URL:}

```
