# 前端技术评审 v7.8 — 评审闭环与覆盖率可信

> 版本 v7.8，一旦确定尽量不要轻易改动。基线 v7.7。本版含前端改动：覆盖矩阵双栏（计划/执行）展示 + 用例详情模糊接口提示。

## 一、变更点

### 1.1 覆盖矩阵双栏（R7）`src/components/CoverageMatrix.vue`
后端 `CoverageService.getCoverageMatrix` 将覆盖度量拆为两栏：
- **计划覆盖（planned）**：任一用例 `coverageRefs` 引用即算，不要求执行。
- **执行覆盖（executed）**：已执行（passed/failed）用例 `coverageRefs` **并** `stateMachineRef.transitions` 引用。

前端同步**双栏展示**（计划/执行各一个 rate），避免"计划 80%"与"验证 80%"度量语义混淆。向后兼容：`covered/rate` 语义改为 planned（与旧主路径一致），兜底路径变化仅影响"执行过的用例 smRef 补充覆盖"场景。

### 1.2 用例详情模糊接口提示（R3）`src/components/TestCaseCard.vue`
后端 `fuzzyEndpointIds` 记录模糊匹配到的 endpoint id，前端用例详情对"该接口引用为模糊匹配，请人工确认"给出轻量提示。

### 1.3 评审修正展示（R1 辅助）
高置信评审修正（`coverageRefs`/`priority`）自动生效并登记于 `aiReview.autoApplied`；未采纳项（title/module/type）保留 `suggestedChanges` 供前端"待人工确认"展示。前端分数展示无阈值逻辑（G6 口径变化为相对值）。

## 二、文件变更清单
`src/components/CoverageMatrix.vue`（R7 双栏展示）；`src/components/TestCaseCard.vue`（R3 fuzzy 提示）。

## 三、前端契约变化
- 覆盖矩阵接口返回双栏（planned/executed）；`covered/rate` 语义改为 planned。
- 用例详情展示 `executionHints.fuzzyEndpointIds` 模糊提示。
- `aiReview.autoApplied`/`suggestedChanges` 供"待人工确认"入口。

## 四、验证结果
前端 `npm run build` 通过；后端 `mvn compile` + 相关单测通过；`CoverageMatrix.vue` 双栏回归无破坏。
