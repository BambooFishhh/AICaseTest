### 2.1 G7：需求 ID 内容 hash 稳定化

```java
// TestGeneratorAgent.buildCoverageChecklist
// 旧：int i = 1; item.put("id", "req-" + i++);
String title = String.valueOf(req.getOrDefault("title", ""));
String description = String.valueOf(req.getOrDefault("description", ""));
item.put("id", "req-" + contentHash(title, description));

// 新增私有方法（包级可见供单测）
String contentHash(String... parts) {
    String joined = String.join("\u0001", parts);  // 分隔符用不可见控制字符，避免拼接歧义
    byte[] digest = MessageDigest.getInstance("SHA-256")
            .digest(joined.getBytes(StandardCharsets.UTF_8));
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < 5; i++) {  // 前 5 字节 = 10 个十六进制位
        sb.append(String.format("%02x", digest[i]));
    }
    return sb.toString();
}
```

- RAG 并入项同款：`"rag-" + contentHash(title, slice)` 取代 `rag-req-N`（rag- 前缀保留 source 区分，不再需要序号）。
- 同内容需求在 checklist 内可能重复出现（PRD 解析出两条同 title+description）→ hash 相同 id 重复。处理：`Set<String> seen` 去重，重复项跳过（同内容需求本就该合并）。
- prompt 表述同步（3 处 skill 文件 + 2 处内联常量）：
  - `resources/skills/test-generation-prd-footer.md`、`ai-review.md`、`test-generation-code-footer.md` 中 `requirementIds 用 "req-N"` → `requirementIds 原样使用 coverageChecklist.requirements[].id`；
  - `TestGeneratorAgent` SYSTEM_PROMPT L389 同步；`TestCaseReviewAgent` 内联 L149 同步。
- few-shot 示例中 `"req-1"` 字面量保持不变（示例仅演示结构，且 hash id 无法在示例中预先计算——加注释说明）。

### 2.8 R5：reject 保护三分带

```java

    prdResult.setEvidenceInconsistencies(inconsistencies);
}
```
