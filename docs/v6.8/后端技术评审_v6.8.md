# 后端技术评审 v6.8

> 版本 v6.8，一旦确定尽量不要轻易改动。主题：高可用 P3 - 队列与多实例。

## 1. 变更点

### 1.1 Redis Streams 事件总线

新增 `service/TaskEventStreamService.java`：

- `publish(taskId)`：XADD 到 `aicasetest:task:events`。
- `consume(batchSize)`：XREADGROUP + 立即 ACK（事件丢失由 DB 轮询兜底）。
- Redis 不可用时不抛错，返回空列表。

`AgentTaskService.createTask/createTaskWithId` 落库后发布事件；`HaTaskScheduler` 先消费事件，再做 DB 轮询。

### 1.2 CAS 抢占

`AgentTaskRepository.claimQueued`：

```sql
UPDATE AgentTask t SET t.status=..., t.leaseOwner=..., t.leaseExpireAt=...
WHERE t.id=:id AND t.status='QUEUED'
```

`AgentTaskService.claimQueued(taskId)` 返回是否抢占成功；`TaskRetryDispatcher.dispatchQueued` 抢占失败即返回。

### 1.3 本地状态迁 Redis

- `AnalysisService`：`ConcurrentHashMap` 替换为 `RuntimeStore` flag `analysis:running:{projectId}`。
- `ExecutionService`：删除 `executionCancellations` Map，`isExecutionCancelled` 改为 `runtimeStore.isFlagSet("exec:cancel:"+id)`。

### 1.4 告警

`monitoring/prometheus/alerts.yml` 新增 DLQ 与任务失败率规则。

## 2. API 契约变化

无 REST 契约变化；Redis Streams 为内部事件。

## 3. 向后兼容性

- DB 轮询调度保留，Redis 事件只是加速信号。
- RuntimeStore flag 在 Redis/内存双实现，单实例行为不变。

## 4. 测试验证方案

- `AgentTaskServiceTest.claimQueuedUsesCasUpdate`。
- 回归 `mvn verify`、`npm run build`。
- 部署后验证 Redis Stream 有事件、多实例领取幂等。
