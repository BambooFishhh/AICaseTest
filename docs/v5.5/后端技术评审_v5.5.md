# 后端技术评审 v5.5：正式切换与全量回归

> 版本 v5.5，一旦确定尽量不要轻易改动。

## 1. 变更点

### 1.1 profile 组

`application.yml` 增加：

```yaml
spring:
  profiles:
    group:
      prod: mysql
      migrate: mysql
```

替代原先在 profile 专用文件里写 `spring.profiles.include`（后者在 profile 专用资源中非法，已修复）。

### 1.2 prod 默认全栈

`application-prod.yml`：

```yaml
app:
  redis:
    enabled: ${APP_REDIS_ENABLED:true}
  milvus:
    enabled: ${APP_MILVUS_ENABLED:true}
```

### 1.3 健康检查

`HealthController` 注入 `DataSource` / `RuntimeStore` / `MilvusService`，返回：

- `dataSource`：连接校验 UP/DOWN。
- `redis`：RedisRuntimeStore 时 "redis"，否则 "memory"。
- `milvus`：开关状态 enabled/disabled。

### 1.4 compose

- 后端 `depends_on` mysql/redis/milvus 健康条件。
- 注入 `MYSQL_URL` / `REDIS_HOST` / `MILVUS_HOST` / `APP_REDIS_ENABLED` / `APP_MILVUS_ENABLED`。

## 2. 文件变更清单

| 文件 | 变更 |
|---|---|
| resources/application.yml | profile group + Redis 默认 host 127.0.0.1 |
| resources/application-prod.yml | 默认启用 Redis/Milvus |
| resources/application-migrate.yml | 移除非法 include |
| controller/HealthController.java | 组件健康状态 |
| dto/HealthDTO.java | 新增字段 |
| docker-compose.yml | 后端依赖与连接环境 |
| scripts/verify-v5-stack.ps1 | 新增全量回归脚本 |

## 3. API 契约变化

- `/api/health` 响应新增 `dataSource` / `redis` / `milvus` 字段，向前兼容。

## 4. 向后兼容性

- 默认（无 profile）仍为 H2 开发模式。
- prod 必须提供 MySQL/Redis；Milvus 可关闭。

## 5. 测试验证方案

- `scripts/verify-v5-stack.ps1` 全量回归。
- prod + MySQL + Redis 冒烟：健康检查、登录锁定、50 并发请求。
