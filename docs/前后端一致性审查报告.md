## 二、响应格式一致性

后端约定的统一响应格式 vs 前端拦截器解析：

| 项 | 后端约定 | 前端处理 | 一致性 |
|----|----------|----------|--------|
| 成功响应 | code=0 | 检查 code===0 ✅ | ✅ |
| 异步任务 | code=202 | 检查 code===202 ✅ | ✅（已修复） |
| 错误响应 | code=40001-50003 | 非0且非202时 reject | ✅ |
| HTTP错误 | HTTP 4xx/5xx | error.response.data.message | ✅ |

**修复记录**：前端拦截器原先只处理 code===0，未处理 code===202（异步任务响应），已修复。

## 四、业务流程一致性

### 4.1 项目生命周期流程

```
后端状态机：created → analyzing → analyzed → generating → completed
前端处理：
  - 项目列表页：展示所有状态 ✅
  - 项目详情页：按状态控制按钮可用性 ✅
  - 轮询机制：analyzing/generating 期间每3秒轮询 ✅
  - 状态变更：analyzed/completed/failed 时停止轮询 ✅
```

### 4.2 异步任务流程

```
后端：POST → 202响应 → @Async 线程池 → 更新status
前端：POST → 收到202 → 启动轮询 → 检查status → 停止轮询

一致性：✅
```

### 4.3 状态机可视化数据流

```
后端：状态机 JSON → states + transitions + forbidden_transitions
前端：ECharts graph → nodes(states) + edges(transitions)
  节点颜色映射：is_initial=绿, is_terminal=蓝, 普通=灰
  边样式映射：正常转换=实线, 禁止转换=虚线

一致性：✅
```
