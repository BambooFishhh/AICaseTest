# PRD v3.11 — 执行闭环补全

**版本**：v3.11
**基线**：v3.10（含 12f0795 前端界面重构 flush 提交）
**日期**：2026-08-12
**主题**：执行结果回写用例状态 + 执行历史页 + 覆盖率矩阵跳转修复，打通"生成→执行→结果→回看"闭环

---

## 一、迭代背景与痛点

系统已具备单条/批量执行、结果详情、录屏与报告能力，但执行数据与用例数据之间存在断点：

1. **执行状态不回写**：用例执行完（无论单条还是批量），列表与详情里 `executionStatus` 永远是"未执行"，用户跑完看不到结果。
2. **无执行历史入口**：后端 `GET /api/projects/{projectId}/executions` 接口与前端 `getExecutions()` 封装均已存在，但没有任何页面调用，用户无法总览"这个项目跑过哪些用例、结果如何"。
3. **覆盖率矩阵跳转失效**：覆盖率矩阵"关联用例 N 条"点击后把用例 ID 塞进 keyword 搜索，但 keyword 只匹配标题/模块，筛选结果为空，无法从"未覆盖转换"定位到对应用例。

## 二、范围

### In scope

- 后端：执行开始时用例状态置 `running`，结束时回写 `passed/failed`（单条 + 批量，programmatic + agent 两种模式）
- 前端：新增"执行历史"页（列表 + 汇总统计 + 详情/报告入口）
- 前端：项目详情、用例列表增加"执行历史"入口
- 前端：修复覆盖率矩阵→用例跳转（内存按 ID 筛选 + 清除筛选引导）

### Out of scope

- 用例列表"执行状态列 + 筛选 + 失败一键重跑"（v3.12，P1-1）
- 评审→执行承接、批次失败摘要（v3.12）
- 默认执行 URL、生成前置预检（v3.12）
- 任何安全、并发、性能相关改动

## 三、功能详情

### 3.1 执行状态回写（后端）

- `ExecutionService.execute()`：执行启动时 `testCase.executionStatus = "running"` 并保存
- `runAgentAsync` / `runAsync` 完成阶段：按最终结果回写 `passed` / `failed`
- 新增私有方法 `updateTestCaseExecutionStatus(testCaseId, status)`，失败仅告警不阻断执行记录落库

### 3.2 执行历史页（前端新增）

- 路由：`/projects/:id/executions`（列表），与现有 `/projects/:id/executions/:eid`（详情）并存
- 页面内容：
  - 顶部汇总卡：总计 / 通过 / 失败 / 运行中 / 通过率
  - 执行记录表格：用例标题、模式（programmatic/agent）、状态、耗时、批次、开始时间、操作（查看详情、下载报告）
  - 空状态：引导去用例列表执行
  - 刷新按钮手动刷新（不做自动轮询，保持简单）
- 行点击 / "查看详情" → 跳转执行结果页

### 3.3 入口

- 项目详情"查看"操作卡：新增"执行历史"按钮
- 用例列表页头操作区：新增"执行历史"按钮

### 3.4 覆盖率矩阵跳转修复（前端）

- 新增 `idFilter` 状态：`handleFilterByIds(ids)` 在内存中按 ID 过滤展示，不再依赖 keyword 搜索
- 表格上方显示筛选横幅（命中 N 条 + 清除筛选按钮）
- 与优先级筛选可叠加；模块分组逻辑不变

## 四、验收标准

1. 单条/批量执行开始后，用例状态在列表/详情显示"执行中"
2. 执行结束后，用例状态自动变为"通过/失败"
3. 执行历史页展示全部记录，统计卡数字与记录一致，可跳详情与下载报告
4. 覆盖率矩阵点击关联用例后，列表只展示对应用例并出现清除筛选横幅
5. 后端 `mvn compile` BUILD SUCCESS；前端 `npm run build` 成功

## 五、风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 状态回写与执行记录更新不一致 | 用例状态与结果页不一致 | 回写失败仅告警不抛错；以 ExecutionRecord 为权威 |
| 历史接口数据量大 | 页面渲染慢 | 本期仅展示最近记录（接口按时间倒序，前端列表展示全部，数据量增长后做分页） |
| 覆盖率筛选与既有筛选冲突 | 展示混乱 | idFilter 独立于 filters，清除按钮一键还原 |
