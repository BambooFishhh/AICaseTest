## 一、变更点

### 1.1 vueLlmExecutor 共享池（C8）

`config/AsyncConfig.java` 新增：

```java
@Bean(destroyMethod = "shutdown")
public ExecutorService vueLlmExecutor(
        @Value("${app.executor.llm-concurrency:4}") int llmConcurrency) {
    ThreadPoolTaskExecutor te = new ThreadPoolTaskExecutor();
    te.setCorePoolSize(n); te.setMaxPoolSize(n);
    te.setThreadNamePrefix("vue-llm-");
    te.setTaskDecorator(new MdcTaskDecorator());   // 补齐 MDC 装饰缺口
    te.initialize();
    return te.getThreadPoolExecutor();             // destroyMethod=shutdown 归容器管理
}
```

**VueAnalyzer**：

- 字段 `private ExecutorService vueLlmExecutor;` 默认 null + @Autowired(required=false) setter；
- 组件摘要并发块改为：`pool = vueLlmExecutor != null ? vueLlmExecutor : Executors.newFixedThreadPool(workers)`，finally 仅在**非借用共享池**时 shutdown；
- telemetryCtx/bindPhase 手工传播保留（TelemetryContext 是埋点上下文而非 MDC，两者互补不冲突）。

### 1.2 并发压测工具与数据（12.7）

新增 `perf/load-shortrequests.ps1`：Start-Job N worker（独立进程规避此前 runspace 注入问题），各自顺序请求 health/projects 固定次数并收集耗时，父进程聚合去装箱合并统计。

**实测**（8 worker × 150 = 1200 请求，5.9s）：

| Requests | Failures | ElapsedS | RPS | P50ms | P95ms | MaxMs |
|---|---|---|---|---|---|---|
| 1200 | 0 | 5.9 | 202.4 | 15 | 82 | 103 |

结论回填容量报告：零失败 + P95<100ms 印证 C1 连接池对齐后连接竞争消除（CR §9.3 C1 闭环的数据面证据）。
