# PRD v4.2 — 多线程高并发治理

**版本**：v4.2
**基线**：v4.1
**日期**：2026-08-13
**主题**：线程池参数化 + 独立执行池 + 项目级并发配额 + 批量执行排队与取消 + 幂等

## 一、背景与痛点

1. 批量执行（Agent 模式）复用 `analysisExecutor` 线程池，20 条批量会把代码分析任务挤到 CallerRunsPolicy，分析阻塞在请求线程
2. 批量执行一次性全量并发提交，无并发上限、无排队概念，批次页看不到"排队中"
3. 批量不可取消；同一用例可被重复触发执行
4. 线程池参数硬编码在代码里，无法按环境调整

## 二、范围

### In scope

- 线程池参数化（application.yml）+ 新增独立 `executionExecutor`
- 项目级执行并发配额（默认 3，可配置），超出排队
- 批量执行：记录状态 pending（排队中）→ running（运行中），批次接口返回 queued/cancelled
- 批量取消：未开始任务直接置取消，运行中任务在步骤检查点停止
- 执行幂等：同一用例已有 running 记录时拒绝重复触发
- 前端：批次页排队/取消统计与取消按钮；cancelled 状态展示

### Out of scope

- 分布式部署、消息队列
- 数据库性能调优

## 三、验收标准

1. 批量执行不再占用分析线程池
2. 同一项目同时执行数不超过配额，其余排队（批次页可见）
3. 批次可取消：排队任务立即取消，运行中任务尽快停止
4. 同一用例重复触发被拒绝并提示
5. 线程池参数可通过环境变量调整
6. mvn test + npm run build 通过
