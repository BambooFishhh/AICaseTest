# 后端技术评审 v8.9.8 — litemall 实测 12.11~12.14 修复 + 临时移动适配

> 版本 v8.9.8，一旦确定尽量不要轻易改动。基线 v8.9.6。四张修复卡（12.11~12.14）+ 临时移动适配，含前端 SSE 事件消费。

## 一、变更点

### 1.1 临时移动适配（可回退）
`skill/PlaywrightRecordSkill.java` + `application.yml`：
```java
@Value("${app.execution.browser-device:}")   // 默认空=桌面
private String browserDevice;                  // 移动端临时设 iPhone 14，可回退
```
- `browserLaunch` 组装参数时若 `browserDevice` 非空则追加 `device`；`playwright-mcp-server/index.js` 的 `browser_launch` 新增 `device` 参数，命中 `devices[device]` 用预设（含视口/isMobile/touch/UA），否则回落宽高桌面。
- 移动模拟截图实测 **1170×1992 = 390×664 CSS @ 3x**（iPhone 14 生效，不再 B 端失真）。

**登录态注入**：`playwright-mcp-server/index.js` 新增 `browser_set_storage` 工具（`page.evaluate` 写 localStorage）；`PlaywrightRecordSkill.setStorage` + `ExecutionService.injectStorage`（导航后注入项目 `settings.executionStorage`）。因 litemall 为 localStorage token（`litemall_token`），cookie 注入不适用。

### 1.2 12.14 UI 导航缺口
**执行器** `agent/ExecutionAgent.java`：
- `executeStep` 增 baseUrl 重载（6 参，5 参兼容委托）。
- `isNavigationStep`：`uiSelector.type=route` 或 target 匹配 `^/[\w:{}$-]`（frontendRoutes 注入后 LLM 以 `/user` 等为 target）。
- `executeNavigation`：`browserNavigate(joinBase(baseUrl,target))` → `getPageStatus` 校验 URL 含 routeKey；history 拼不到再试 hash 兜底 `baseUrl/#/target`；`okNav` 记 passed。

**生成** `agent/TestGeneratorAgent.java`：
- prompt 硬规则"目标页非首页的 UI 用例第一步必须是导航步骤（uiSelector.type=route）"。
- `frontendRoutes` 注入（`frontendResult.getRoutes()` 截 60 条），作为导航路由唯一来源。

**存量兜底** `service/ExecutionService.java`：
- `buildStepNodes`：含 ui_action 且首步非导航时，读最新分析 `frontendResult.routes`，按标题/模块/首步关键词匹配前置一条 route 导航步骤；无匹配不硬造（记日志）。

### 1.3 12.13 live 评测口径
`eval/EvalRunner.java`：
- 从 `expected.json` 的 endpoints 构造 `BackendResult`（EndpointInfo method/path）注入 `genAgent.generate`。
- 召回改双口径：标题包含（辅助）+ `requirementIdMap` id 匹配（主）。
- `TestGeneratorAgent.setMaxGeneratedCases`（large 30/其余 15，`-Deval.largeGate=` 覆盖）。

**复测**：`eval/results/20260827-052127-live-d2cbd90.json`——**接口覆盖 0.45→1.0**、结构 1.0、召回 0.71。large 覆盖=0 证实为口径假阳性。

### 1.4 12.11 SSE 断连宽限 + 跨实例回放
`service/TestCaseService.java`：
- `onCompletion/onTimeout/onError` 不再立即 `cancel`，改进宽限期 `app.sse.reconnect-grace-seconds:90`，期满无重连才取消（`scheduleGracefulCancel`）。
- 生成期每条用例 `recordGenerationEvent(taskId,"case",caseDtoJson)` 持久化。

`service/AgentTaskService.java`：
- `recordGenerationEvent(taskId,phase,status,payload)`（payload 暂存 `errorMessage`TEXT）。
- `latestGenerationTask(projectId)`（`findFirstByRequestIdAndTaskTypeOrderByCreatedAtDesc`）。

`controller/ProjectController.java`：
- `GET /testcases/generate-stream-replay`：按最新生成任务 + `timeline(taskId)` 回放 phase=case 事件 + progress"任务仍在运行" + complete(replayed=N)。

### 1.5 12.12 排队闸门 + 首事件
`controller/ProjectController.java`：
- 注入 `generationExecutor`（`@Qualifier`）+ `@Value stream-max-queued:8`；`generateStream` 预检队列 ≥ 阈值直接 503"生成繁忙（当前排队 N）"。

`service/TestCaseService.java`：`runGenerateStream` 提交后即时推 `started` 首事件。

## 二、文件变更清单
`skill/PlaywrightRecordSkill`、`agent/ExecutionAgent`、`agent/TestGeneratorAgent`、`service/ExecutionService`、`service/TestCaseService`、`service/AgentTaskService`、`controller/ProjectController`、`eval/EvalRunner`、`config/application.yml`、`playwright-mcp-server/index.js`（前端技术部分）；`docs/*`。

## 三、API 契约变化
- 新增 `GET /api/projects/{id}/testcases/generate-stream-replay`（回放已产生 case 事件）。
- `browser_launch` 新增可选 `device`；新增 `browser_set_storage` MCP 工具。
- SSE 新增 `started`/`queued` 事件（前端映射进度文案）。
- 生成队列过深返回 503"生成繁忙（当前排队 N）"（原静默排队）。
