# 前端技术评审 v8.9.8 — SSE 事件消费（started/queued）+ 临时移动适配

> 版本 v8.9.8，一旦确定尽量不要轻易改动。基线 v8.9.6。范围：SSE 生成首事件前端消费 + 临时移动设备模拟与登录态注入（Playwright MCP/后端侧，前端 UI 侧无代码变更）。

## 一、变更点

### 1.1 SSE 首事件消费（12.12）
`frontend/src/api/testcase.js`（`streamGenerate` 与 `streamGenerateAppend` 两处）：
```js
// v8.9.8(12.12): started/queued 事件——即时反馈"已接受/排队"，消灭静默黑洞
es.addEventListener('started', (e) => { try { onProgress?.(JSON.parse(e.data).message) } catch {} })
es.addEventListener('queued', (e) => { try { onProgress?.(JSON.parse(e.data).message) } catch {} })
```
- 后端 `runGenerateStream` 提交后即时推 `started`；排队闸门超限推 `error`（503"生成繁忙"）。
- 前端复用既有 `onProgress` 文案通道，不改既有 `progress/case/complete/retryReset` 契约。

### 1.2 临时移动适配（UI 侧无代码变更，属 Playwright MCP/后端）
- 移动设备模拟在 `playwright-mcp-server/index.js`（`browser_launch` 加 `device`）与后端（`app.execution.browser-device`）实现，前端 UI 无需改动。
- 登录态注入（`browser_set_storage` + `injectStorage`）同样在 MCP/后端，前端 UI 不涉及。

## 二、文件变更清单
`frontend/src/api/testcase.js`（修改）；`playwright-mcp-server/index.js`（修改，MCP 侧）；后端 `application.yml`（配置项）。

## 三、前端契约变化
- 新增事件监听：`started`、`queued`（均映射到 `onProgress` 文案通道）。
- 既有事件（progress/case/complete/cancelled/error/retryReset/onDisconnect）保持不变。

## 四、验证结果
- 前端 Vitest `npx vitest run`：**4 文件 10 用例全通过**（FakeEventSource 覆盖 started/queued 不破坏既有断言）。
- 说明：AICaseTest 前端容器（`test-agent-frontend`）尚未重建，`started/queued` 监听需重建镜像后在 UI 生效。
