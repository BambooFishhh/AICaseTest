## 一、变更点

### 1.1 连接池对齐（12.1）

`application-mysql.yml`：

```yaml
hikari:
  maximum-pool-size: ${HIKARI_MAX_POOL:40}   # 20→40
  minimum-idle: ${HIKARI_MIN_IDLE:10}        # 5→10
  connection-timeout: ${HIKARI_CONNECTION_TIMEOUT:30000}
  leak-detection-threshold: ${HIKARI_LEAK_DETECTION_MS:60000}   # 新增
```

容量依据：analysis 6 + generation 6 + execution 12 + semantic 2 = 26 任务线程 + HTTP 余量 ≤ 40；MySQL max-connections=200 容纳多实例 × 40。泄漏检测超阈值打印 WARN 借出堆栈。只改配置与注释不改代码（任务卡约束）。

### 1.2 LlmRateLimiter（12.2）

新增 `service/LlmRateLimiter.java`（@Component）：

```java
public <T> T execute(String channel, Supplier<T> body)
```

- 通道信号量：text=6 / stream=6 / embedding=4 / fallback-text=4（`llm.rate-limit.*` 五键三件套）
- tryAcquire 超时（wait-timeout-ms 默认 120s）→ 抛 BusinessException(50300, "LLM 并发配额已满(channel)")——可重试语义衔接既有降级路由
- release 于 finally；等待 >5s 计 `llm_rate_limit_wait_total{channel}`；拒绝计 `llm_rate_limit_rejected_total{channel}`（启动零值预注册）

### 1.3 入口接入

| 入口 | 主通道配额 | 降级通道配额 |
|---|---|---|
| chatWithUsageOn（同步） | text | fallback-text |
| chatStreamingOn（流式） | stream | fallback-text |
| EmbeddingService.embed | embedding | —（空向量降级） |

方法体拆分为 On 包装器 + Body 私有实现，包装器以 rateLimiter.execute 包裹（breaker 检查在限流之前，熔断打开快速失败不占配额）。50300 与 v8.8.1 降级路由天然衔接：主配额满自动分流备用供应商。
