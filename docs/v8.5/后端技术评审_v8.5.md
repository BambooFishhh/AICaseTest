# 后端技术评审 v8.5 — 安全闭环

> 版本 v8.5，一旦确定尽量不要轻易改动。基线 v8.4。本文覆盖任务 8.1/8.2/8.3/8.4/8.6（后端+部署），8.5 见前端评审。

## 一、变更点

### 1.1 弱默认密钥清零（8.1）

**`application.yml`**（4 处）：

```yaml
# 旧 → 新（去掉 : 后默认值，缺失即占位符未解析）
jwt:
  secret: ${APP_JWT_SECRET}          # 旧 ${APP_JWT_SECRET:aicasetest-dev-secret-change-me-please-0123456789}
admin:
  password: ${APP_ADMIN_PASSWORD}    # 旧 ${APP_ADMIN_PASSWORD:admin123}
milvus:
  password: ${MILVUS_PASSWORD}       # 旧 ${MILVUS_PASSWORD:aicasetest-milvus}
mcp:
  bridge-token: ${MCP_BRIDGE_TOKEN}  # 旧 ${MCP_BRIDGE_TOKEN:aicasetest-mcp-local}
```

**新增 `config/SecurityKeyGuard.java`**：

- `@Component` 无 profile 注解 = 全 profile 生效；实现 `InitializingBean`，在容器刷新期（早于 `ProductionGuard` 的 CommandLineRunner 执行期）校验。
- `@Value` 注入四键（`:}` 空默认兜底直接 new 场景），任一为空抛 `IllegalStateException`，消息逐项列出缺失环境变量名（`APP_JWT_SECRET` / `APP_ADMIN_PASSWORD` / `MILVUS_PASSWORD` / `MCP_BRIDGE_TOKEN`）。
- 只查"非空"，强度检查（长度/默认值黑名单）仍归 prod 的 ProductionGuard，两层不合并、互不影响。

```java
@Component
public class SecurityKeyGuard implements InitializingBean {
    @Value("${app.jwt.secret:}") private String jwtSecret;
    // ... 四键
    @Override public void afterPropertiesSet() { /* 缺失即 throw */ }
}
```

**为什么不用 EnvironmentPostProcessor**：spring-dotenv 同样以 EnvironmentPostProcessor 注册属性源，两者顺序无契约保证——若先于 dotenv 执行会把本地 `.env` 已配置的键误判缺失，破坏本地启动。InitializingBean 在全部属性源就绪后的刷新期执行，时序确定。

**`.env.example`**：新增 `MCP_BRIDGE_TOKEN=replace-with-strong-mcp-token`；其余三键已有条目补注释说明"必填、缺失启动失败"。

### 1.2 Grafana 凭据纳管（8.2）

**`docker-compose.yml`** grafana 服务：

```yaml
# 旧 - GF_SECURITY_ADMIN_PASSWORD=${GRAFANA_ADMIN_PASSWORD:-admin}
- GF_SECURITY_ADMIN_PASSWORD=${GRAFANA_ADMIN_PASSWORD:?GRAFANA_ADMIN_PASSWORD 必须设置}
```

未设置该变量时 `docker compose config/up` 直接报错退出。`.env.example` 已有该键，无需改动。

### 1.3 MCP 桥接回环限制（8.3）

**`controller/McpBridgeController.java`**：

- 新增 `@Value("${app.mcp.allowed-remote-addrs:}") private List<String> allowedRemoteAddrs = new ArrayList<>();`（字段初始化兜底 + yml 键 `${APP_MCP_ALLOWED_REMOTE_ADDRS:}` 三件套）。
- `assertBridgeToken` 前插入 `assertLoopbackSource(request)`：
  ```java
  private void assertLoopbackSource(HttpServletRequest request) {
      String ip = request.getRemoteAddr();
      if (isLoopback(ip) || allowedRemoteAddrs.contains(ip)) return;
      throw new BusinessException(40300, "MCP bridge 仅允许本机回环访问", HttpStatus.FORBIDDEN);
  }
  ```
- 判定位移：来源校验在 token 之前——非回环即使携带正确 token 也返回 403（验收口径）。
- 回环判定：`127.0.0.1` / `127.` 前缀 / `::1` / `0:0:0:0:0:0:0:1`。

**`application.yml`** mcp 段新增注释键：`allowed-remote-addrs: ${APP_MCP_ALLOWED_REMOTE_ADDRS:}`（反代场景逃生口，默认仅回环）。

SecurityConfig 对 `/api/mcp/**` 的 permitAll 保持不变（控制器层自校验，避免动鉴权链路）。

### 1.4 DNS rebinding 收敛（8.4）

**新增 `common/SafeDnsResolver.java`**（@Component）：

```java
public class SafeDnsResolver {
    private final Function<String, InetAddress[]> lookup;   // 生产 = InetAddress::getAllByName
    private long probeDelayMs = 300;                        // 双解析间隔，测试注入 0

    boolean isInternal(InetAddress addr);                   // loopback/siteLocal/linkLocal/anyLocal
    void assertPublicHost(String host, String desc);        // 全 A 记录逐一判内网，命中抛 invalidParam
    void assertStablePublicHost(String host, String desc);  // 两轮解析：均公网 且 结果集一致，否则拒绝
}
```

- 包级私有构造器接受自定义 lookup 函数，单测可 mock "首轮公网、次轮私网"等序列，无需真实 DNS。
- 抛错统一 `BusinessException.invalidParam`（与两处既有行为一致）。

**`service/GitCloneService.java`**：

- 字段 `@Autowired(required = false) setter` 注入 + 字段初始化 `new SafeDnsResolver()` 兜底（既有直 new 测试不受影响）。
- `assertNotInternalHost` 内联的 `getAllByName` 循环替换为 `safeDnsResolver.assertStablePublicHost(host, "Git 地址")`；ssh/git@ 跳过逻辑保留。
- 更新注释：v8.4 标注的 rebinding 残留风险收敛说明（git 进程实际连接仍由 OS 解析，窗口已收窄但未消除，轻量方案取舍记录在案）。

**`agent/PrdAgent.java`**：

- 同模式注入 SafeDnsResolver；`validatePublicUrl` 的 InetAddress 循环替换为 `assertStablePublicHost(uri.getHost(), "URL")`，重定向每一跳天然复用（每跳都调 validatePublicUrl）。
- 方案偏差说明：计划书步骤③假设 URL 抓取走 OkHttp 可绑 Dns 接口；实际实现为 Jsoup（HTML 解析依赖），无法钉 IP，故采用计划书为 git 预授权的同款轻量方案，两个入口行为一致。
