# 前端技术评审 v8.5 — 消费 retryReset 事件（任务 8.5）

> 版本 v8.5，一旦确定尽量不要轻易改动。基线 v8.4。

## 一、背景

v8.4 后端在流式生成 LLM 重试前推送 `retryReset` SSE 事件（`TestCaseService` CaseCallback.onRetryReset），并已同步清空服务端解析缓冲。前端 `api/testcase.js` 未接线该事件：重试瞬间旧草稿仍挂在界面上，与新一批推送短暂叠加，直到 complete 才被列表刷新覆盖。

## 二、变更点

### 2.1 `api/testcase.js`

两个流式函数签名新增可选回调：

```js
export async function streamGenerate(projectId, { onProgress, onCase, onRetryReset, onComplete, ... } = {})
export async function streamGenerateAppend(projectId, type, { onProgress, onCase, onRetryReset, onComplete, ... } = {})
```

新增监听（两个函数各一处）：

```js
// v8.5: 后端 LLM 重试前推送 retryReset——清空已渲染草稿，避免重推后新旧叠加
es.addEventListener('retryReset', () => { onRetryReset?.() })
```

不解析 payload（当前事件无数据体），纯信号量。

### 2.2 `views/TestCaseList.vue`

`handleRegenerate` 与 `startAppendStream` 的 streamGenerate/streamGenerateAppend 配置对象各新增：

```js
onRetryReset: () => {
  streamedCases.value = []
  streamProgress.value = '模型输出异常，正在重试...'
}
```

- 只清流式草稿缓冲 `streamedCases`；不动 `generationError`、统计、落库列表。
- 进度文案切换给用户"正在重试"反馈；后续 case/progress 事件自然覆盖。

## 三、props / emit 变化

无组件 props/emit 变化；仅 api 层回调入参新增可选项，向后兼容（旧调用不传即无行为）。

## 四、数据流

```
SSE: case → case → retryReset → (后端清缓冲+重推) → case...
前端: 草稿[a,b] → 草稿[a,b] → 清空[] → 草稿[c...]
```

## 五、向后兼容

- 后端低版本不推 retryReset：监听器永不触发，零影响。
- retryReset 在 cancelled/error/complete 前任意时点到达均安全：仅操作响应式数组。

## 六、测试验证

- 新增 `src/api/testcase.test.js`（Vitest）：stub 全局 EventSource + mock fetchSseTicket，捕获事件监听器；按 `case→case→retryReset→case` 序列触发，断言 onCase 调用 3 次、onRetryReset 恰在第二次与第三次之间触发一次。
- `npm run test` 绿；`npm run build` 通过。
- 手动验证可选（需真实 LLM 重试场景）。
