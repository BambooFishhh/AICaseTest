# 高可用优化分析方案（v6.5 基线）

> 输出时间：2026-08-22。本方案为 AICaseTest 高可用改造的整体分析，v6.5 仅落地 P0 中的"任务状态持久化与中断恢复"。

## 0. 现状基线

- 已有有界线程池（analysis/generation/execution/semantic）、Redis/内存运行态、LLM 重试 3 次、执行心跳、项目级并发配额、启动恢复（清空队列 + 项目状态复位）。
- 核心缺口：分析/生成没有持久化任务与 checkpoint；队列只是计数器不是消息；恢复是"清空"而不是"恢复"；LLM 重试不区分可重试/不可重试错误；无租约、无 DLQ、无统一任务管理入口。

## 1. 任务与状态持久化、状态机、checkpoint、幂等

- 新增 `agent_task` 表：task_type、project_id、status、phase、attempts/max_attempts、input_json、checkpoint_json、error_code/message、degraded、lease_owner、lease_expire_at、heartbeat_at、started/ended/created/updated。
- 状态机：CREATED → QUEUED → RUNNING → SUCCEEDED / FAILED / CANCELLED / NEEDS_REVIEW / DLQ。
- 阶段粒度：分析（scan → parse → state_machine → index）；生成（generate → persist → index）；执行后续版本接入。
- checkpoint 先写库再执行外部动作；状态迁移幂等；生成落入 `replaceAll` 前记录 persist 阶段，避免崩溃后重复做破坏性覆盖。
- 多实例租约：`SET NX EX` 或 DB lease 字段 + 心跳续期；恢复只能由 lease 过期触发。

## 2. 中断场景容错

- LLM：只重试超时/网络/429/5xx；4xx 与模型拒绝直接失败；指数退避 + 抖动；单任务总超时。
- 工具（MCP/Playwright）：按工具超时；只对幂等工具自动重试（截图/status/scroll），点击/输入不自动重试。
- 进程 OOM/被杀：持久化任务 + checkpoint + lease；重启后标记 NEEDS_REVIEW，人工确认后重试。
- 前端断线不等于任务失败；SSE 断线保留服务端任务状态，任务由状态机驱动。

## 3. 降级兜底

- LLM 重试耗尽后走既有规则生成（confidence 偏低 + degraded 标记）。
- 分析保留确定性基线（frontend/backend 静态扫描结果），LLM 摘要失败不阻塞分析。
- 生成按模块保留已成功批次；跨模块失败仍落库部分结果并告警。
- 任务状态 NEEDS_REVIEW + 管理端列表/详情/重试，人工兜底。

## 4. 并发与故障隔离

- 队列与 executor 分离；拒绝策略由 CallerRuns 改为队列/DLQ 背压。
- 每项目并发配额沿用；多实例用 Redis Streams consumer group 或 DB lease claim。
- `agent_task` 唯一 request_id 防重复创建；恢复与手动操作通过 lease CAS 防双抢占。

## 5. 可观测

- TaskTelemetry 扩展 task_id/attempt/phase/status/error_code/degraded/lease_owner。
- Prometheus 增加 task.started/completed/failed/retried/degraded、llm.retries、queue.depth、lease_expired。
- 日志 MDC 携带 trace_id/task_id/phase；Grafana 增加卡死任务（heartbeat 过期）与 DLQ 告警。

## 6. 落地优先级

| 级别 | 内容 |
|---|---|
| P0 | agent_task 表 + 分析/生成接入；lease/heartbeat；启动恢复改为标记 NEEDS_REVIEW；LLM 重试分类 + 抖动；管理端任务列表/详情/重试；统计扩展 |
| P1 | 从 checkpoint 续跑（分析/生成/执行步）；Redis Streams + consumer group；断路器；前端任务中心 |
| P2 | 执行任务租约恢复；动态重试策略；任务 timeline 回放 |

## 7. 高频踩坑点

- 只加状态不落 payload/checkpoint，重启后仍不知道从哪继续。
- 恢复"清空队列"会吞掉 pending 任务；必须恢复或标记人工处理。
- 幂等要建立在落库副作用上：`replaceAll`、click 等重试会产生重复副作用。
- 心跳与 lease 混淆：心跳=存活，lease=执行资格，只有 lease 过期能触发恢复。
- 恢复与手动操作并发抢占：需要 CAS/lease claim。
- 前端断线不 cancel 服务端任务；任务终止必须由服务端状态机判定。
