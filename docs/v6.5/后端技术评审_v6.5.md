# 后端技术评审 v6.5

> 版本 v6.5，一旦确定尽量不要轻易改动。主题：高可用 P0 - 任务状态持久化与中断恢复。

## 1. 变更点

### 1.1 新表 agent_task（Flyway V8）

```sql
CREATE TABLE agent_task (
    id VARCHAR(64) NOT NULL PRIMARY KEY,
    request_id VARCHAR(128),
    task_type VARCHAR(32) NOT NULL,
    project_id VARCHAR(64),
    status VARCHAR(32) NOT NULL,
    phase VARCHAR(64),
    attempts INT NOT NULL DEFAULT 0,
    max_attempts INT NOT NULL DEFAULT 3,
    input_json LONGTEXT,
    checkpoint_json LONGTEXT,
    error_code VARCHAR(32),
    error_message TEXT,
    degraded TINYINT(1) NOT NULL DEFAULT 0,
    lease_owner VARCHAR(64),
    lease_expire_at DATETIME(6),
    heartbeat_at DATETIME(6),
    started_at DATETIME(6),
    ended_at DATETIME(6),
    created_at DATETIME(6) NOT NULL,
    updated_at DATETIME(6) NOT NULL,
    KEY idx_agent_task_status (status, created_at),
    KEY idx_agent_task_project (project_id, created_at),
    KEY idx_agent_task_request (request_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 1.2 新增类

- `entity/AgentTask.java`：字段与表一一对应，`id` 为 String UUID。
- `repository/AgentTaskRepository.java`：按 request_id+type 查最新、按 status 查租约过期列表、Specification 分页。
- `service/AgentTaskService.java`：create/start/checkpoint/succeed/fail/cancel/markNeedsReview/markDlq/requeue/recoverStaleTasks/list/statusCounts。
- `common/LlmRetryPolicy.java`：`isRetryable(Throwable)` 静态分类。
- `dto/AgentTaskDTO.java`：管理端 API 响应结构。
- `controller/AgentTaskAdminController.java`：`/api/admin/tasks` 列表/详情/重试。
- `service/TaskRetryDispatcher.java`：按 taskType 分发 analysis/generation；避免 AgentTaskService ↔ 业务 Service 循环依赖。

### 1.3 修改类

| 文件 | 变更 |
|---|---|
| `service/TaskQueueService.java` | 恢复逻辑保留清空计数，同时提示任务表恢复由 AgentTaskService 负责；`stats()` 合并 agentTask 状态计数需在 Controller 聚合（具体见 TaskController） |
| `service/AnalysisService.java` | runAnalysisWithProgress 创建/启动任务，scan/parse/state_machine/index checkpoint，成功/失败收尾 |

| `controller/TaskController.java` | `/api/tasks/stats` 增加 `agentTasks` 状态统计 |
| `service/LlmService.java` | chat/stream/image 三处重试循环接入分类与抖动；失败信息更明确 |

## 2. API 契约变化

### 新增

- `GET /api/admin/tasks?taskType=&status=&projectId=&page=&size=`
- `GET /api/admin/tasks/{id}`
- `POST /api/admin/tasks/{id}/retry`

`retry` 响应：

```json
{"code":200,"message":"success","data":{"taskId":"...","status":"QUEUED","dispatched":true}}
```

`APPEND_GENERATION` 不自动分发，返回 `dispatched=false` 和提示。

### 修改

- `GET /api/tasks/stats` 返回体增加：

```json
{"generation":{...},"execution":{...},"agentTasks":{"QUEUED":0,"RUNNING":1,...}}
```

兼容性：原字段不变，仅新增字段，前端无破坏。

## 3. 向后兼容性

- 新增表与接口，不改动既有表结构；`/api/tasks/stats` 只增字段。
- H2 dev 由 `ddl-auto: update` 自动建表，不影响现有 JPA 实体。
- `recoverStaleTasks` 仍清空内存/Redis 计数（防旧实例污染），但项目状态复位前先恢复 `agent_task`，语义更完整。

## 4. 测试验证方案

- `AgentTaskServiceTest`：Mock Repository 验证 create 去重、start/checkpoint/succeed/fail/requeue 状态迁移、lease 过期恢复为 NEEDS_REVIEW。
- `LlmRetryPolicyTest`：超时/5xx/429 为可重试；400/401/取消为不可重试。
- 回归：`mvn compile`、`npm run build`；可选 `mvn -Dtest=AgentTaskServiceTest,LlmRetryPolicyTest test`。
- 部署后：调用 `/api/admin/tasks` 列表与 `/api/tasks/stats`，确认新字段返回。
