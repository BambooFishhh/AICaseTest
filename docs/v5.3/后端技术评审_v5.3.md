# 后端技术评审 v5.3：缓存与任务队列

> 版本 v5.3，一旦确定尽量不要轻易改动。

## 1. 变更点

### 1.1 缓存

```java
@Configuration
@EnableCaching
public class CacheConfig {
    @Bean
    @ConditionalOnProperty(name = "app.redis.enabled", havingValue = "true")
    public CacheManager redisCacheManager(RedisConnectionFactory factory) {
        return RedisCacheManager.builder(factory)
                .cacheDefaults(RedisCacheConfiguration.defaultCacheConfig()
                        .entryTtl(Duration.ofMinutes(10))
                        .disableCachingNullValues())
                .build();
    }

    @Bean
    @ConditionalOnProperty(name = "app.redis.enabled", havingValue = "false", matchIfMissing = true)
    public CacheManager memoryCacheManager() {
        return new ConcurrentMapCacheManager();
    }
}
```

注解落点：

- `SettingsService.getSettings()` → `@Cacheable(value="settings", key="'llm'")`
- `SettingsService.getDefaultGenerationParams()` → `@Cacheable(value="settings", key="'generationParams'")`
- `ProjectService.getGenerationParams()` → `@Cacheable(value="projectParams", key="#projectId")`
- `AnalysisService.getAnalysis()` / `getStateMachines()` → 缓存，重新分析后 `CacheManager.evict`

### 1.2 任务队列

```java
public interface TaskQueueStore {
    void enqueue(String queue, String taskId);
    void markRunning(String queue, String taskId);
    void markDone(String queue, String taskId);
    long queuedCount(String queue);
    long runningCount(String queue);
}
```

- `MemoryTaskQueueStore`：ConcurrentHashMap + Set。
- `RedisTaskQueueStore`：Redis Set + 24h TTL，异常降级内存。
- `TaskQueueService` 封装生成/执行队列；`TaskController` 暴露 `/api/tasks/stats`。

## 3. API 契约变化

- 新增 `GET /api/tasks/stats`（认证访问）。
- 其余接口不变。

## 4. 向后兼容性

- 默认内存缓存与内存队列，行为与 v5.2 一致。
- Redis 开启时缓存/队列自动切换。

## 5. 测试验证方案

- `mvn compile` / `mvn test`。
- 打开设置→修改→再读取，确认 evict 生效。
- 触发一次生成/执行，观察 `/api/tasks/stats` 计数变化。
