## 2. ScopeSlicingService（新增）

```java
@Service public class ScopeSlicingService {
    public record ScopeSlice(String definitionId, String name, String baselineRef,
                             Set<String> targetEndpointIds,
                             List<Map<String,Object>> targetEndpointsDetail,
                             Map<String,List<Map<String,Object>>> sprintTransitionsBySmId,
                             Map<String,List<Map<String,Object>>> historicalTransitionsBySmId,
                             List<Map<String,Object>> setupHints) {
        public boolean isEmpty() { return definitionId == null; }
    }

    public ScopeSlice loadForGeneration(String projectId)   // 无 confirmed 返回 EMPTY
    boolean hasConfirmedScope(String projectId)
}
```

- 转换分类：复用 v8.1 的证据匹配（normalizeStateCode + from/to 相等或 "*"），命中证据 file ∈ definition.changed_files → sprint，否则 historical
- BFS：邻接表 = 该 SM 除目标转换外的全部转换；初始态 = states 中 is_initial=true 或首条；路径边输出 `{trigger}` 文案骨架；历史边优先不强制（最短路径优先，同长取含历史边多者）
- targetEndpointsDetail：backendResult.endpoints 按 itemRef("METHOD /path") 精确匹配出完整 toContextMap()

## 3. TestGeneratorAgent 改造点

1. **新 overloads**（不动既有签名，单测兼容）：
   `generate(..., GenerationReport report, ScopeSlice slice)` / `generateStreaming(... 同 ...)`，
   逐层透传 runPrdPipeline → generateByLlmWithPrd → generatePrdRound → buildCoverageChecklist
2. **buildCoverageChecklist**：slice 非空时 endpoints 清单 = scope 目标接口（id 归一 "METHOD path"）；transitions 清单 = 各范围 SM 的 sprint 转换
3. **generatePrdRound**：
   - `context.put("scope", {name,baselineRef,targets:{endpoints:[detail],transitions:[...]}, historicalTransitions:[...], setupHints:[...]})`
   - smList 仅保留范围内 SM；每条转换附 `"role": "sprint_target"|"historical_context"`
   - epList 先按 scope 目标过滤再走 G25 容量控制
4. **SYSTEM_PROMPT_PRD_HEADER**：# 任务段追加一句"若提供【本期范围(scope)】，所有用例的断言目标必须落在范围内"
5. **SYSTEM_PROMPT_PRD_FOOTER**：新增 `## 本期范围（scope，v8.2）` 段——目标/历史角色规则、setupHints 使用方式、coverageRefs 只允许引用本期目标、structuredSteps phase 字段规范；structuredSteps 要求段加 phase 说明；few-shot 增补一条含 setup 步骤的精简示例

## 6. Execution blocked 语义

两个循环统一模式：

```java
boolean setupFailed = false; String setupError = null;
// 步骤收尾处：
if ("setup".equalsIgnoreCase(node.path("phase").asText()))
        && "failed".equals(step.getResult())) {
    setupFailed = true; setupError = step.getError(); break;
}
```

终态判定（两处 finalize）：

```java
if (!cancelled && setupFailed) {
    status = "blocked";
    summary = "前置准备失败，已停止后续验证步骤（" + setupError + "）";
}
```

- agentTaskService 收尾：blocked 与 failed 同路 fail
- 失败经验库写入守卫 `"failed".equals(status)` 天然排除 blocked，无需改
- getStats 统计（L1017 区域）与 updateTestCaseExecutionStatus：blocked 已是合法值
- ReportService：批次 overview 增加 blocked 计数行
