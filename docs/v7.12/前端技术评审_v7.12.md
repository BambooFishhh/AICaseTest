## 2. api/testcase.js

**现状**：error 事件统一 `onError(msg) + es.close()`。SSE 原生 error 在两种场景触发：① 后端主动下发 error 事件（`e.data` 有值）；② 连接层断开——网络瞬断/代理空闲超时（`e.data` 为空）。场景②后端生成仍在异步进行，报"生成失败"是误报。

**修改**（两个函数同构）：

```js
es.addEventListener('error', (e) => {
  // v7.12(E16): e.data 有值 = 后端下发的真实错误；为空 = 连接层断开（后端任务仍在跑）
  // 断连不再误报失败，交由 onDisconnect 降级轮询跟踪进度
  if (e.data) {
    let msg = '生成连接异常'
    try { msg = JSON.parse(e.data).message || msg } catch {}
    onError?.(msg)
  } else {
    onDisconnect?.()
  }
  es.close()
})
```

回调签名变更：options 新增可选 `onDisconnect`——纯增量，不传时行为为"静默断开"（不再误报错误）。

## 3. TestCaseList.vue

两处调用（`handleRegenerate` / 追加生成）增加：

```js
onDisconnect: () => {
  // v7.12(E16): 连接层断开——生成仍在后台进行，降级为轮询（复用刷新恢复机制）
  streaming.value = false
  currentGenMode.value = null
  streamProgress.value = ''
  regenerating.value = false
  cancelling.value = false
  ElMessage.info('生成连接中断，已切换为进度轮询')
  projectStore.startPolling(projectId, (next, prev) => {
    if (prev !== 'generating' || next === prev) return
    if (next === 'completed') {
      ElMessage.success('用例生成完成')
      Promise.all([loadList(), loadAllForStats(), loadCoverageMatrix()])
    } else if (next === 'failed') {
      ElMessage.error('用例生成失败')
      loadList()
    }
  })
}
```

轮询回调与 `resumeGenerationIfActive` 完全同构（v6.1 既有模式）。不置 `streaming=true`，避免"无 SSE 连接却显示可取消"的中间态——与刷新恢复路径行为一致。

## 4. ProjectDetail.vue

分析 SSE（`handleAnalyze`）error 分支同构区分：`e.data` 为空时不再报"分析失败，请重试"，改为 `ElMessage.info` + 复用既有 `resumeActiveStatus()`（内部 `projectStore.startPolling`，终态自动提示并刷新）。后端错误（`e.data` 有值）维持现状。
