## 2. R15 reject 分母

**现状**（`TestCaseReviewAgent.llmReview`）：

```java
int n = cases.size();
double ratio = n == 0 ? 0 : (double) rejectIndices.size() / n;
```

**问题**：rejectIndices 只能来自 `byIndex`（已评审条目），缺评条目（R4 补评后仍缺的）计入分母稀释比例。20 条送评、10 条有输出且全 reject：真实比例 100%（应全保留+告警），算出 50%（灰区，低置信照删）。

**修改**：

```java
// v7.12(R15): 分母改为已评审数——缺评条目计入分母会稀释批量 reject 比例，
// 使 >70% 全保留保护带在截断场景失灵（缺评保护由 R4 补评机制负责，两道防线各司其职）
int reviewed = byIndex.size();
double ratio = reviewed == 0 ? 0 : (double) rejectIndices.size() / reviewed;
```

## 3. G22 选择器池只收 DOM 选择器

**现状**（`TestGeneratorAgent.enrichStructuredSteps`）：pool 同时收 DOM 选择器（`{type: css/xpath/text, value, element}`）与表单字段（`{name, type: 输入框类型, label}`）。

**问题**：表单字段无 `value`、其 `type` 是 input 类型。文本匹配胜出后写入 `uiSelector = {type: "text", value: null}`——`"text"` 被执行器当选择器类型解析，value 为空，废数据固化进用例资产。

**修改**：删除 forms 分支（L879-892），pool 只由 `domSelectors` 构成。表单字段本就不具备可执行性，从 uiSelector 候选中移除后，LLM 未给选择器的步骤宁留空由 Agent 模式执行时 LLM 自定位（与 L12"宁留空不赌错"原则一致）。

## 4. G23 判重门槛与口径对齐

### 4.1 子串规则加最短门槛（两处同步）

```java
// v7.12(G23): 子串判重加最短门槛——2~3 字通用动词（"登录"/"查询"/"下单"）的
// 包含关系不构成判重证据；4 字及以上同型同模块包含仍判重（真重复由语义去重兜底）
int shorter = Math.min(titleA.length(), titleB.length());
if (shorter >= 4 && (titleA.contains(titleB) || titleB.contains(titleA))) {
    return true;
}
```

### 4.2 TestCaseService 落库侧对齐生成侧（v7.1(G1) 修复同步）

`TestCaseService.isDuplicate` 与 `TestGeneratorAgent.isDuplicate` 的三处漂移：

| 规则 | 生成侧（正确） | 落库侧（漂移） | 修复 |
|---|---|---|---|
| 标题完全相同 | 有 type 守卫 | 无 type 守卫 | 加守卫 |

## 5. E15 Redis 信号量租约

### 5.1 接口变更

```java
// RuntimeStore.java
boolean tryAcquireProjectPermit(String projectId, int maxPermits, long timeoutMs, String permitId);
void acquireProjectPermit(String projectId, int maxPermits, String permitId);
void releaseProjectPermit(String projectId, String permitId);
void renewProjectPermit(String projectId, String permitId);   // 新增
```

permitId = executionId（每次执行唯一）。`MemoryRuntimeStore`：忽略 permitId（Semaphore 语义不变），`renew` 为 no-op。

### 5.2 RedisRuntimeStore 租约模型

```java
// ZSET：member=permitId, score=授予/续租时刻。租约 5 分钟，执行器每步心跳续租。
private static final long PERMIT_LEASE_MS = 5 * 60_000L;
// acquire 降级内存时登记，release 按授予来源路由（修复双向漂移）
private final Set<String> memoryGrantedPermits = ConcurrentHashMap.newKeySet();

ACQUIRE_SCRIPT(key, max, nowMs, leaseMs, permitId):
  ZREMRANGEBYSCORE key -inf (nowMs-leaseMs)     // 淘汰过期租约（崩溃自愈）
  if ZCARD(key) < max:
    ZADD key nowMs permitId
    PEXPIRE key (leaseMs+60s)
    return 1
  return 0

RELEASE_SCRIPT(key, permitId):
  return ZREM(key, permitId)                     // 幂等：重复释放/释放未持有均无害

RENEW_SCRIPT(key, nowMs, leaseMs, permitId):
  if ZSCORE(key, permitId):
    ZADD key nowMs permitId
    PEXPIRE key (leaseMs+60s)
    return 1
  return 0
```

**行为对照**：

| 场景 | 旧（计数器+EXPIRE600） | 新（ZSET 租约） |
|---|---|---|
| 执行 >10 分钟、期间无新 acquire | 键过期 → 计数清零 → 超发 | 心跳续租，租约不过期 |
| JVM 崩溃未释放 | 计数残留 ≤600s | 租约 5 分钟自动淘汰 |
| acquire 降级内存、release 时 Redis 已恢复 | release 扣减 Redis（偷槽位）+ 内存泄漏 | release 路由回内存（memoryGrantedPermits） |
| release 调用两次 | 计数双扣 → 超发 | ZREM 幂等，无害 |
| Redis 释放失败 | 降级内存乱扣 | 仅告警，租约 ≤5 分钟自愈 |

### 5.3 调用方适配

- `ProjectExecutionLimiter`：`acquire/tryAcquire/release` 透传 permitId，新增 `renew(projectId, permitId)`（内部全吞异常——续租失败不得影响执行主流程）。
- `ExecutionService`：
  - `acquireProjectPermitOrTimeout` → `tryAcquire(projectId, timeoutMs, executionId)`；禁用超时分支 → `acquire(projectId, executionId)`；
  - 4 处 `release(projectId)` → `release(projectId, executionId)`；
  - `touchHeartbeat` 增加 projectId 参数，内部同步 `projectExecutionLimiter.renew`（4 处调用点机械适配——两个 worker 的启动处与步骤循环处均有 testCase 在作用域）。

### 5.4 兼容性

- `ExecutionServiceQueueTimeoutTest`（v7.11）：mock 签名 `tryAcquire(anyString(), anyLong())` → 3 参加 permitId。
- 无其他调用方（全库 grep 确认 limiter 仅 ExecutionService 使用）。

## 7. L15 熔断半开

```java
private static class CircuitState {
    final AtomicInteger consecutiveFailures = new AtomicInteger();
    volatile long openedUntil = 0;
    volatile long probeLeaseUntil = 0;   // v7.12(L15): 半开探测租约
}

@Value("${llm.circuit.probe-lease-seconds:120}")
private long probeLeaseSeconds = 120;    // 覆盖最长 LLM 调用，探测既无成功也无失败时自愈

public boolean allowRequest(String channel) {
    synchronized (state(channel)) {
        CircuitState s = state(channel);
        long now = System.currentTimeMillis();
        if (now < s.openedUntil) return false;          // OPEN：全拒（不变）
        if (s.openedUntil > 0) {                        // HALF_OPEN：单探测
            if (now < s.probeLeaseUntil) return false;  // 已有探测在途
            s.probeLeaseUntil = now + probeLeaseSeconds * 1000;
            return true;                                // 当前调用者成为探测器
        }
        return true;                                    // CLOSED
    }
}
```

- `onSuccess`：清零三项（全关闭）。
- `onFailure`：达阈值重开 + 清租约（下轮开启期过后再探测）。
- 探测请求走"不可重试 4xx 不计数"路径时无回调 → 租约 120s 自然过期 → 下个调用者成为新探测器——无死锁。
- `synchronized` 状态对象：LLM 调用 40s+，锁开销可忽略，消除租约授予竞态。

**行为对照**：开启期（30s）过后，旧实现全量放行（几十个 doomed 请求涌入后才因首个失败重开）；新实现仅放行 1 个探测，其余照旧快速失败——provider 恢复时一次探测即全量恢复，未恢复时每 30s 仅牺牲 1 个请求。

## 9. 风险

- 信号量接口签名变更编译期全暴露，调用方仅 ExecutionService + 1 测试类。
- 租约续租依赖步骤心跳：单步 LLM 超时/熔断约束下远小于 5 分钟租约；即使过期，release 幂等无害。
- 报告流式后若 DB 读取异常，response 可能已部分写出（HTTP 200 + 截断 HTML）——旧实现同风险（500 前已装配完整串），不新增风险面。
