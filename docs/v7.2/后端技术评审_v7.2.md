## 1. 改动点

### 1.1 ExecutionService — 状态判定收敛 + 全跳过记 skipped（R10）

两处收尾（Agent 执行路径 L797、程序化执行路径 L472）现状：

```java
// 现状（两处相同）
if (errorMessage != null && failed == 0) failed++;
status = failed > 0 ? "failed" : "passed";
```

改为统一调用新方法：

```java
if (errorMessage != null && failed == 0) failed++;   // v7.0(E3) 保持
status = determineStatus(passed, failed, skipped);   // v7.2(R10)

/**
 * v7.2(R10): 执行终态判定——全 skipped 不再记 passed。
 * 背景：纯 api_call 用例 10 步全跳过，旧逻辑挂 passed 徽章，
 * 报告却是"通过 0/失败 0/跳过 10, 通过率 0%"，同屏自相矛盾。
 */
static String determineStatus(int passed, int failed, int skipped) {
    if (failed > 0) return "failed";
    if (passed == 0 && skipped > 0) return "skipped";
    return "passed";
}
```

- 包级私有静态方法，可直接单测（与 v7.1 `isDuplicate` 同风格）
- `agentTaskService` 分支不变：skipped 且无 errorMessage → succeed（任务本身跑完了）
- 失败经验入库（`"failed".equals(status)`）不变
- 回写 `executionStatus`：cancelled → not_executed（既有），其余直接写终态，skipped 自然回写

### 1.2 ReportService — 通过率口径 + 版本常量 + 批次报告（R10/R12）

```java
private static final String APP_VERSION = "v7.2";   // v7.2(R12): 报告版本收敛为单一常量

/**
 * v7.2(R10): 通过率分母 = passed + failed（跳过不计入，对齐 Allure 惯例）。
 * 全部跳过/无判定步骤时返回 0，由调用方追加说明文字。
 */
static double passRateOf(long passed, long failed) {
    long judged = passed + failed;
    return judged == 0 ? 0 : (double) passed / judged * 100;
}
```

单次报告（generateExecutionReport）：

```java
double passRate = passRateOf(passedSteps, failedSteps);   // 分母不再含 skipped
// 通过率单元格：跳过 > 0 时追加说明
html.append("<tr><th>通过率</th><td>").append(String.format("%.1f%%", passRate))
    .append(skippedSteps > 0 ? "（跳过 " + skippedSteps + " 步未计入分母）" : "")
    .append("</td></tr>");
```

批次报告（generateBatchReport）：

```java
long skipped = records.stream().filter(r -> "skipped".equals(r.getStatus())).count();  // 新增计数
double passRate = passRateOf(passed, failed);   // 分母不再含 running/pending/cancelled/skipped
// 汇总表新增"已跳过"行；通过率单元格在有未判定记录时追加说明
```

footer（两处）：

```java
html.append("<div class=\"footer\">AICaseTest ").append(APP_VERSION).append(" 报告</div>");
```

### 1.3 TestCaseReviewAgent — mergeCoverageRefs 改并集（R2）

```java
// v7.2(R2): 评审 refs 与既有 refs 取保序并集（旧实现是非空即整体替换，
// 生成阶段正确的 requirementIds 会被评审 LLM 的不完整返回覆盖丢失）
Map<String, Object> mergeCoverageRefs(Map<String, Object> existing, Map<String, Object> review) {
    Map<String, Object> merged = new LinkedHashMap<>(existing == null ? Map.of() : existing);
    for (String key : List.of("requirementIds", "transitionIds", "endpointIds", "ruleIds")) {
        List<String> union = new ArrayList<>();
        collectIds(merged.get(key), union);
        collectIds(review == null ? null : review.get(key), union);
        merged.put(key, union);
    }
    return merged;
}

private void collectIds(Object value, List<String> union) {
    if (value instanceof List) {
        for (Object item : (List<?>) value) {
            if (item != null) {
                String id = String.valueOf(item);
                if (!id.isBlank() && !union.contains(id)) {
                    union.add(id);
                }
            }
        }
    }
}
```

- 方法可见性 private → 包级私有（单测直接调用）
- endpointIds 合法的 checklist 校验不受影响：`applyEndpointMatching` 在 LLM 评审之后仍按 `readValidEndpointIds` 重过滤
