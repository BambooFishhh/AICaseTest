## 1. 改动点

后端 v7.2 新增执行记录终态 `skipped`（全步骤跳过，如纯 api_call 用例）。前端需在四处状态映射 + 一处筛选下拉补齐展示；Dashboard 无需改动（从未消费 apiRate/avgApiRate）。

### 1.1 TestCaseList.vue — 状态白名单 + 文案 + 筛选（R10）

```js
// 现状：skipped 不在白名单，会被静默映射成 not_executed（"未执行"）——不诚实
function executionStatusKey(status) {
  const key = status || 'not_executed'
  return ['not_executed', 'running', 'passed', 'failed', 'blocked'].includes(key) ? key : 'not_executed'
}
function executionStatusText(status) {
  return { not_executed: '未执行', running: '执行中', passed: '通过', failed: '失败', blocked: '阻塞' }[status] || '未执行'
}

// 改为：白名单加入 skipped，文案"已跳过"
function executionStatusKey(status) {
  const key = status || 'not_executed'
  return ['not_executed', 'running', 'passed', 'failed', 'blocked', 'skipped'].includes(key) ? key : 'not_executed'
}
function executionStatusText(status) {
  return { not_executed: '未执行', running: '执行中', passed: '通过', failed: '失败', blocked: '阻塞', skipped: '已跳过' }[status] || '未执行'
}
```

执行状态筛选下拉追加：

```html
<el-option label="已跳过" value="skipped" />
```

状态点样式（status-pill SCSS）追加中性色：

```scss
&.status-skipped { color: var(--text-tertiary); }
```

- status-pill SCSS 补 `&.status-skipped { color: var(--text-tertiary); }`
- 统计卡：后端 stats 新增 `skipped` 计数，前端本地兜底统计同步补齐；新增"已跳过"统计卡（放"运行中"之后，通过率之前）

## 3. 数据流

- 后端 `ExecutionService.determineStatus` 产出 `skipped` → ExecutionRecord.status / 回写 testCase.executionStatus
- 列表接口（testcases）executionStatus → TestCaseList / TestCaseCard 展示
- 执行历史接口（executions）status + stats.skipped → ExecutionHistory 展示
- 执行详情接口 status → ExecutionResult 展示
- 筛选：`filters.executionStatus=skipped` → 后端 listTestCases 的 coalesce 过滤（既有机制，无白名单校验，直接生效）

## 4. 向后兼容

- 未部署新后端时：前端不会收到 skipped 状态，新增映射为死分支，无副作用
- 已有旧数据：不存在 skipped 记录（新状态只在新执行产生）
- stats.skipped 缺失时 `{{ stats.skipped || 0 }}` 兜底为 0
