# 水平扩容指南（v8.9.5，计划书任务 12.8）

> 适用基线：v8.9.4+（LLM 入口实例级限流、票据 Redis 双实现、全量 @SchedulerLock 就绪）。
> 本指南 + 附录演练记录 = 计划书 12.8 交付物。

## 一、拓扑

```
                    ┌── Nginx / SLB（ip_hash 或最少连接）
   用户 ──────────┤
                    ├── backend 实例 A :8000 ─┐
                    │                          ├─ MySQL(3308) ← Flyway 权威 schema
                    └── backend 实例 B :8001 ─┘   Redis        ← RuntimeStore/票据/限流外置
                                                  Milvus       ← 共享向量库
                                                  MinIO        ← 共享对象存储
```

共享前提：所有实例连**同一** MySQL / Redis / Milvus / MinIO；`outputs/` 证据目录必须为共享卷（NFS/云盘）或接入对象存储——否则报告缺图告警会频繁出现。

## 二、多实例环境变量清单

每实例 `.env` **完全相同**（无差异点），关键项核对：

| 变量 | 要求 |
|---|---|
| `APP_REDIS_ENABLED=true` | **硬约束**：取消/配额/心跳/票据全部依赖 Redis，内存实现双实例不互通 |
| `MYSQL_URL` 指向同一 MySQL | Flyway 由先启动实例执行迁移，其余实例等待即可 |
| `MILVUS_*` / `MINIO_*` | 与主栈同值 |
| `APP_JWT_SECRET` 等安全四键 | 各实例一致（JWT 无状态校验） |
| `LLM_RATE_*_CONCURRENCY` | 见下方限流聚合公式 |

## 三、LLM 限流聚合口径（12.2 配套公式）

实例级信号量配额（默认 text=6 / stream=6 / embedding=4）为**每实例**上限：

```
集群聚合并发 = 实例配额 × 实例数 ≤ 供应商 RPM 对应的并发额度
例：供应商 RPM=300、单请求均耗 60s → 安全并发 ≈ 5 → 双实例时每实例 text 配额应下调至 2~3
```

如需精确全局配额而非乘法估算，引入 Bucket4j+Redis 分布式限流——属计划外依赖，单独立项确认后实施。

## 四、SSE 路由两方案对比

| 方案 | 做法 | 优点 | 缺点 | 推荐 |
|---|---|---|---|---|
| A：ip_hash 会话亲和 | Nginx upstream `hash $remote_addr consistent` | 零代码改动；EventSource 断线重连回同一实例 | 节点摘除时该节点全部 SSE 断开（前端已有断连降级轮询兜底）；负载可能倾斜 | ✅ 当前规模首选 |
| B：无亲和 + 前端重连换票 | 任意实例接续；断线后前端重新 fetchSseTicket 重连任意实例 | 负载均匀、滚动发布友好 | 需前端重连编排与事件去重逻辑改造 | 规模扩大后再评估 |

Nginx 样例（方案 A）：

```nginx
upstream aicasetest_backend {
    hash $remote_addr consistent;
    server 127.0.0.1:8000;
    server 127.0.0.1:8001;
}
server {
    location /api/ {
        proxy_pass http://aicasetest_backend;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 1800s;          # SSE 长连接
        proxy_buffering off;               # SSE 必须
    }
}
# ⚠️ 若启用 MCP 反代转发到 /api/mcp/**，后端需 APP_MCP_TRUST_PROXY=true
#   （仅可信反代可开，见 McpSourceFilter 注释）
```

## 五、附录：双实例演练记录（2026-08-26，本机 Docker）

演练方式：在 compose 网络内以同镜像起第二实例 `test-agent-backend-b`（端口 127.0.0.1:8001），连接同一 MySQL/Redis/Milvus。

| # | 演练项 | 结果 |
|---|---|---|
| 1 | 两实例 `/api/health` 均 UP，B 实例 dataSource/milvus 正常 | ✅ |
| 2 | A 实例登录的 JWT 在 B 实例直接可用（无状态 + 每请求查用户） | ✅ |
