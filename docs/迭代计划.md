## 排布原则

1. **诚实化先行（v7.0–v7.4）**：先把所有"说谎"的地方修掉——执行结果、生成一致性、度量指标、组件稳定性、分析器。指标可信是后续一切闭环的前提。
2. **缓存基线居中（v7.5）**：可复现基线在闭环反馈前建立，避免反馈进来的是噪音。
3. **闭环其次（v7.6–v7.8）**：断言闭环（E5/L6/A17）→ 投喂精准（G16/G17/G4）→ 评审回写（R1/R3/R7）。
4. **效率与杂项收尾（v7.9–v7.10）**：依赖前序语义稳定。
5. **依赖硬约束**：A15 先于 G7（v7.5 内有序）；G2（v7.1）先于 R1（v7.8），R1 落地时复验推送/落库一致性；E4 最小版（v7.0）与 G20层3（v7.6）分层兑现。

# v4.0 规划：账号登录 + 安全校验 + 多线程高并发（2026-08-12 追加）

> v3.x 产品线已全部完成（v3.11~v3.18）。v4.0 起进入账号/安全/并发线，建议拆 3 版，仍按 version-iteration skill 逐版迭代。

## 版本拆分

| 版本 | 主题 | 核心内容 |
|---|---|---|
| **v4.0** | 账号体系与登录 | 用户注册/登录、JWT、路由守卫、数据归属隔离、存量数据迁移、默认管理员初始化 |
| **v4.1** | 安全校验与权限 | 角色权限（ADMIN/USER）、登录防爆破、密码策略、输入校验、敏感保护、审计 |
| **v4.2** | 多线程高并发 | 线程池治理、项目级并发控制、批量执行排队与取消、可观测性 |

## v4.0 范围（本次执行）

### 后端

- 依赖：spring-boot-starter-security + jjwt（HS256）；BCrypt 密码加密
- 新实体 `User`（username 唯一 / passwordHash / displayName / role：USER、ADMIN）
- `AuthService` + `AuthController`：register / login（返回 token + user）/ me
- `JwtAuthFilter` + `SecurityConfig`：放行 `/api/auth/**`、`/api/health`、`/swagger-ui/**`、`/v3/api-docs/**`；其余需认证；`/api/settings/**`、`/api/stats/**` 仅 ADMIN；无状态会话
- `Project.userId` 归属 + `ProjectAccessService` 统一越权校验（所有项目级接口）
- `DataInitializer`：无用户时创建默认管理员（admin/admin123，可配置）；存量项目归默认管理员

### 前端

- 登录/注册页（`/login`、`/register`），Pinia authStore + localStorage
- axios 拦截器自动带 Bearer；401 → 清 token 跳登录
- 路由守卫：未登录重定向登录页；仪表盘/系统设置仅 ADMIN 显示
- 顶栏用户菜单（用户名/退出）

### 迁移与风险

- 破坏性变更：所有 API 需带 token（前端 axios 统一处理）

## 目标

## 一、MySQL 负责什么（持久化主数据）

全部业务实体迁 MySQL（utf8mb4，JSON 字段用 TEXT/JSON 列）：

| 域 | 表 |
|---|---|
| 账号与组织 | users、project_groups、group_members |
| 项目 | projects（settings/prd/techStack 为 JSON/TEXT 列） |
| 用例 | test_cases（preconditions/steps/expectedResults/structuredSteps/apiEndpoints/testData/executionHints/stateMachineRef 为 JSON 列）、test_case_versions |
| 分析 | code_analysis、state_machines |
| 脑图 | mindmaps |
| 执行 | execution_record（含 test_case_snapshot/writeBack）、execution_step |
| 测试集 | test_suites |
| 配置 | system_settings |

配套：Flyway 管理 schema 版本；一次性 H2→MySQL 迁移（启动检测 + 迁移任务 + H2 文件备份）；compose 新增 aicasetest-mysql（避开 3306/3307）。

## 二、Redis 负责什么（运行态/缓存/队列）

| 类别 | 内容 | 现状（内存态，重启即丢） |
|---|---|---|
| 运行态标志 | 生成/执行取消标志、执行心跳 | cancellationFlags / executionHeartbeats |
| 分布式并发 | 项目级执行配额（信号量） | ProjectExecutionLimiter |
| 安全 | 登录失败计数/锁定、token 黑名单（刷新令牌） | LoginAttemptService 内存计数 |
| 缓存 | 系统设置、生成参数、分析/状态机结果（@Cacheable） | 无 |
| 队列（可选增强） | 生成/执行任务排队（Redis Stream），批次排队计数 | @Async 线程池 + CallerRunsPolicy |
| 进度/会话 | SSE 生成进度、批次 queued/running 计数（可选） | 内存 |

引入 spring-data-redis；运行态迁移后支持多实例部署。

## 三、Milvus 负责什么（语义检索层）

引入 Milvus 做向量检索，支撑"资产智能"：

| 优先级 | 场景 | 说明 |
|---|---|---|
| 必选 | 生成前 RAG 上下文检索 | PRD 分段 + 状态机/业务规则/前端表单/选择器 embedding，生成某模块时语义检索 Top-K 拼进 prompt |
| 必选 | 用例语义去重 | 用例（标题+步骤+预期）embedding，写入时按相似度阈值去重，metadata 过滤 projectId/type |
| 必选 | 用例语义搜索 | 列表/跨项目按语义检索，metadata 过滤（项目/模块/类型/评审状态） |
| 推荐 | 失败经验知识库 | 失败步骤（action/错误/截图路径）embedding，新失败时检索相似历史并提示 |
| 可选 | 跨项目资产复用 | 检索相似用例 → 复制执行/复制到项目（与项目组联动） |
| 可选 | XMind 导入去重 | 导入时语义相似度检测，提示"疑似重复 N 条" |

实现：embedding 管道（生成时/导入时/执行失败时写入向量）+ Milvus collection（cases / contexts / failures）+ 标量字段过滤；引入 Milvus 容器。

## 五、风险与回滚

## 自审发现的问题清单

| 类别 | 问题 | 现状 |
|---|---|---|
| 一致性 | 重新生成落库非事务，中途失败可能只剩半批用例 | runGenerateStream 直接 deleteAll+save |
| 一致性 | 删除项目会留下执行记录/步骤/测试集/用例版本孤儿数据 | ProjectService.deleteProject 只删部分表 |
| 一致性 | 用例增删改/导入/复制后 Milvus 向量不同步 | 只有生成/追加写索引 |
| 一致性 | PRD/分析上下文反复写入 contexts，旧向量堆积 | 只有插入没有按模块替换 |

| 性能 | MySQL 连接池未显式调优 | 用 Spring Boot 默认值 |
| 性能 | Milvus 未建 ANN 索引，检索退化为暴力扫描 | ensureCollection 只建 schema |
| 治理 | 执行记录/录屏/证据无限增长，无保留策略 | 无清理任务 |
| 治理 | 数据健康无观测入口，孤儿/存量无法快速发现 | 无数据健康 API |
