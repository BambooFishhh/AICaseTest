## 1. L14 流式错误处理

**文件**：`service/LlmService.java`（chatStreamingWithUsage，约 L269-309）

现状：
```java
}).doOnError(errorRef::set)
  .doOnComplete(done::countDown)
  .doOnCancel(done::countDown)
  .subscribe();
...
while (!done.await(200, TimeUnit.MILLISECONDS)) { ... }   // error 时永不退出
...
if (cancelSignal != null && cancelSignal.getAsBoolean()) { throw new GenerationCancelledException(...); }
Throwable error = errorRef.get();                          // 永远到不了这里（error 时）
```

改动：
```java
}).doOnError(error -> {
      errorRef.set(error);
      done.countDown();          // v7.11(L14): error 信号也释放 latch，防死循环
  })
  .doOnComplete(done::countDown)
  .doOnCancel(done::countDown)
  .subscribe();
...
// v7.11(L14): errorRef 检查提前——真实错误优先于取消判定，防止网络错误被谎报为"用户取消"
Throwable error = errorRef.get();
if (error instanceof GenerationCancelledException gce) {
    throw gce;                   // doOnNext 内取消异常回流：保持取消语义
}
if (error != null) {
    throw new RuntimeException(error);
}
if (cancelSignal != null && cancelSignal.getAsBoolean()) {
    throw new GenerationCancelledException("用户取消生成");
}
```

**验证**：单测 mock chatClientBuilder 使 flux 发 error 信号——断言抛 RuntimeException 且非 GenerationCancelledException、熔断 onFailure 被调用；flux 正常完成 + cancelSignal=true——断言抛 GenerationCancelledException。

## 2. T1+T2 用例全局唯一编号

**新增** `service/TestCaseIdAllocator.java`：
```java
@Component
public class TestCaseIdAllocator {
    private final TestCaseRepository testCaseRepository;
    private final AtomicInteger cachedMax = new AtomicInteger(-1);   // -1 = 未初始化

    public synchronized String nextId() {
        int max = cachedMax.updateAndGet(v -> v >= 0 ? v : loadMaxFromDb());
        // updateAndGet 内嵌 DB 读取：cachedMax 为 -1 时仅首次查库
        int next = max + 1;
        cachedMax.set(next);
        return String.format("TC-%03d", next);
    }

    private int loadMaxFromDb() {
        return testCaseRepository.findAll().stream()
                .map(TestCase::getId)
                .filter(id -> id != null && id.startsWith("TC-"))
                .mapToInt(this::parseSuffix)
                .max().orElse(0);
    }
    // parseSuffix: substring(3) -> int，异常返回 0
}
```
设计要点：
- JVM 缓存避免逐条查库（60 条生成只查 1 次）；synchronized 保证进程内取号互斥（单实例部署前提，多实例为已知限制）；
- `findAll()` 全表拉取仅在冷启动第一次——之后走 AtomicInteger。全库几千条规模可接受；后续量大可换 `@Query("select t.id from TestCase t where t.id like 'TC-%'")` 投影查询。

**改造点**：

| 文件 | 位置 | 改动 |
|---|---|---|
| `TestCaseService.java` | `nextTestCaseNumber(projectId)`（约 L1080） | 方法体改为 `allocator.nextId()` 解析数字（或直接返回分配器结果），保留签名兼容 4 个调用点（追加/JSON 导入/XMind 导入/跨项目复制） |
| `TestCaseService.java` | `createTestCase`（约 L1197-1200） | 删除 `existing.size() + 1`，改 `tc.setId(allocator.nextId())` |
| `TestGeneratorAgent.java` | 生成收尾编号（约 L813-817） | `int counter = 1; ... String.format("TC-%03d", counter++)` 改为 `tc.setId(idAllocator.nextId())`——注入 TestCaseIdAllocator（Agent 注入 repository/service 已有先例：OrchestratorAgent） |
| `TestCasePersistenceService.java` | replaceAll | 无改动（上游已唯一） |

注意：TestGeneratorAgent 单测中 new TestGeneratorAgent() 手工构造场景需兼容 allocator 为 null（防御式：`tc.setId(idAllocator != null ? idAllocator.nextId() : String.format("TC-%03d", counter++))`）或测试统一注入 mock。

## 3. E12 Playwright 多会话隔离

**3.1 Node 端** `playwright-mcp-server/index.js`：

```js
const sessions = new Map();   // sessionId -> { browser, context, page }

function getSession(id) {
  const s = sessions.get(id || 'default')
  if (!s || !s.page) throw new Error(`会话不存在或已关闭: ${id || 'default'}`)
  return s
}

// browser_launch:
case 'browser_launch': {
  const sid = args.session_id || 'default'
  const old = sessions.get(sid)                       // 同 id 重复 launch：先关旧会话
  if (old) { await closeSession(sid).catch(() => {}) }
  const browser = await chromium.launch({ headless: args.headless ?? true })
  const ctxOpts = { viewport: { width: args.width ?? 1280, height: args.height ?? 720 } }
  if (args.video_dir) { fs.mkdirSync(args.video_dir, { recursive: true });
    ctxOpts.recordVideo = { dir: args.video_dir, size: { width: args.width ?? 1280, height: args.height ?? 720 } } }
  const context = await browser.newContext(ctxOpts)
  const page = await context.newPage()
  sessions.set(sid, { browser, context, page })
  return { content: [{ type: 'text', text: sid }] }
}
```
- 其余工具：`const { page } = getSession(args.session_id)`（navigate/screenshot/visualClick/domClick/fill/keyPress/scroll/getPageStatus）；`const { context } = getSession(...)`（addCookies）；
- `browser_video_save`：`const { page, context } = getSession(args.session_id)`——close 该会话 context 落盘，随后 `sessions.delete(sid)`（视频保存后会话终结，Java 端再 close 走"会话不存在"静默路径）；
- `browser_close`：关闭并 delete 指定会话；`browser_launch` 返回 sessionId（而非 'ok'）——Java 端取用。
- inputSchema：每个工具 properties 加 `{ session_id: { type: 'string', description: '会话 ID（缺省 default）' } }`。
- 错误兜底：不存在的会话返回 isError（现有 catch 统一处理）。

**3.2 Java 端** `skill/PlaywrightRecordSkill.java`：

| 方法 | 改动 |
|---|---|
| `browserLaunch(boolean,int,int)` | 签名改 `browserLaunch(String sessionId, boolean headless, int width, int height)`；MCP 参数加 `"session_id", sessionId`；返回 sessionId |
| `browserNavigate/takeScreenshot/visualClick/domClick/fillInput/pressKey/scroll/addCookies/getPageStatus` | MCP 参数 Map 统一加 `"session_id", sessionId` |
| `stopRecording(String filename)` | 签名改 `stopRecording(String sessionId, String filename)`；MCP 参数加 session_id |
| `closeSession(String sessionId)` | MCP 参数加 `"session_id", sessionId` |
| 截图文件名 | `"screenshots/" + sessionId + "-" + System.currentTimeMillis() + ".png"` 防并发碰撞 |

Map.of(...) 最多 10 对参数——navigate 加 session_id 后 2 对、domClick 2 对、fillInput 3 对、launch 5 对，均在限内；scroll/addCookies/getPageStatus 原用 HashMap，put 即可。

**3.3 调用方** `service/ExecutionService.java`：
- 约 L481：`sessionId = playwrightSkill.browserLaunch(executionId, true, 1280, 800)`——executionId 即会话标识（与 runtimeStore.putSession(executionId, sessionId) 的值一致）；
- 约 L544-549（正常收尾）：`playwrightSkill.stopRecording(executionId 会话, videoPath)`——从 runtimeStore.getSession(executionId) 取（通常等于 executionId）；
- `markRunningCancelled`（约 L1153-1171）：stopRecording 传该 executionId 的 sessionId——**只保存/关闭自己的会话**，并发任务不受影响（核心修复）；
- 其余 browserLaunch 调用点（约 L695 程序化模式路径）同步改传 executionId。

**验证**：单测 mock McpClientManager 断言全部调用携带 session_id；手工/集成验证双会话隔离。
