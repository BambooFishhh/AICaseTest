# 后端技术评审 v5.4：Milvus 语义检索层

> 版本 v5.4，一旦确定尽量不要轻易改动。

## 1. 变更点

### 1.1 依赖与配置

```xml
<dependency>
    <groupId>io.milvus</groupId>
    <artifactId>milvus-sdk-java</artifactId>
    <version>2.4.4</version>
</dependency>
```

```yaml
app:
  milvus:
    enabled: ${APP_MILVUS_ENABLED:false}
    host: ${MILVUS_HOST:localhost}
    port: ${MILVUS_PORT:19530}
    dimension: ${MILVUS_DIMENSION:1536}
    duplicate-threshold: ${MILVUS_DUPLICATE_THRESHOLD:0.92}
```

### 1.2 新增服务

| 服务 | 职责 |
|---|---|
| EmbeddingService | 调用 MCP `llm_embedding`，解析向量 |
| MilvusService | 连接/建集合/insert/search/delete，全部异常降级 |
| SemanticService | 语义去重、RAG 检索、语义搜索、失败经验写入 |

### 1.3 链路接入

- `TestCaseService`：重新生成 clear + indexCases；追加生成语义去重 + indexCases。
- `ProjectService`：PRD 保存/上传/抓取后 indexContext("prd")。
- `AnalysisService`：分析完成后 indexContext("backend"/"frontend")。
- `OrchestratorAgent`：生成前 `retrieveContexts` 填充 `PrdAnalysisResult.ragContexts`。
- `ExecutionService`：最终 failed 时逐失败步骤 `recordFailure`。
- `TestCaseController`：新增 `GET /testcases/semantic-search?q=`。

## 3. API 契约变化

- 新增 `GET /api/projects/{projectId}/testcases/semantic-search?q={query}`，返回 `List<TestCaseDTO>`。
- 其余 API 不变。

## 4. 向后兼容性

- Milvus 默认关闭，`SemanticService.isAvailable()` 为 false 时所有语义调用直接返回空，不影响原流程。

## 5. 测试验证方案

- `mvn compile` / `mvn test`。
- `node --check` 两个 MCP Server。
- 启用 Milvus（compose）后冒烟：PRD 保存 → 分析 → 追加生成（观察 dropped 数）→ 语义搜索 → 失败执行（检索 failures）。
