## 一、v1.2 后端改动点

### 1.1 TestGeneratorAgent — 分模块生成

文件：`backend/src/main/java/com/testagent/agent/TestGeneratorAgent.java`

**现状（v1.1）**：`generate(stateMachines, backendResult)` 一次性把所有状态机传给 LLM。

**v1.2 改造**：

```
generate(stateMachines, backendResult):
  result = []
  for sm in stateMachines:
    try:
      cases = generateByLlmForStateMachine(sm, backendResult)   // 单模块 LLM 生成
    catch:
      cases = generateByRulesForStateMachine(sm, backendResult) // 单模块规则回退
    result.addAll(cases)
  // 无状态机时回退：按 endpoints 生成（保留 v1.1 逻辑）
  if result.isEmpty() && backendResult.endpoints:
    result = generateByEndpoints(backendResult)
  result = deduplicate(result)       // 去重
  calculateQualityScores(result)     // 质量评分
  重新编号 ID
  return result
```

- `generateByLlmForStateMachine(sm, backendResult)`：复用现有 prompt 逻辑，但 context 只含 1 个状态机 + matchEndpoints 匹配的相关端点
- `generateByRulesForStateMachine(sm, backendResult)`：复用现有 buildPositiveTest/buildNegativeTest/buildBoundaryTest（已实现），针对单个 sm
- `generateByEndpoints(backendResult)`：抽取现有"无状态机时按 endpoint 生成"逻辑

**收益**：单次聚焦、避免 token 超限、单点失败隔离。

### 1.2 用例去重

新增方法 `deduplicate(List<TestCase> cases)`：
- 标题完全相同 → 保留首个
- 标题字符重叠率 > 80% 且 module 相同 → 保留 qualityScore 更高者
- 重叠率计算：`intersection(title1, title2).length / max(title1, title2).length`

### 1.3 质量评分

新增方法 `calculateQualityScore(TestCase tc)` 返回 int（0-100）：

| 维度 | 分值 | 判定 |
|------|------|------|
| 结构化步骤完整 | 30 | structuredSteps 非空且每步含 action+target+expected |
| 关联接口 | 20 | apiEndpoints 非空 |
| 测试数据 | 15 | testData 非空 |
| 执行提示 | 15 | executionHints 非空且含 approach |
| 步骤数量 | 10 | structuredSteps 步骤数 >= 2 |
| 预期结果 | 10 | expectedResults 非空 |

新增方法 `calculateQualityScores(List<TestCase> cases)`：遍历设置 qualityScore。

**注意**：去重依赖 qualityScore，因此先计算评分再去重。

### 1.7 TestCaseService — 覆盖率计算

文件：`backend/src/main/java/com/testagent/service/TestCaseService.java`

`listTestCases()` 增加覆盖率计算并塞入响应：

```java
Map<String, Object> coverage = calculateCoverage(projectId, all);
return TestCaseListResponse.builder()
        .total(total).page(page).pageSize(pageSize)
        .testCases(items)
        .coverage(coverage)
        .build();
```

新增方法 `calculateCoverage(projectId, allTestCases)`：
- 查 `stateMachineRepository.findByProjectId(projectId)` 汇总总 transitions
- 查 `codeAnalysisRepository.findByProjectId(projectId)` 取总 endpoints
- 遍历 allTestCases 提取已覆盖 transitions（from→to 对）和 endpoints（method+path）
- 计算 covered/total/rate
- 计算 typeDistribution

## 四、风险与对策

| 风险 | 对策 |
|------|------|
| 分模块生成增加 LLM 调用次数 | 异步生成，单次更聚焦；可接受 |
| 覆盖率计算增加 listTestCases 耗时 | 数据量有限（百级用例 + 十级状态机），计算轻量 |
| 去重误删 | 相似度阈值 80% 保守，仅同模块才判重 |
