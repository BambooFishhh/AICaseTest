## 2. 线程池饱和快速失败链路

### 2.1 AsyncConfig

`buildExecutor` 增加 rejectFast 参数：

- analysis/generation 池 → 快速拒绝 handler（log.error + 抛 RejectedExecutionException）。旧 CallerRunsPolicy 让分钟级 AI 任务回落 HTTP 线程，阻塞全部普通接口
- execution/semantic 池 → 保留 CallerRuns（短任务，降失败率）

### 2.2 调用方逐点兜底

| 入口 | 行为 |
|---|---|
| ProjectController 三个 SSE 流式接口 | catch RejectedExecutionException → 发 `error` 事件"服务器繁忙，任务队列已满"+ complete |
| ProjectService.startAnalysis/startGenerate | catch → 项目状态回滚（analyzing/generating → 原状态）+ 50300 业务异常 |
| TestCaseReviewRunner.startReview | catch → markReviewFailed("评审任务队列已满")，不卡 reviewing |

## 3. 流式重试一致性与解析容错

### 3.1 LlmService

- **流级看门狗** `llm.stream-total-timeout-ms`（默认 900s）：轮询检查 deadline，超时 dispose 并抛含 timeout 字样的异常（重试策略识别为可重试）——网关心跳保活时底层 read-timeout 不触发
- **retryResetHook**：chatStreaming 新增带 Runnable 的重载；某次尝试已向消费者推送过内容（delivered 标记）且失败重试前回调 hook
- **boundPrompt 保头尾**：超限裁剪从纯头部改为保头 3/4 + 保尾 1/4（封顶 40k）——任务指令与 gaps 清单在尾部；触发即 log.error（保险丝语义）

### 3.2 TestGeneratorAgent

- StreamingTestCaseParser.reset()：清空 buffer/scanPos/状态机/parsedCount/collected——LLM 重订阅全量重推前必须清态
- CaseCallback 新增 default onRetryReset()；生成流式路径把 parser.reset + caseCb.onRetryReset 打包传入 LlmService
- parseTestCases 逐条容错：单条 buildTestCase 异常跳过并 warn（含片段），整段非 JSON 数组才上抛触发重试
- extractJsonArray 遍历全部代码围栏取第一个可解析为 JSON 数组的块（looksLikeJsonArray 试解析）
- normalizeCaseType/normalizePriority 白名单归一：中文别名/大小写变体映射到 positive/negative/boundary/data 与 P0~P3，防脏值入库
- prompt 注入防护：系统提示追加【输入安全约定】+ 用户上下文以 `<context>` 定界隔离

### 3.3 TestCaseService

两个流式入口的 CaseCallback 改匿名类实现 onRetryReset → 向 SSE 推送 `retryReset` 事件，前端清空已渲染草稿后接收重推。

## 4. 数据层加固

### 4.1 MilvusService

- truncateToBytes：按 schema VarChar 上限（UTF-8 字节）预截断，回退多字节字符边界；id≤128B/project≤64B/title≤512B/module≤128B/text≤8192B；截断计数告警。修复中文超限插入失败仅 warn 导致向量静默丢失
- escapeExpr：布尔表达式字符串转义（反斜杠+双引号），buildSearchExpr/deleteByProject/deleteByIds/deleteByModule 全部收敛走此方法——module 来自分析器/LLM 可能含引号，未转义时 expr 语法错误检索静默空召回
- deleteWithRetry：删除统一入口，2 次短重试，终败升级 ERROR（残留向量=幽灵用例/误判重复，需可告警对账）

### 4.2 SemanticService

去重 embedding 全批并行预计算（固定 4 线程池 + CompletableFuture.allOf）：60 条由 N 次串行 HTTP 往返降到约 N/4；单条失败降级空向量（该条退出语义判重，结构判重兜底）。

## 5. 安防收敛

| 点位 | 措施 |
|---|---|
| FilesystemController | 根节点只返回 `app.filesystem.browse-roots` 白名单（默认 projects 目录 + git 克隆目录）；子路径 toAbsolutePath().normalize() 后必须 startsWith 某白名单根——旧 contains("..") 检查在 normalize 后实际无效 |
| McpBridgeController.analyze* | sourcePath 白名单校验（projects/git 目录内），越界抛 40300；bridge token 改 MessageDigest.isEqual 常量时间比较，空/弱 token 直接拒绝 |
| GitCloneService | assertNotInternalHost：http(s)/git 协议解析全部 A 记录，任一落在回环/私网/链路本地/任意本地即拒绝；域名无法解析报 invalidParam；ssh/git@ 无法预解析仅 INFO 告知跳过 |
| CORS 双轨 | 全部 Controller 移除 @CrossOrigin，统一走 WebConfig.addCorsMappings（app.cors.allowed-origins）+ SecurityConfig cors |
