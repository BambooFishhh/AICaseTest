# 后端技术评审 v7.1 — 生成链路一致性修复

**评审范围**: TestGeneratorAgent / TestCaseReviewAgent / OrchestratorAgent / TestCaseService / SemanticService

---

## 1. TestGeneratorAgent.java

### 1.1 统一 PRD 生成管线（G2/G11 载体）
generate（6 参）与 generateStreaming（8 参）原本是两份近乎相同的 120 行代码，改为共同委托私有 `runPrdPipeline(..., caseCb, cancelled, params, report)`：

```
runPrdPipeline:
  前置: prdResult 空 → "请先添加 PRD 文档"
  effectiveCb = wrapFocusFilter(params, caseCb)        // 聚焦类型仅透传推送
  result = generateByLlmWithPrd(..., effectiveCb, ..., report)
  report.generated = result.size()
  result = filterByFocusTypes(params, result)
  report.focusDropped = 差值
  G11: result 为空且 focusTypes 非空 → 抛"已生成 N 条，但聚焦类型 [...] 过滤后为 0 条"
  enrichStructuredSteps(...)                            // G3: 不再补空 data
  result = review(result, checklist, "generation", report)  // review agent 内记录 reviewDropped/reviewDegraded
  calculateQualityScores → deduplicate                  // report.dedupDropped
  result = semanticService.deduplicateBatch(result)     // G14: report.semanticDropped
  编号 TC-001... → report.finalCount
```

- 新增重载 `generate(..., GenerationReport)` / `generateStreaming(..., GenerationReport)`，旧签名委托新签名（既有调用方与测试不动）
- 取消语义保持：GenerationCancelledException 直接上抛不包装；其他异常包装 BusinessException(50016)

### 1.2 GenerationReport（新增 public static class）
字段：generated / focusDropped / reviewDropped / dedupDropped / semanticDropped / finalCount / roundsNotConverged / reviewDegraded + toMap()。
- `roundsNotConverged`：generateByLlmWithPrd 循环结束后 `all.size() < MAX_GENERATED_CASES && hasRemainingGaps(...)` 时置位（达上限导致的缺口属 G10，不算未收敛）
- `reviewDegraded`：由 TestCaseReviewAgent 置位（LLM 评审失败保留规则评审结果时）

### 1.3 isDuplicate 判重修复（G1）
```java
boolean sameType = typeA.equals(typeB);
if (titleA.equals(titleB) && sameType) return true;
if (modA.equals(modB) && sameType) {
    if (titleA.contains(titleB) || titleB.contains(titleA)) return true;
    if (titleA.length() <= 20 && titleB.length() <= 20) {
        // v7.1(G1): 0.8 → 0.9，且 type 必须一致
        if (maxLen > 0 && (double) intersection.size() / maxLen > 0.9) return true;
    }
}
// v5.14 指纹判重不变（本就要求 type 一致）
```
isDuplicate 由 private 收窄为包级可见（供单测直接验证判重语义）。

### 1.4 enrichStructuredSteps（G3）
删除 `if (best.containsKey("name") && step.get("data") == null) { data.put(name, ""); }` 分支：
- DOM 执行路径取 `inputValue`/`value` 字段，不读 data map（已核实 ExecutionService L680-705）
- Agent 模式 data 由 LLM 决定；空字符串占位会让必填校验必败
- 分析器表单字段目前仅有 name/type/label/required/rules，无默认值来源——宁缺勿错

## 2. TestCaseReviewAgent.java

新增 4 参重载 `review(cases, coverage, source, report)`，原 2/3 参签名委托：
- `ruleReview` 丢弃（无 structuredSteps）+ `llmReview` reject 丢弃 → `report.reviewDropped = 输入 - 输出`
- llmReview 抛异常被 catch 时 → `report.reviewDegraded = true`（G5 真实降级信号）

## 3. OrchestratorAgent.java

- generate / generateStreaming 各加 report 重载，透传给 TestGeneratorAgent（G2）
- loadGenerationContext（G15）：catch 块内直接判断——settings 有实质内容（非空且非 "{}"）却解析失败 → 抛 50015"项目配置解析失败：无法读取需求文档配置..."；settings 为空/{} 时维持 warn 降级（新项目未配置属正常路径），后续走"请先添加 PRD 文档"

## 4. TestCaseService.java

- hasPrd（G15）：JSON 解析异常由静默 return false 改为抛 IllegalStateException（含原因），三处调用点外层 catch 会以 failed 状态如实展示
- runGenerate / runGenerateStream / runGenerateStreamAppend：创建 GenerationReport 传入；markDegraded 判定改为 `report.roundsNotConverged || report.reviewDegraded`（G5）
- runGenerateStream（G2）：
  - caseCb 包装 AtomicInteger pushedCount（实际推送计数，比 generated-focusDropped 推导更可信）
  - complete 事件：`{total, pushed, droppedTotal, dropped:{focusType,review,dedup,semantic,other}, roundsNotConverged, reviewDegraded}`，other = pushed - total - 各分类和（吸收流式/全量解析差，即 G8 的错位量，为 v7.10 观测留钩子）

## 5. SemanticService.java（G14）

新增 `deduplicateBatch(List<TestCase>)`：
- 前置跳过：size<2 或 !isAvailable()
- 逐条 embed（title + module，与跨库 isDuplicate 同文本形状）→ 与已保留集做余弦相似度，≥ milvusService.duplicateThreshold() 判重
- type 不同不判重（G1 同款原则）；判重保留 qualityScore 高者（替换语义与 deduplicate 一致）
- 余弦实现本地计算；异常时整体跳过返回原列表（与跨库判重降级行为一致）
- 成本：≤ MAX_GENERATED_CASES(60) 次 embed，与落库后 indexCases 的全量 embed 同量级
