## 1. L4a 头尾保留截断（PrdAgent）

### 1.1 truncateDoc 改造

```java
private String truncateDoc(String content) {
    String trimmed = content == null ? "" : content.trim();
    if (trimmed.length() <= MAX_PRD_LENGTH) {
        return trimmed;
    }
    int half = MAX_PRD_LENGTH / 2;  // 6000
    return trimmed.substring(0, half)
            + "\n...(中略 " + (trimmed.length() - MAX_PRD_LENGTH) + " 字符)...\n"
            + trimmed.substring(trimmed.length() - half)
            + "\n...(文档头尾各保留 " + half + " 字符)";
}
```

### 1.2 总量截断同理

`buildRequirementPrompt` 末尾的 `sb.setLength(MAX_TOTAL_DOC_LENGTH)` 改为头尾各保留 12000：

```java
if (sb.length() > MAX_TOTAL_DOC_LENGTH) {
    String full = sb.toString();
    int half = MAX_TOTAL_DOC_LENGTH / 2;
    sb = new StringBuilder(full.substring(0, half)
            + "\n...(中略)...\n" + full.substring(full.length() - half)
            + "\n...(需求资料头尾各保留 " + half + " 字符)");
}
```

**风险**：头尾拼接处语义断裂——中略标记明示 LLM 存在省略，比静默丢尾更诚实。

## 2. A13 大 PRD 解析失败降级重试（PrdAgent）

### 2.1 降级重试流程

`analyzeByLlm` 内部（完整解析 `parsePrdResponse(response)` 返回 null 或 isEmpty 时）：

```java
// 完整解析失败 → 瘦身重试一次（只要求核心三块，stateFlows/entities 由代码侧提供）
String slimSystemPrompt = promptSkillLoader.load("prd-analysis-slim", SLIM_PROMPT);
// SLIM_PROMPT 只要求 {"modules":[...],"requirements":[...],"businessRules":[...]}
PrdAnalysisResult slim = 走缓存 → llmService.chatWithAnalysis(slimSystemPrompt, userPrompt, 0.2) → 解析;
if (slim != null && !slim.isEmpty()) {
    log.warn("[PRD] 完整解析失败，降级为核心需求解析（stateFlows/entities 缺失，由代码分析补充）");
    return slim;  // 缓存写入同 v7.5 规则
}
```

- 瘦身 prompt 与完整 prompt 的 systemPrompt 不同 → 缓存键天然分离，互不污染
- 两次都失败 → 抛 BusinessException，消息附文档长度：`"PRD 解析失败：需求资料 N 字符，模型输出可能被截断，请精简文档或拆分后重试"`（替换现有笼统消息）
- `analyze()` 外层 catch 保持不变（降级结果非空即返回）

**不做**：截断 JSON 的局部补全抢救（流式生成路径 v7.3(L8) 已有类似机制，PRD 解析是非流式 chat，补全逻辑不通用）。

## 3. A4a supplementalEndpoints 源码校验（SpringAnalyzer）

### 3.1 证据收集（enhanceWithLlm 内，LLM 调用前）

```java
// 类名集合：文件名去 .java（Controller 类名与文件名一致的 Spring 约定）

// 类级 @RequestMapping 前缀：正则扫控制器文件
// @RequestMapping("/api/order") / @RequestMapping(value = "/api/order")
Set<String> knownPathPrefixes = ...;
```

签名变更：`mergeSupplementalEndpoints(JsonNode nodes, List<EndpointInfo> endpoints)` → 增加 `Set<String> knownClasses, Set<String> knownPathPrefixes, List<String> warnings` 参数。

### 3.2 校验规则

```java
String cls = function.contains(".") ? function.substring(function.lastIndexOf('.') + 1) 前'.'段 : "";
// 注意 function 形如 "OrderController.create"——取最后一个 '.' 之前整体可能含包名，
// 取"文件名可匹配"策略：knownClasses 中任一类名出现在 function 字符串中即可
boolean pass = !function.isBlank() && knownClasses.stream().anyMatch(function::contains)
        || knownPathPrefixes.stream().anyMatch(path::startsWith);
if (!pass) {
    warnings.add("LLM 补充接口未通过源码校验已丢弃: " + method + " " + path);
    continue;  // 丢弃
}
```

**取舍**：`anyMatch(function::contains)` 是宽松匹配（类名出现在 function 字符串任意位置）——宁可放过不可误杀（LLM 可能带包名前缀）；路径前缀校验作为第二道闸。

## 4. A5 规则层参数提取（SpringAnalyzer）

### 4.1 extractEndpoints 内新增参数解析

```java
List<Map<String, Object>> parameters = new ArrayList<>();
String requestBody = null;
for (Parameter p : method.getParameters()) {
    AnnotationExpr ann = p.getAnnotationByName("RequestParam")
            .or(() -> p.getAnnotationByName("PathVariable")).orElse(null);
    if (ann instanceof NormalAnnotationExpr n) { /* name/value/required/defaultValue 成员对 */ }
    else if (ann instanceof SingleMemberAnnotationExpr s) { /* @RequestParam("name") 简写 */ }
    else if (ann instanceof MarkerAnnotationExpr) { /* 无属性，用参数名 */ }
    // @RequestParam → in=query, required 缺省 true
    // @PathVariable → in=path, required true
    // @RequestBody（MarkerAnnotation）→ requestBody = p.getType().asString()；parameters 加 in=body 条目
}
```

- 参数 type 取 `p.getType().asString()`
- 挂到 `EndpointInfo.builder().parameters(parameters).requestBody(requestBody != null ? requestBody : 原逻辑)`——requestBody 原值为 null（规则层此前不填），有 @RequestBody 时填类型名
- sources 仍为 `List.of("rules")`——参数现在是规则层事实

## 5. G16 RAG 切片并入考点清单（TestGeneratorAgent）

### 5.1 buildCoverageChecklist 扩展

```java
// requirements 构建后追加：
int ragSeq = 1;
for (String slice : prdResult.getRagContexts() == null ? List.<String>of() : prdResult.getRagContexts()) {
    if (ragSeq > 20) break;  // 上限 20
    String title = 首个非空行剥离 "#* " 前缀，截 60 字符;
    if (title.length() < 4) continue;  // 太短无区分度
    if (maxSimilarityScore(title, requirements) >= 3) continue;  // 已有需求覆盖（token 重叠打分）
    Map<String, Object> item = {id: "rag-req-" + ragSeq++, title, description: slice 前 200 字符, source: "rag"};
    requirements.add(item);
}
```

**相似度打分**（复用 bestSelector 思路，新私有方法 `scoreTextOverlap(String a, String b)`）：
- 双方按 `[^a-zA-Z0-9\u4e00-\u9fa5]+` 切词，token ≥2 字符
- 一方 token 在另一方文本（lowercase contains）中出现 → +token 长度
- 阈值 3：约一个 3 字词或两个 2 字词的重叠即判同需求

新需求自动进入 `gaps.requirementIds`（现有 stream 已覆盖——requirements 加完再算 gaps）。

## 10. 风险与回滚

- **G17 过滤误伤**：关键词匹配不到相关 endpoint → 兜底全量；阈值取 ">0"（极宽松）确保只过滤明显无关项
- **G16 噪声需求**：RAG 切片标题可能非需求语义（如表格行）→ 相似度阈值 + 最短标题 4 字符 + 上限 20 三重限制；观察到噪声率过高再上 LLM 去重（非目标已声明）
- **A13 降级质量**：stateFlows 缺失影响 StateMachineAgent 的 LLM 输入（有代码侧兜底）——可接受，比阻断生成好
- 回滚：各改动点独立（无 schema 变更），revert 单文件即可
