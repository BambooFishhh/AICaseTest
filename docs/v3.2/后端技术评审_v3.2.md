# 后端技术评审 v3.2 — 用例生成流式输出（SSE）

**版本**: v3.2
**基线**: v3.1
**日期**: 2026-08-11
**一旦确定尽量不要轻易改动**

---

## 1. 改动总览

在现有 `POST /generate` 异步生成链路之外，新增一条 SSE 流式生成链路：Controller 返回 `SseEmitter`，`@Async` 任务在后台执行生成，每解析出一条用例即通过 emitter 推送 `case` 事件，最终推送 `complete` 并落库。旧端点保留不动。

## 2. 改动点

### 2.1 `agent/TestGeneratorAgent.java` — 新增 CaseCallback + generateStreaming

```java
// v3.2: 用例流式回调接口，每生成一条用例立即回调一次（用于 SSE 推送）
@FunctionalInterface
public interface CaseCallback {
    void onCase(TestCase tc);
}
```

新增重载 `generateStreaming`，与现有 `generate` 行为一致（PRD 驱动 / 代码驱动分支、去重、质量评分、编号），仅在"每条用例解析完成时"额外触发 `caseCb.onCase(tc)`：

```java
// v3.2: 流式重载。caseCb 每条用例解析后立即回调（去重前），用于 SSE 推送
public List<TestCase> generateStreaming(PrdAnalysisResult prdResult, List<StateMachine> stateMachines,
                                        BackendResult backendResult, FrontendResult frontendResult,
                                        ProgressCallback progressCallback, CaseCallback caseCb) {
    List<TestCase> result = new ArrayList<>();
    if (prdResult != null && !prdResult.isEmpty()) {
        progressCb(progressCallback, "基于 PRD 生成用例...");
        try {
            result = generateByLlmWithPrdStream(prdResult, stateMachines, backendResult, frontendResult, caseCb);
        } catch (Exception e) {
            log.warn("PRD-driven streaming generation failed, fallback to code-driven: {}", e.getMessage());
            result = new ArrayList<>();
        }
    }
    if (result.isEmpty()) {
        result = generateCodeDrivenCasesStream(stateMachines, backendResult, frontendResult, progressCallback, caseCb);
    }
    progressCb(progressCallback, "正在质量评分与去重...");
    calculateQualityScores(result);
    result = deduplicate(result);
    int counter = 1;
    for (TestCase tc : result) {
        tc.setId(String.format("TC-%03d", counter++));
        tc.setCreatedAt(LocalDateTime.now());
    }
    return result;
}
```

**逐条回调时机**：在 `parseTestCases` 解析循环中，每 `result.add(tc)` 后立即 `caseCb.onCase(tc)`。为避免大改 `parseTestCases` 签名，新增 `parseTestCasesStreaming(json, caseCb)` 重载，原 `parseTestCases(json)` 改为调用 `parseTestCasesStreaming(json, null)`。

**代码驱动分支**：`generateCodeDrivenCasesStream` 与原 `generateCodeDrivenCases` 结构一致，`generateByLlmForStateMachine` 调用后用 `parseTestCasesStreaming` 解析并触发回调；规则回退分支（`generateByRulesForStateMachine`/`generateByEndpoints`）同样在每条 `result.add` 后触发 `caseCb.onCase`。

### 2.3 `service/TestCaseService.java` — 新增 runGenerateStream

```java
// v3.2: SSE 流式生成。emitter 由 Controller 传入，本方法负责推送事件并落库
@Async("generationExecutor")
public void runGenerateStream(String projectId, SseEmitter emitter) {
    AtomicBoolean clientGone = new AtomicBoolean(false);
    emitter.onCompletion(() -> { clientGone.set(true); log.info("SSE client disconnected: {}", projectId); });
    emitter.onTimeout(() -> { clientGone.set(true); log.warn("SSE timeout: {}", projectId); });
    emitter.onError(t -> { clientGone.set(true); log.warn("SSE error: {}", projectId, t); });

    try {
        // 前置校验（复用 runGenerate 逻辑）
        Project project = projectRepository.findById(projectId)
                .orElseThrow(() -> new IllegalArgumentException("项目不存在: " + projectId));
        boolean hasPrd = project.getPrdContent() != null && !project.getPrdContent().isBlank();
        CodeAnalysis analysis = codeAnalysisRepository.findByProjectId(projectId).orElse(null);
        boolean hasAnalysis = analysis != null && "completed".equals(analysis.getStatus());
        if (!hasPrd && !hasAnalysis) {
            throw new IllegalStateException("请先输入 PRD 或完成代码分析，至少需要一项才能生成用例");
        }
        updateProjectStatus(projectId, "generating");

        // 进度/用例回调 → emitter 推送
        TestGeneratorAgent.ProgressCallback progressCb = msg -> {
            sendEvent(emitter, clientGone, "progress", Map.of("message", msg));
            projectRepository.updateProgress(projectId, msg);
        };
        TestGeneratorAgent.CaseCallback caseCb = tc -> {
            sendEvent(emitter, clientGone, "case", Map.of("testCase", TestCaseDTO.from(tc)));
        };

        List<TestCase> testCases = orchestratorAgent.generateStreaming(projectId, progressCb, caseCb);

        progressCb.update("正在保存用例...");
        testCaseRepository.deleteAll(testCaseRepository.findByProjectId(projectId));
        for (TestCase tc : testCases) {
            tc.setProjectId(projectId);
            testCaseRepository.save(tc);
        }
        projectRepository.updateProgress(projectId, null);
        updateProjectStatus(projectId, "completed");

        sendEvent(emitter, clientGone, "complete", Map.of("total", testCases.size()));
        safeComplete(emitter, clientGone);
        log.info("Streaming generation completed for project {}: {} cases", projectId, testCases.size());
    } catch (Exception e) {
        log.error("Streaming generation failed for project {}", projectId, e);
        String errorMsg = e.getMessage() != null ? e.getMessage() : e.getClass().getSimpleName();
        projectRepository.updateStatusWithError(projectId, "failed", errorMsg);
        sendEvent(emitter, clientGone, "error", Map.of("message", errorMsg));
        safeCompleteWithError(emitter, clientGone, e);
    }
}

// 安全推送：客户端已断开则跳过，IllegalStateException 静默吞掉
private void sendEvent(SseEmitter emitter, AtomicBoolean clientGone, String name, Object data) {
    if (clientGone.get()) return;
    try {
        emitter.send(SseEmitter.event().name(name).data(data, MediaType.APPLICATION_JSON));
    } catch (IllegalStateException | IOException ex) {
        clientGone.set(true);
        log.debug("SSE send failed (client likely gone): {}", ex.getMessage());
    }
}

private void safeComplete(SseEmitter emitter, AtomicBoolean clientGone) {
    if (clientGone.get()) return;
    try { emitter.complete(); } catch (Exception ignored) {}
}

private void safeCompleteWithError(SseEmitter emitter, AtomicBoolean clientGone, Exception e) {
    if (clientGone.get()) return;
    try { emitter.completeWithError(e); } catch (Exception ignored) {}
}
```

**关键点**：
- `@Async("generationExecutor")` 复用现有线程池，与 `runGenerate` 共用，互斥由 `generating` 状态保证
- `clientGone` 标志位由 `onCompletion`/`onTimeout`/`onError` 置位，`sendEvent` 每次检查，避免客户端断开后 send 抛异常
- `TestCaseDTO.from(tc)` 序列化用例为前端可读结构（与 `GET /testcases` 一致）
- 落库逻辑与 `runGenerate` 完全一致（先删后存），保证数据一致性

### 2.4 `controller/ProjectController.java` — 新增 SSE 端点

```java
// v3.2: SSE 流式生成端点
@GetMapping("/{projectId}/testcases/generate-stream")
public SseEmitter generateStream(@PathVariable String projectId) {
    // 并发校验：generating 状态直接拒绝（避免 @Async 任务启动后才发现冲突）
    Project p = projectService.getProject(projectId); // 复用，找不到会抛 BusinessException
    if ("generating".equals(p.getStatus())) {
        SseEmitter err = new SseEmitter(0L);
        try {
            err.send(SseEmitter.event().name("error").data(
                    Map.of("message", "正在生成中，请等待当前任务完成"),
                    MediaType.APPLICATION_JSON));
            err.complete();
        } catch (Exception ignored) {}
        return err;
    }
    SseEmitter emitter = new SseEmitter(5L * 60 * 1000); // 5 分钟超时
    testCaseService.runGenerateStream(projectId, emitter);
    return emitter;
}
```

**为什么用 `@GetMapping`**：浏览器 `EventSource` 仅支持 GET。

**为什么不做 `@RequestParam`**：流式生成复用项目内全部 PRD + 代码上下文，无需参数。

### 2.5 路由说明

SSE 端点路径 `/api/projects/{projectId}/testcases/generate-stream` 与 `TestCaseController` 的 `@RequestMapping("/api/projects/{projectId}/testcases")` 前缀重叠，但放在 `ProjectController`（`@RequestMapping("/api/projects")`）中更合理，因为：
1. `ProjectController` 已有 `POST /{projectId}/generate` 旧端点，流式端点是它的流式版本，逻辑上同属项目级操作
2. `TestCaseController` 侧重 CRUD，生成触发放项目级更清晰

> 注意：`ProjectController` 的 `@RequestMapping` 是 `/api/projects`，子路径 `/{projectId}/testcases/generate-stream` 不与 `TestCaseController` 冲突（后者整体挂在该子路径下，但 Spring MVC 按方法级 `@GetMapping` 精确匹配，无歧义）。

## 4. 线程模型与并发

```
HTTP 线程（Tomcat）                    generationExecutor 线程
─────────────────────                  ──────────────────────
Controller.generateStream()
  ├─ 创建 SseEmitter
  ├─ testCaseService.runGenerateStream()  ──代理──►  runGenerateStream()
  └─ return emitter                                    ├─ 校验 + 设 generating
       │                                               ├─ OrchestratorAgent.generateStreaming()
       │                                               │    ├─ PrdAgent.analyze
       │                                               │    └─ TestGeneratorAgent.generateStreaming()
       │                                               │         └─ 每条用例 → caseCb → emitter.send(case)
       │                                               ├─ 落库
       │                                               ├─ emitter.send(complete)
       │                                               └─ emitter.complete()
       ▼
  Spring MVC 持有 emitter，HTTP 线程释放
  emitter.send 由 generationExecutor 线程调用
```

- `SseEmitter` 线程安全，可跨线程 send
- `@Async` 必须由其他 Bean 调用才生效（Controller → Service 跨 Bean，OK）
- `generationExecutor` 线程池 core=2/max=4/queue=20，SSE 任务与旧 `runGenerate` 共用，互斥由 `generating` 状态保证

## 6. 异常与边界

| 场景 | 处理 |
|------|------|
| 项目不存在 | `ProjectService.getProject` 抛 `BusinessException` 404，返回标准错误响应（非 SSE） |
| 项目状态为 generating | 推送 `error` 事件 + 立即 complete |
| 无 PRD 且无分析 | `runGenerateStream` 内抛异常 → 推送 `error` + 设 status=failed |
| 客户端中途断开 | `onCompletion` 置 `clientGone=true`，后续 send 静默跳过；生成继续完成落库 |
| emitter 超时（5min） | `onTimeout` 置 `clientGone=true`；生成线程继续完成落库 |
| LLM 调用失败 | `TestGeneratorAgent` 内部已 try-catch 回退规则生成；若规则也失败 → 抛异常 → 推送 error |
| 推送时序列化失败 | `sendEvent` catch `IOException`，置 `clientGone=true`，不再推送 |
