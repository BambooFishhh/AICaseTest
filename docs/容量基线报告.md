### 1.2 并发压测（v8.9.6 补充：8 worker × 150 = 1200 请求 / **0 失败** / 5.9s）

### 1.4 SSE 生成场景实测（2026-08-31，真实 LLM token，原"待补"项解除）

> 环境：单实例 backend + 真实 LLM（.env 供应商）；数据集=黄金 small PRD（326 字符）×4 个专用项目（perf-sse-load*，测试后可删）；计时口径=SSE 事件流（首条 case 事件→complete 事件）。

| 场景 | 结果 |
|---|---|
| 单项目全量生成（冷 PRD 缓存） | 14 条推送，首条用例 **148.7s**，总耗时 378.2s，complete（语义去重 -2） |
| 单项目全量生成（热缓存，v7.5 prompt-hash 缓存命中） | 首条用例 **28.9s（-81%）**，总耗时 **127.0s（-66%）** |
| 同项目 4 路并发追加 | 1 路 busy 秒拒（0.0s 快速失败），2 路并行（首条 31.8/38.8s，与单路持平），1 路排队顺延 |
| 同项目 8 路并发追加 | 5 路 busy 秒拒、2 路并行、1 路排队；全程零失败零互踩 |
| 跨项目 4 路并行全量（1 热 3 冷） | 全部 complete，首条 72.3 / 29.3(热) / 177.8 / 295.6s，总耗时 150.7~356.6s，degradedProvider 全空 |

结论：
1. **项目级生成单例锁**符合设计——同项目超额并发秒级 busy 拒绝，不排队不互踩（HTTP 线程零占用）；
2. **LLM 四通道信号量（text=6）**可吸收 4 路跨项目并行，无等待超时/降级；
3. PRD 解析缓存对首条用例延迟收益显著（-81%），冷/热差异即"分析→规划"前置段耗时（约 120s）。
