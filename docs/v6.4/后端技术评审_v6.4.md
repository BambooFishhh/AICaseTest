# 后端技术评审 v6.4 — RAG 切片化与多源检索增强

> 版本 v6.4，一旦确定尽量不要轻易改动。

## 1. 变更点

### 1.1 新增 `service/RagTextChunker.java`

```java
public final class RagTextChunker {
    public record Chunk(String title, String text) {}

    public static List<Chunk> chunk(String text, int chunkSize, int overlap)
}
```

- 按 Markdown 标题与空行段落切块，标题下沉到后续块作为 `title`。
- 长块按中文/英文标点边界二次切分并保留重叠。
- 供 `SemanticService` 索引需求文档与补充需求时使用。

### 1.2 `service/SemanticService.java`

- 新增 `replaceRequirementContexts(projectId, prdDocs, contextDocs, supplementary)`：按 `prd` / `context` / `supplementary` 三个 module 重建 Milvus 切片索引。
- 新增 `retrieveContexts(projectId, queries, topK, modules)`：支持 module 过滤，内部使用 RRF 融合。
- 新增 `retrieveFailures(projectId, queries, topK)`：检索失败经验库，同样走 RRF。
- `retrieveContexts` 单查询重载保留，MCP 桥接接口行为兼容。
- 空结果降级逻辑不变：Milvus 未启用时返回 `List.of()`。

代码片段（RRF 融合核心）：

```java
for (int i = 0; i < hits.size(); i++) {
    SearchHit hit = hits.get(i);
    acc.compute(hit.id(), (id, a) -> {
        if (a == null) a = new RrfAccumulator(hit);
        a.rrf += 1.0 / (rrfK + i + 1);
        if (hit.score() > a.cosine) {
            a.cosine = hit.score();
            a.hit = hit;
        }
        return a;
    });
}
```

### 1.3 `service/MilvusService.java`

- `SearchHit` 增加 `module` 字段，便于上层过滤与格式化。
- 新增 `search(collection, projectId, vector, topK, modules)` 重载，expr 支持 `module in [...]`。
- 原 `search(...)` 签名保留并委托给新重载，兼容现有调用。

### 1.4 `service/ProjectService.java`

- 新增私有方法 `reindexRequirementContexts(Project p)`，统一从 `loadReqDocs` 与 settings 提取文档后调用 `semanticService.replaceRequirementContexts`。
- `updatePrd` / `uploadPrdPdf` / `fetchPrdUrl` / `updateProjectContext` 全部改为调用该方法，替代原先只写整篇 PRD 的 `replaceContext("prd", ...)`。
- 新增 `ensureRequirementContexts`：按需求文档指纹判断索引是否过期，存量项目首次生成时自动切片重建，内容不变不重复 embedding。
- 新增 `ensureRequirementContexts`：按需求文档指纹判断索引是否过期，存量项目首次生成时自动切片重建，内容不变不重复 embedding。

### 1.5 `agent/OrchestratorAgent.java`

- 将 `prdDocs` / `contextDocs` / `otherContextInfo` 写入 `PrdAnalysisResult` 的时间点提前到 RAG 检索之前。
- `buildRagQueries` 去掉整段 PRD 查询，改为模块、需求、上下文文档、补充需求组成的查询段，上限提升到 12。
- RAG 上下文检索限定 `prd / context / supplementary`，避免召回 backend/frontend 整段 JSON。
- 新增失败经验检索并写入 `PrdAnalysisResult.ragFailures`。

### 1.6 `agent/TestGeneratorAgent.java` 与 `dto/PrdAnalysisResult.java`

- `PrdAnalysisResult` 新增 `ragFailures` 字段。
- prompt 上下文新增 `ragFailures`（最多 3 条、每条 800 字符），`ragContexts` 预算调整为最多 6 条、每条 1200 字符。
- PRD-driven system prompt 与 `test-generation-prd-footer.md` 补充 ragContexts/ragFailures 使用说明。

## 3. API 契约变化

- 无新增对外 HTTP API。
- `POST /api/mcp-bridge/semantic-search` 行为兼容：仍返回检索文本列表，现在命中内容带来源标题。
- 内部 `SemanticService.retrieveContexts(query)` 重载保留。

## 4. 向后兼容性

- Milvus 未启用时所有语义方法仍返回空结果，不阻塞生成。
- 存量 `contexts` 集合中的 backend/frontend 整篇向量保留，供语义搜索使用；生成检索限定需求类 module 后不再命中它们。
- 存量 PRD 数据在下次保存/更新 PRD 或项目上下文时自动重建为切片。
- `SearchHit` 新增字段为纯增量，无外部依赖。

## 5. 测试验证方案

- `RagTextChunkerTest`：空文本、短文本、标题层级、超长段落、重叠窗口。
- `SemanticServiceRrfTest`：多路查询跨路合并、同 id 去重、RRF 排序正确性。
- 后端验证：`mvn compile` 必须 BUILD SUCCESS；运行新增单测。
- 前端验证：`npm run build` 必须成功。
- 部署验证：`docker compose build backend frontend` 后重新创建容器，等待 healthy。
- 生产 smoke：检查后端日志出现 RAG context/failure 命中日志；调用 health 接口确认 prod profile。
